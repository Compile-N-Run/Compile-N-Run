# Accessibility Project: Workshop Form and Audit

This project brings together page structure, keyboard navigation, form instructions, error recovery, status messages, and a repeatable audit. It is a small working application with no booking service, external fonts, or media downloads.

**Prerequisites:** The preceding accessibility chapters, HTML forms, and basic JavaScript. The [HTML](/docs/language/html) and [CSS](/docs/language/css) courses provide the underlying syntax and layout foundations.

## Run the complete project

[Open the workshop practice page](/examples/web-accessibility/index.html). Use invented details. The JavaScript enhancement checks entries locally and reports a result; it does not send or store a registration.

The complete source is in `static/examples/web-accessibility/`. Copy the directory into a working folder, keeping these four files together:

```text
workshop-accessibility/
  index.html
  preview.html
  styles.css
  app.js
```

Without a repository checkout, save the source of the [main page](/examples/web-accessibility/index.html), [fallback preview](/examples/web-accessibility/preview.html), [stylesheet](/examples/web-accessibility/styles.css), and [script](/examples/web-accessibility/app.js) under those exact filenames. Use View Source or an HTML-only save option for the HTML pages.

From the copied directory, start a local server:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Visit `http://127.0.0.1:8000/`. Use your platform's Python launcher if it differs. The example also works as local files in browsers that allow the linked local script, but an HTTP server makes testing tools and navigation behavior more predictable.

## Understand the interaction

The source contains a skip link, meaningful headings, native navigation, labeled controls, persistent help text, and native disclosures. The form starts with ordinary HTML constraints. Only after the enhancement script runs does it turn on custom validation with `form.noValidate = true`.

After an invalid submission, the script rebuilds the summary, marks the affected fields invalid, and connects their messages through `aria-describedby`. It focuses the summary once. Its links focus the corresponding field. Values remain in place so the user can correct them and submit again; errors are re-evaluated on submission rather than on every keystroke.

After a valid check, errors are cleared and an existing status region receives a short result. Focus is not moved to that message. Input is handled as text, and no user-entered markup is injected into the document.

If JavaScript cannot run, native constraints remain and the form uses GET to navigate to `preview.html`. Practice values appear in the URL; the static page explicitly explains that it does not process them. This fallback demonstrates the browser/server boundary without inventing a booking confirmation.

## Extend one behavior

Add a third session named “Keyboard testing.” Update the select and the allowed values in `app.js`; changing only the visible option would leave it rejected by the demonstration validator. Update error text so it describes the choices accurately.

Then audit initial, invalid, and valid states. Your acceptance checks are:

- The skip link reaches main content, and focus remains visible throughout keyboard navigation.
- Empty submission creates two current errors; summary links reach the intended controls.
- Correcting both values removes stale errors and produces the truthful status message.
- The added session is accepted, while unknown values are not treated as valid selections.
- At narrow widths and enlarged text, controls and feedback remain available.
- With JavaScript disabled, native validation and the explanatory fallback still work.

Run the [automated example](./2-automated-checks.mdx), then document the [manual](./0-manual-audit.mdx) and [screen-reader](./1-screen-reader-testing.mdx) checks separately. Report what was actually tested, including any environment you could not test. The result is a reproducible learning project and evidence record, not a blanket accessibility certification.
