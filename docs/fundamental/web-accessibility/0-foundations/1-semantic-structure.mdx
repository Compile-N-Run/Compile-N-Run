# Semantic Structure and Reading Order

A visual layout can suggest relationships through spacing and position. Semantic HTML expresses those relationships in the document itself. Start with the reading sequence, then use CSS to arrange it.

**Prerequisites:** [The introduction](./0-accessibility-introduction.mdx). Reuse its document shell and replace the body when trying an independent example; do not nest one main region inside another.

## Organize the content before styling

Suppose a workshop page contains a header, session details, preparation advice, and a booking link. A useful source sequence is:

```html
<header>
  <p>Workshop Finder</p>
  <nav aria-label="Main"><a href="#details">Session details</a></nav>
</header>
<main>
  <h1>Bicycle maintenance workshop</h1>
  <section id="details" aria-labelledby="details-title">
    <h2 id="details-title">Session details</h2>
    <p>Saturday, 10:00–11:30. Garden room.</p>
  </section>
  <section aria-labelledby="prepare-title">
    <h2 id="prepare-title">What to bring</h2>
    <ul>
      <li>A clean bicycle</li>
      <li>A water bottle</li>
    </ul>
  </section>
</main>
<footer><p>Ask at reception if you need help finding the room.</p></footer>
```

The page has a primary topic followed by two sections. Choose heading levels for that hierarchy. Do not jump to `h4` because its default size fits your design; style an appropriate heading instead. A section does not automatically reset heading ranks.

Native elements provide useful semantics when used in the right context. A main region identifies the primary page content. Navigation identifies a collection of navigation links. A list expresses a group with discrete members. Generic `div` and `span` elements remain useful for styling wrappers that have no additional semantic meaning.

## Make repeated regions distinguishable

If a page has both primary navigation and article navigation, give them different accessible names, such as `aria-label="Main"` and `aria-label="On this page"`. Avoid labeling every region identically. A page with many named regions can become noisy, so name regions when the name helps people navigate.

A visible heading can name a section through `aria-labelledby`. The value refers to an existing element ID. An ID typo breaks that relationship even if the visual heading still appears correctly. Do not add an ARIA role when a suitable native element already supplies the required semantics.

## Check source order separately from position

Grid placement and Flexbox ordering can move content visually without making the same change to reading or keyboard order. A sidebar displayed above a form might still come after it in source order. Consider both experiences when arranging content.

Turn off the stylesheet in developer tools and read the document from top to bottom. Ask whether instructions appear before the controls that need them and whether related information stays together. Then restore styles and Tab through interactive elements. Decorative rearrangement must not turn a logical sequence into a confusing one.

## Exercise and solution

Add a second navigation region for two workshop topics. Give it a distinct name, and point its links at actual section IDs. Use `h2` headings for the two topics if they are sibling sections under the page's `h1`.

Your checks are: one visible primary main region, meaningful heading levels, unique IDs, distinguishable navigation names, and a sensible unstyled reading order. Inspect the browser's accessibility tree to confirm the navigation names. Seeing the text on screen is not enough to verify the programmatic relationship.
