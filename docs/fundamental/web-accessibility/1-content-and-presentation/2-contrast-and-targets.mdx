# Color, Contrast, and Target Size

Color can support an interface, but it should not be the only carrier of essential meaning. Contrast and target size are separate concerns: a prominent-looking control may still have low-contrast text or a very small activation area.

**Prerequisites:** Basic CSS selectors and [accessible names](../0-foundations/2-accessible-names.mdx). Start with a text link, a paragraph, and a native button in your practice page.

## Evaluate the actual color pair

For WCAG 2.2 Level AA text contrast, ordinary text generally needs at least 4.5:1 against its background. Large text has a 3:1 threshold; the criterion defines large text as at least 18pt, or 14pt when bold, approximately 24px or 18.67px respectively. Exceptions exist, including certain inactive controls and logos. Consult the actual criterion when assessing a specific case.

Use a contrast checker or developer tools to measure a foreground/background pair. Do not estimate the ratio from how vivid the colors look. Transparent colors, gradients, background images, and hover or disabled states can change the result.

```css
body { color: #18243a; background: #ffffff; }
a { color: #164a8a; text-decoration: underline; }
button {
  color: #ffffff;
  background: #164a8a;
  border: 2px solid #164a8a;
  padding: 0.75rem 1rem;
  font: inherit;
}
```

Treat these as test inputs, not a universal palette. Verify the pairs in your final page and all interactive states. The ratio for text is not the same assessment as the non-text contrast requirement for identifying certain interface components and states, which generally uses 3:1 against adjacent colors where applicable.

## Pair visual signals with meaning

An invalid input can have a red border and a visible message, such as “Choose a session.” The message explains the problem without requiring color perception. Likewise, show the current step with text or a programmatic state as well as a different color.

Links embedded in paragraphs should remain distinguishable from surrounding prose. An underline is a straightforward visual cue that survives many color changes. Removing it transfers more responsibility to color, contrast, and interaction styling.

## Give controls room

WCAG 2.2's Level AA minimum target-size criterion uses 24 by 24 CSS pixels, with defined exceptions such as spacing and inline targets. It does not mean every inline link must be converted into a large block. Assess the entire criterion rather than treating a single number as a complete test.

For prominent form actions, a practical design can provide more space than the minimum. Padding can enlarge a native button's activation area. Increasing a decorative icon's size without enlarging its clickable parent may not help. Avoid placing small destructive actions tightly beside a commonly used action.

## Exercise and checks

Create two workshop status messages: one for available places and one for a full session. Include the words “Places available” and “Full”; do not express the difference only through green and red.

Measure their text contrast, inspect the button's actual bounding box, and navigate using the keyboard. A successful solution remains understandable in grayscale, provides a visible focus indication, and preserves its labels when text is enlarged. Record the tested colors and states so a later theme change can be checked again.

Further reading: [W3C text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), and [minimum target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
