# Text Alternatives and Accessible Media

An alternative should preserve useful information or function when someone cannot use the original format. The right text depends on what an image does in its surrounding page, not just what pixels it contains.

**Prerequisites:** [Semantic structure](../0-foundations/1-semantic-structure.mdx). The image snippets below require your own matching files in an `images` folder; they do not download example photographs automatically.

## Describe the purpose in context

For a preparation guide, an informative photograph could use:

```html
<img src="images/repair-stand.jpg"
     width="800" height="600"
     alt="A bicycle clamped by its seat post in the repair stand.">
```

This description is useful only if the actual photograph communicates that information. Inspect the real image before writing its alternative. Do not use a filename, search keywords, or a generic “picture” label as a substitute for its purpose.

If an image is purely decorative and adds nothing to adjacent content, use an empty alternative:

```html
<img src="images/decorative-divider.svg" alt="">
```

Omitting `alt` is different from intentionally providing an empty one. Some tools may expose the filename when an alternative is absent. Also reconsider an empty alternative if the image is the only content of a link; that link still needs a useful name.

For a linked logo beside visible site text, avoid making the same destination two separate keyboard stops:

```html
<a href="#home">
  <img src="images/workshop-mark.svg" alt="" width="32" height="32">
  Workshop Finder
</a>
```

Add `id="home"` to the page's main heading when trying this fragment. The visible text supplies the link's name; the decorative mark need not repeat it.

## Make complex information available as content

A timetable, chart, or diagram may contain more detail than fits a short alternative. Introduce its conclusion in surrounding prose and provide the detailed values or process in a table or structured description. Do not bury an entire report in one enormous `alt` attribute.

For a chart of workshop attendance, a useful page might explain that bicycle maintenance had the largest attendance, then provide a table of all session counts. Readers can inspect the exact values instead of relying on a visual comparison of bar heights. Keep the data alternative updated whenever the chart changes.

## Plan recordings before publishing

A video with speech generally needs synchronized captions; a transcript serves a different reading purpose and does not replace those captions. Captions should include meaningful non-speech audio as well as dialogue. Important visual information that is not conveyed through the soundtrack also needs an appropriate description approach.

An audio-only interview can have an adjacent transcript. A silent demonstration has different alternatives from a narrated lecture. Evaluate the actual content and applicable success criteria rather than adding one generic “transcript” link to every kind of media. The [HTML media lesson](/docs/language/html/html-images-and-media/html-audio-and-video/) shows the mechanics of native controls and WebVTT files.

## Exercise and checks

Choose three images from a page you own: an informative image, a decorative one, and an image inside a link. Write or revise their alternatives, then explain your reasoning for each. Temporarily hide the images and read the remaining text.

A successful result preserves the task and the link destination without repeating nearby prose unnecessarily. For a chart, include its actual values in an available text format. A nonempty `alt` attribute is only a structural check; a person must still judge whether its content is useful.

Further reading: [W3C image alternatives decision tree](https://www.w3.org/WAI/tutorials/images/decision-tree/) and [accessible audio and video](https://www.w3.org/WAI/media/av/).
