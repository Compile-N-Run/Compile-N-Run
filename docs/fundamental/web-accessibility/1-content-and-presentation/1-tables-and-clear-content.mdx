# Accessible Tables and Clear Instructions

Clear content reduces the amount of inference a reader must do. A table should explain its data relationships, a link should suggest its destination, and an instruction should identify the relevant control without depending on its visual position.

**Prerequisites:** [Semantic structure](../0-foundations/1-semantic-structure.mdx). Place the following table in the main region of a fresh practice page.

## Give data its structure

```html
<table>
  <caption>Saturday workshop places</caption>
  <thead>
    <tr>
      <th scope="col">Session</th>
      <th scope="col">Start</th>
      <th scope="col">Places available</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Bicycle maintenance</th>
      <td>10:00</td>
      <td>4</td>
    </tr>
    <tr>
      <th scope="row">Simple sewing</th>
      <td>13:00</td>
      <td>6</td>
    </tr>
  </tbody>
</table>
```

The caption identifies this table. Column headers label the kinds of values, and row headers identify each session. Visual bold styling alone does not create these associations. Use a table for tabular data, not to place unrelated cards beside one another.

For a complex table with grouped or irregular headers, additional associations may be necessary. Before implementing those, ask whether two simpler tables would communicate the information better. A complicated visual spreadsheet is not automatically the best web presentation.

## Keep alternatives synchronized

If a chart displays the same counts, update the chart and table from the same underlying data when possible. A stale “accessible version” creates a different information problem. If users sort or filter a table, the keyboard controls, current sort state, and updated data also become part of the experience that needs testing.

A table may legitimately need two-dimensional presentation. That does not justify horizontal scrolling for the whole page. Contain any necessary table scrolling and test how a keyboard user reaches and operates that region. Short beginner tables often fit naturally when text is allowed to wrap.

## Name actions and locations precisely

Compare “Click the green button on the right” with “Choose Preview request.” The second instruction works if colors change, columns reflow, or someone uses speech input. Similarly, replace a set of identical “Read more” links with names that identify their topics, such as “Bicycle workshop preparation.”

Visible labels should remain consistent through a process. If a control is labeled “Session” on the form, an error saying “Select an event type” introduces avoidable translation work. Explain unfamiliar abbreviations at their first meaningful use and keep essential instructions near the relevant action.

Set the document language accurately. Mark substantial language changes with an appropriate `lang` attribute when needed; this can help pronunciation and other language-dependent processing. Language metadata does not translate the content or guarantee that a particular voice is installed.

## Exercise and solution

Add a third workshop row with a start time and available-place count. Then write a paragraph telling users how to choose a session, without mentioning color or screen position.

A suitable instruction is “Review the available places, then choose a session in the interest form.” Check that each row has a session header and every value remains under the correct column. Read the table caption and headers aloud without looking at visual styling; they should provide enough context to interpret “4” as a number of places, not a time or price.
