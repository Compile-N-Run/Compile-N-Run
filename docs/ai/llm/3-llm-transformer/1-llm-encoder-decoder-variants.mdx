# Encoder-Only, Decoder-Only and Encoder-Decoder Models

## Introduction

Within eighteen months of the original Transformer, the field split it three ways. Google's BERT (October 2018) kept only the encoder. OpenAI's GPT (June 2018) kept only the decoder. Google's T5 (October 2019) kept both. Each choice came with its own training objective and its own sweet spot of tasks, and for several years it was not obvious which would win.

Today almost every large language model, open or closed, is decoder-only. Encoders are still the right tool for embeddings, classification and retrieval, and encoder-decoders still power speech recognition and some translation systems. Knowing why the split happened, and why decoder-only took over generative AI, helps you pick the right model for a task and read architecture papers critically.

After this page you will be able to:

- describe the three variants by their attention masks, and print those masks in PyTorch;
- explain masked language modeling, next-token prediction and span corruption, and how much training signal each extracts from a sequence;
- name representative models of each family with their sizes and dates;
- give the concrete technical reasons, with evidence, for the dominance of decoder-only models;
- estimate when an encoder-decoder is cheaper than a decoder-only model, with a worked calculation.

## Three Ways to Use the Same Stack

All three variants use the same building block: attention followed by a feed-forward network, with residual connections and normalization. What distinguishes them is which tokens each position may attend to, and what the model is trained to predict. The first is fully described by the attention mask.

```python
import torch

T, prefix = 6, 3          # 6 tokens; for the prefix LM the first 3 are the "prompt"

bidirectional = torch.ones(T, T, dtype=torch.bool)                  # encoder (BERT)
causal = torch.tril(torch.ones(T, T, dtype=torch.bool))             # decoder (GPT)
prefix_lm = causal.clone()
prefix_lm[:, :prefix] = True                                        # everyone sees the whole prefix

def show(name, m):
    print(name)
    for row in m.int().tolist():
        print("  ", " ".join("x" if v else "." for v in row))

show("encoder-only: every token sees every token", bidirectional)
show("decoder-only: token i sees tokens 0..i", causal)
show("prefix LM: full attention inside the prefix, causal after it", prefix_lm)

# How many positions produce a training signal per sequence of 512 tokens?
L = 512
print("causal LM targets:", L - 1)
print("BERT MLM targets (15%):", int(0.15 * L))
```

```text
encoder-only: every token sees every token
   x x x x x x
   x x x x x x
   x x x x x x
   x x x x x x
   x x x x x x
   x x x x x x
decoder-only: token i sees tokens 0..i
   x . . . . .
   x x . . . .
   x x x . . .
   x x x x . .
   x x x x x .
   x x x x x x
prefix LM: full attention inside the prefix, causal after it
   x x x . . .
   x x x . . .
   x x x . . .
   x x x x . .
   x x x x x .
   x x x x x x
causal LM targets: 511
BERT MLM targets (15%): 76
```

Row $i$ shows which columns (keys) query $i$ may look at. An encoder-decoder uses the bidirectional mask in its encoder, the causal mask in its decoder's self-attention, and a full rectangular mask in cross-attention (every target position sees every source position). The prefix LM is a decoder-only model that treats the first part of the sequence as an encoder would; we come back to it below.

The masks look like a small detail, but they decide what the model can be trained to do. A bidirectional model cannot be trained with plain next-token prediction, because every position can see the token it would have to predict. A causal model can, and that one fact shapes everything that follows.

## Encoder-Only: BERT and Its Descendants

BERT (Devlin, Chang, Lee and Toutanova, "BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding", 2018) is a stack of Transformer encoder layers. BERT-Base has 12 layers, width 768 and 12 heads, about 110M parameters; BERT-Large has 24 layers, width 1024 and 16 heads, about 340M. You can still check these numbers in the `bert-base-uncased` config.json on Hugging Face: `hidden_size` 768, `num_hidden_layers` 12, `intermediate_size` 3072, `max_position_embeddings` 512.

Because every token sees every other token, BERT needs a different objective. **Masked language modeling (MLM)** picks 15% of token positions at random. Of those, 80% are replaced by a special `[MASK]` token, 10% by a random token, and 10% are left unchanged; the model must predict the original token at each picked position. The 80/10/10 split exists because `[MASK]` never appears at fine-tuning time; mixing in real tokens keeps the model from relying on its presence. BERT also used a next-sentence prediction task, which RoBERTa (Liu et al., 2019) later showed was unnecessary.

The loss covers only the masked positions:

$$
\mathcal{L}_\mathrm{MLM} = -\frac{1}{\lvert \mathcal{M} \rvert} \sum_{i \in \mathcal{M}} \log p_\theta\!\left(x_i \mid \tilde{x}\right)
$$

where $\mathcal{M}$ is the set of picked positions and $\tilde{x}$ is the corrupted sequence. Every prediction gets to use context on both sides, which is why encoders produce excellent token and sentence representations. But only about 15% of positions are scored, so each sequence yields 76 targets out of 512 instead of 511. ELECTRA (Clark et al., 2020) attacked exactly this inefficiency by training the encoder to detect replaced tokens at every position.

Encoder-only models are used by attaching a small head to their outputs: a classifier on the first token's vector for sentiment or intent, a span predictor for extractive question answering, a pooling layer for sentence embeddings. They are not natural generators; there is no clean way to sample a sentence from a model trained to fill in blanks.

This family is far from dead. Embedding models for search and RAG are mostly encoders, and ModernBERT (Warner et al., December 2024) refreshed the design with RoPE, an 8,192-token context and about 2 trillion training tokens. If your task is "turn text into a vector" or "assign a label", a 150M-parameter encoder is often faster and better than prompting a billion-parameter generator. For using such models in retrieval pipelines, see the [AI Agents tutorial](/docs/ai/agents).

## Decoder-Only: GPT and the Causal Language Model

GPT (Radford, Narasimhan, Salimans and Sutskever, "Improving Language Understanding by Generative Pre-Training", June 2018) kept the decoder stack, minus cross-attention since there is no encoder. It had 12 layers, width 768, 12 heads and a 3,072-wide FFN, about 117M parameters, trained on the BooksCorpus with next-token prediction. Fine-tuning on each downstream task came after.

The objective is the one introduced in [Language Modeling and Next-Token Prediction](../0-llm-fundamentals/1-llm-language-modeling.mdx):

$$
\mathcal{L}_\mathrm{CLM} = -\frac{1}{T} \sum_{t=1}^{T} \log p_\theta\!\left(x_t \mid x_1, \dots, x_{t-1}\right)
$$

Thanks to the causal mask, one forward pass computes all $T$ conditional distributions at once; [Causal Masking](../2-llm-attention/3-llm-causal-masking.mdx) shows how. Every position is a target, there is no corruption and no special token, and the trained model is directly a generator: sample $x_{t}$, append it, repeat.

The GPT line then scaled. GPT-2 (February 2019) reached 1.5B parameters with 48 layers, width 1600 and a 1,024-token context, and showed that a big enough language model can do some tasks with no fine-tuning at all. GPT-3 (Brown et al., May 2020) went to 175B parameters: 96 layers, width 12,288, 96 heads of 128, a 2,048-token context, trained on 300 billion tokens. Its paper's main result was in-context learning: show the model a few examples in the prompt, and it performs the task. That turned "a model per task" into "one model, many prompts", and it only works naturally with a model that continues text.

## Encoder-Decoder: T5, BART and the Text-to-Text Framing

T5 (Raffel et al., "Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer", October 2019) argued for keeping both halves. Every task becomes text in, text out: the input "translate English to German: That is good." maps to the output "Das ist gut.", and "cola sentence: ..." maps to "acceptable". The encoder reads the input bidirectionally; the decoder writes the answer causally, attending to the encoder through cross-attention.

T5's pretraining objective is **span corruption**. It corrupts 15% of tokens, in spans with a mean length of 3, replaces each span with a sentinel token in the input, and asks the decoder to output the spans:

```text
original: Thank you for inviting me to your party last week .
input:    Thank you <X> me to your party <Y> week .
target:   <X> for inviting <Y> last <Z>
```

The encoder sees a lightly damaged input with full bidirectional context; the decoder's target is short, which keeps pretraining cheap. T5 was trained on C4, about 750 GB of cleaned Common Crawl text, at sizes up to 11 billion parameters. BART (Lewis et al., 2019) is a similar encoder-decoder trained to reconstruct documents corrupted with several kinds of noise.

The T5 paper is also the most careful head-to-head comparison of the three architectures from that era. With a denoising objective and matched compute, its encoder-decoder beat a decoder-only prefix LM and a plain causal language model on its benchmark suite, and denoising beat plain language modeling across the board. That result is one reason the question stayed open until about 2022. Note what it measured: fine-tuned performance on classification, summarization and translation tasks, at roughly 220M parameters. It did not measure open-ended generation or in-context learning.

Encoder-decoders remain the default where input and output are different kinds of things. OpenAI's Whisper speech recognizer encodes audio and decodes text. Many production translation systems are still encoder-decoders.

## Prefix LMs: A Middle Ground

A prefix LM (or non-causal decoder) is a single decoder stack with the third mask printed above: tokens in the prefix (the prompt) attend to each other bidirectionally, and tokens after it attend causally. It gets the encoder's bidirectional view of the input without a separate encoder or cross-attention. UniLM (Dong et al., 2019) and the prefix-LM variant in the T5 paper explored it, and several later models used it for the prompt portion.

The prefix LM shows that "encoder vs decoder" is really a question of masks and objectives, not of two different kinds of layer. The weights are interchangeable; only the attention pattern and the loss differ.

## Why Decoder-Only Won

By 2023 nearly every frontier model and every popular open model (Llama, Mistral, Qwen, Gemma, DeepSeek) was decoder-only. There was no single decisive paper; several advantages compounded.

**1. Every token is a training target.** A causal LM gets a loss term at all $T$ positions of every sequence. MLM gets one at about 15%, span corruption at a similar fraction. With web-scale data, the cost of pretraining is dominated by forward and backward passes, so extracting more signal per pass matters.

**2. One objective covers every task.** Anything expressible as text can be posed as "continue this", from translation to code to dialogue. GPT-3 showed that this generality grows with scale through in-context learning, and instruction tuning and RLHF (see [Post-Training Overview](../8-llm-post-training/0-llm-post-training-overview.mdx)) later turned the same continuation machinery into assistants. Encoders need a task head; encoder-decoders need an input/output split decided in advance.

**3. Zero-shot ability after pretraining.** Wang et al. ("What Language Model Architecture and Pretraining Objective Work Best for Zero-Shot Generalization?", 2022) trained models with over 5B parameters on 170B tokens across architectures and objectives. A causal decoder trained with plain next-token prediction had the best zero-shot generalization straight after pretraining. A non-causal decoder trained with MLM and then multitask-finetuned did best overall, and the authors showed that one can be adapted into the other cheaply. For an open-ended assistant, zero-shot behavior after pretraining is the property that matters most.

**4. Simplicity and the KV cache.** A decoder-only model is one stack with one attention type. In a chat, the conversation is one growing sequence; keys and values for earlier turns can be cached and reused, and only new tokens are processed. With an encoder-decoder, a growing input means re-running the encoder over the whole history every turn, since bidirectional attention lets each new token change every earlier representation. Serving engines such as vLLM, with prefix caching and paged KV memory ([PagedAttention](../10-llm-inference/3-llm-paged-attention.mdx)), are built around the decoder-only pattern.

**5. Scaling evidence and momentum.** The scaling-law papers (Kaplan et al., 2020; Hoffmann et al., 2022) studied decoder-only models, and GPT-3, PaLM and Llama demonstrated the recipe at scale. Once the tooling, the kernels and the know-how were all decoder-shaped, an alternative needed a big advantage to compete. This is partly path dependence, and you should treat it as such.

None of this says decoders are better at everything. Bidirectional attention still gives better representations per parameter for retrieval and classification, which is why embedding models are encoders. The decoder-only win is about the general-purpose, generative, prompt-driven model.

## Worked Example: When Is an Encoder-Decoder Cheaper?

Decoder-only models are not free. Consider summarizing a 1,000-token document into 100 tokens. Compare a 24-layer decoder-only model with a 12 + 12 encoder-decoder, both of width 1,024 with a 4x MLP. Use the rule from [Counting Parameters, FLOPs and Memory](./6-llm-parameter-and-flop-counting.mdx): a forward pass costs about 2 FLOPs per weight per token (we ignore the attention-score term, which is small at this length).

```python
# Forward-pass cost of a long-input, short-output task under two designs.
d = 1024                                  # model width
attn, mlp = 4 * d * d, 8 * d * d          # weights per self-attention and per 4x MLP

dec_only_layer = attn + mlp               # 12 d^2
enc_layer = attn + mlp                    # 12 d^2
dec_layer = 2 * attn + mlp                # 16 d^2: self-attention + cross-attention + MLP

N_dec_only = 24 * dec_only_layer
N_enc, N_dec = 12 * enc_layer, 12 * dec_layer
print(f"decoder-only, 24 layers:      {N_dec_only/1e6:6.1f}M weights")
print(f"encoder-decoder, 12 + 12:     {(N_enc + N_dec)/1e6:6.1f}M weights")

src, out = 1000, 100                      # e.g. summarize a 1000-token document into 100 tokens
flops_dec_only = 2 * N_dec_only * (src + out)          # every token goes through all 24 layers
flops_enc_dec = 2 * N_enc * src + 2 * N_dec * out      # source only through encoder, output only through decoder
print(f"decoder-only forward:    {flops_dec_only:.2e} FLOPs")
print(f"encoder-decoder forward: {flops_enc_dec:.2e} FLOPs")
```

```text
decoder-only, 24 layers:       302.0M weights
encoder-decoder, 12 + 12:      352.3M weights
decoder-only forward:    6.64e+11 FLOPs
encoder-decoder forward: 3.42e+11 FLOPs
```

The encoder-decoder has slightly more weights (cross-attention adds $4d^2$ per decoder layer) but needs about half the compute for this task, because each source token passes through only 12 layers and each output token through only 12. When inputs are long, outputs are short and the input is fixed (translation, summarization, speech-to-text), this is a real advantage, and it is why Whisper and many translation systems keep the design.

Now change the scenario to a 20-turn chat where each turn adds 100 tokens. The decoder-only model with a KV cache processes each new token once: 2,000 tokens in total over the whole conversation. The encoder-decoder must re-encode the growing history at every turn, about $100 + 200 + \dots + 2000 = 21{,}000$ encoder token-passes. The ranking flips. The workload decides, and the workload of general assistants and agents is long, growing, multi-turn context.

:::tip
When choosing a model for a production task, do not default to the largest chat model. For classification, tagging or embeddings, benchmark a fine-tuned encoder first; for fixed-input transformation tasks, consider an encoder-decoder. Reach for a decoder-only LLM when you need open-ended generation, instruction following or in-context learning.
:::

## Common Mistakes

- **Generating text with BERT.** An MLM encoder is not trained to produce left-to-right text. Iteratively filling `[MASK]` tokens gives poor results; use a causal or encoder-decoder model.
- **Using a decoder-only model's last-token vector as a sentence embedding without training for it.** The last hidden state is tuned for predicting the next token, not for similarity. Use a model trained for embeddings.
- **Forgetting that T5 inputs and targets have different lengths.** Span-corruption targets are short; padding or truncating them like inputs wastes compute or drops content.
- **Assuming the T5 comparison settled the question.** It compared fine-tuned performance at small scale with a denoising objective. Zero-shot generation at billions of parameters is a different experiment, and it gave a different answer.
- **Thinking encoder and decoder layers are different kinds of computation.** They are the same block with a different mask (plus cross-attention in the decoder of an encoder-decoder). A prefix LM is one stack with a hybrid mask.
- **Counting only parameters when comparing designs.** As the worked example shows, an encoder-decoder with more weights can need less compute per task, and a decoder-only model can be far cheaper in multi-turn use.

## Summary

- The three variants share the same block and differ in attention mask and objective: bidirectional with MLM (BERT), causal with next-token prediction (GPT), or encoder plus causal decoder with span corruption (T5).
- Encoders give the best representations per parameter and remain the standard for embeddings and classification (ModernBERT, 2024).
- Encoder-decoders are efficient for fixed-input, short-output tasks such as translation and speech recognition (Whisper).
- Decoder-only won general-purpose LLMs because every token is a target, one objective covers every task, zero-shot behavior is strongest after plain pretraining (Wang et al., 2022), the KV cache makes multi-turn context cheap, and the scaling and tooling ecosystem grew around it.
- A prefix LM shows that the difference is in masks and losses, not in the layers themselves.
