# LLM Terminology Cheat Sheet

## Introduction

LLM papers and model cards are dense with jargon. A single sentence such as "a 30B-A3B MoE with GQA, 128K context via YaRN, released in BF16 and FP8, served with paged attention and speculative decoding" packs a dozen concepts. Each term is simple once you know it, but looking them up one at a time is slow.

This page is a reference you can keep open while reading the rest of the tutorial, or a paper. Terms are grouped by topic, each with a one- or two-sentence definition in plain words and a link to the page that explains it properly. Symbols used across the tutorial are listed at the end.

Use it in two ways:

- **Before a section:** skim the relevant table so the vocabulary is familiar.
- **While reading a paper or config:** search this page for the term.

## Text, Tokens and Vocabulary

| Term | Meaning | Learn more |
| --- | --- | --- |
| Token | The unit a model reads and writes: a word, part of a word, a byte or a symbol. English averages roughly 0.75 words per token with typical tokenizers. | [Tokenization Basics](../1-llm-tokenization/0-llm-tokenization-basics.mdx) |
| Tokenizer | The program that converts text to token ids and back. Trained once, then frozen with the model. | [Tokenization Basics](../1-llm-tokenization/0-llm-tokenization-basics.mdx) |
| Vocabulary, `vocab_size` | The set of all tokens the model knows; sets the size of the embedding table and the output layer. | [Embeddings](../1-llm-tokenization/4-llm-embeddings.mdx) |
| BPE | Byte-pair encoding: builds a vocabulary by repeatedly merging the most frequent adjacent pair. Byte-level BPE works on UTF-8 bytes so any text can be encoded. | [Byte-Pair Encoding](../1-llm-tokenization/1-llm-bpe.mdx) |
| WordPiece, Unigram, SentencePiece | Other subword algorithms (WordPiece for BERT, Unigram usually via the SentencePiece library). | [WordPiece, Unigram and SentencePiece](../1-llm-tokenization/2-llm-wordpiece-unigram-sentencepiece.mdx) |
| Special tokens | Reserved tokens with a structural meaning: beginning or end of sequence, padding, chat role markers. | [Tokenizer Libraries](../1-llm-tokenization/3-llm-tokenizer-libraries.mdx) |
| Chat template | The rule that turns a list of messages into one token sequence with role markers. | [Supervised Fine-Tuning](../8-llm-post-training/1-llm-supervised-fine-tuning.mdx) |
| Embedding | The learned vector for a token, a row of the embedding matrix of shape `(vocab_size, d_model)`. | [Embeddings](../1-llm-tokenization/4-llm-embeddings.mdx) |
| Weight tying | Using the same matrix for the input embedding and the output layer. | [Embeddings](../1-llm-tokenization/4-llm-embeddings.mdx) |
| Context window, context length | The maximum number of tokens the model can attend to at once, prompt plus output. | [Extending Context](../4-llm-positional-encoding/6-llm-context-extension.mdx) |

## Modeling and Probability

| Term | Meaning | Learn more |
| --- | --- | --- |
| Language model | A probability distribution over token sequences. | [Language Modeling](./1-llm-language-modeling.mdx) |
| Autoregressive, causal LM | Generates left to right; each token is predicted from the ones before it. GPT, Llama and all chat models. | [Language Modeling](./1-llm-language-modeling.mdx) |
| Masked LM | Predicts hidden tokens using context on both sides (BERT). Good for understanding tasks, not for generation. | [Encoder and Decoder Variants](../3-llm-transformer/1-llm-encoder-decoder-variants.mdx) |
| Logits | The raw score per vocabulary token that the model outputs before softmax. Shape `(batch, seq_len, vocab_size)`. | [Language Modeling](./1-llm-language-modeling.mdx) |
| Softmax | Turns logits into probabilities: exponentiate, then normalize to sum to 1. | [Neural Network Refresher](./3-llm-neural-network-refresher.mdx) |
| Cross-entropy, NLL | The training loss: the average negative log probability of the true next token. | [Language Modeling](./1-llm-language-modeling.mdx) |
| Perplexity | The exponential of cross-entropy; the effective number of choices the model is unsure between. Lower is better. | [Perplexity](../12-llm-evaluation/1-llm-perplexity.mdx) |
| Teacher forcing | Training on the true previous tokens rather than the model's own predictions, which allows all positions to be trained in parallel. | [Causal Masking](../2-llm-attention/3-llm-causal-masking.mdx) |
| Temperature | Divides logits before softmax. Below 1 sharpens the distribution, above 1 flattens it. | [Decoding Strategies](../10-llm-inference/1-llm-decoding-strategies.mdx) |
| Greedy, top-k, top-p, min-p | Ways of choosing the next token: always the best, or sampling from a truncated set (k most likely, smallest set with probability mass p, or tokens above a fraction of the best probability). | [Decoding Strategies](../10-llm-inference/1-llm-decoding-strategies.mdx) |

## Architecture

| Term | Meaning | Learn more |
| --- | --- | --- |
| Transformer | The architecture of essentially all LLMs: stacked blocks of attention and MLP with residual connections. | [Transformer Overview](../3-llm-transformer/0-llm-transformer-overview.mdx) |
| Decoder-only | A Transformer with only causal self-attention blocks; the standard LLM design. | [Encoder and Decoder Variants](../3-llm-transformer/1-llm-encoder-decoder-variants.mdx) |
| `d_model`, `hidden_size` | The width of the vectors that flow between layers. | [Decoder Block](../3-llm-transformer/2-llm-transformer-block.mdx) |
| Residual stream | The running sum that each block reads from and adds its output to. | [Decoder Block](../3-llm-transformer/2-llm-transformer-block.mdx) |
| Layer, block | One attention sub-layer plus one MLP sub-layer, each with normalization. `num_hidden_layers` counts these. | [Decoder Block](../3-llm-transformer/2-llm-transformer-block.mdx) |
| Attention | Each token builds a query, compares it with every allowed token's key, and takes a weighted average of their values. | [Attention Intuition](../2-llm-attention/0-llm-attention-intuition.mdx) |
| Q, K, V | Query, key and value vectors, computed from the input by three learned projections. | [Scaled Dot-Product Attention](../2-llm-attention/1-llm-scaled-dot-product-attention.mdx) |
| Causal mask | Prevents a token from attending to later tokens. | [Causal Masking](../2-llm-attention/3-llm-causal-masking.mdx) |
| Head, `head_dim` | Attention is split into several independent heads, each of size `head_dim`. | [Multi-Head Attention](../2-llm-attention/4-llm-multi-head-attention.mdx) |
| MHA, MQA, GQA | Multi-head (each query head has its own K and V), multi-query (one shared K and V), grouped-query (groups of query heads share K and V). | [MQA and GQA](../2-llm-attention/5-llm-mqa-gqa.mdx) |
| MLA | Multi-head latent attention (DeepSeek): stores a compressed latent instead of full K and V. | [MLA](../2-llm-attention/6-llm-mla.mdx) |
| MLP, FFN | The per-token feed-forward network in each block, holding most parameters. | [Feed-Forward Networks](../3-llm-transformer/4-llm-feed-forward-and-swiglu.mdx) |
| SwiGLU | A gated MLP using SiLU; standard in Llama, Qwen, Mistral and DeepSeek. | [Feed-Forward Networks](../3-llm-transformer/4-llm-feed-forward-and-swiglu.mdx) |
| LayerNorm, RMSNorm | Normalize each token's vector; RMSNorm skips mean-centering and is cheaper. | [Normalization](../3-llm-transformer/3-llm-normalization.mdx) |
| Pre-norm, post-norm | Whether normalization is applied before each sub-layer (modern) or after the residual addition (original Transformer). | [Normalization](../3-llm-transformer/3-llm-normalization.mdx) |
| QK-norm | Normalizing queries and keys inside attention to stabilize training (Qwen3, Gemma 3). | [Normalization](../3-llm-transformer/3-llm-normalization.mdx) |
| LM head | The final linear layer from `d_model` to vocabulary logits. | [Building a GPT](../3-llm-transformer/5-llm-build-gpt-from-scratch.mdx) |
| Dense model | Every parameter is used for every token. | [MoE Introduction](../7-llm-mixture-of-experts/0-llm-moe-introduction.mdx) |
| MoE, experts, router | Mixture of experts: many MLPs per layer, with a router sending each token to a few of them. | [MoE Introduction](../7-llm-mixture-of-experts/0-llm-moe-introduction.mdx) |
| Total vs active parameters | All parameters stored vs parameters used per token. "30B-A3B" means 30B total, 3B active. | [MoE Introduction](../7-llm-mixture-of-experts/0-llm-moe-introduction.mdx) |
| Shared expert | An expert every token uses, alongside its routed experts (DeepSeek, Qwen MoE models). | [MoE Architectures](../7-llm-mixture-of-experts/2-llm-moe-architectures.mdx) |
| State space model, Mamba | A recurrent-style layer with linear cost in sequence length, an alternative or complement to attention. | [State Space Models](../13-llm-advanced-architectures/1-llm-state-space-models.mdx) |
| Hybrid model | Mixes full attention layers with linear-attention or state space layers. | [Hybrid Models](../13-llm-advanced-architectures/2-llm-hybrid-models.mdx) |

## Positions and Long Context

| Term | Meaning | Learn more |
| --- | --- | --- |
| Positional encoding | Information about token order, needed because attention alone ignores order. | [Why Position Matters](../4-llm-positional-encoding/0-llm-why-position-matters.mdx) |
| Sinusoidal, learned positions | Adding a fixed sine and cosine pattern (original Transformer) or a learned vector (GPT-2) per position. | [Sinusoidal and Learned](../4-llm-positional-encoding/1-llm-sinusoidal-and-learned.mdx) |
| ALiBi | Adds a distance-proportional penalty to attention scores instead of position vectors. | [Relative Positions and ALiBi](../4-llm-positional-encoding/2-llm-relative-position-and-alibi.mdx) |

| Sliding window attention | Each token attends only to the last W tokens, bounding memory. | [Sparse and Linear Attention](../5-llm-flash-attention/5-llm-sparse-and-linear-attention.mdx) |

## Sizes, Units and Symbols

Model names and papers mix units freely. The conventions used in this tutorial:

| Notation | Meaning |
| --- | --- |
| 7B, 70B, 1T | Parameters, in billions or trillions. |
| 15T tokens | Training data size in tokens. |
| 128K context | 131,072 tokens (powers of two, so 1K means 1,024 in context lengths). |
| FLOPs | Floating-point operations (a count). FLOP/s is a rate. |
| GiB, GB | $2^{30}$ bytes vs $10^9$ bytes. This tutorial uses GiB for memory. |
| $B$ | Batch size. |
| $T$ | Sequence length in tokens. |
| $V$ | Vocabulary size. |
| $d$ or $d_\mathrm{model}$ | Hidden size. |
| $L$ | Number of layers. |
| $n_h$, $n_\mathrm{kv}$ | Number of query heads and key-value heads. |
| $d_k$, $d_h$ | Per-head dimension (`head_dim`). |
| $d_\mathrm{ff}$ | MLP hidden size (`intermediate_size`). |
| $N$, $D$ | Parameter count and training tokens (as in $6ND$). |
| $\theta$ | Model parameters in general; also the RoPE base in the RoPE pages (the context makes clear which). |

Tensor shapes are written in parentheses with names, such as `(batch, n_heads, seq_len, head_dim)`, matching the comments in the code.

## Worked Scenario: Decoding a Model Announcement

Here is a sentence of the kind you will read in release notes, followed by its translation using the tables above:

> "We release a 30B-A3B MoE base and instruct model, trained on 36T tokens, with GQA (32 query heads, 4 KV heads), QK-norm, RoPE with theta 1,000,000, 32K native context extendable to 128K with YaRN, available in BF16 and FP8."

- **30B-A3B MoE**: 30 billion parameters stored, about 3 billion used per token. Memory like a 30B model, compute per token like a 3B model.
- **Base and instruct**: a pretrained text continuer for fine-tuning, and a post-trained assistant with a chat template.
- **36T tokens**: far beyond Chinchilla-optimal (about 0.6T for 30B parameters), deliberately over-trained for cheap inference.
- **GQA with 32 query and 4 KV heads**: groups of 8 query heads share K and V, so the KV cache is 8 times smaller than with full multi-head attention.
- **QK-norm**: RMSNorm on queries and keys, a training-stability measure.
- **RoPE theta 1,000,000**: long rotation wavelengths, chosen to support long contexts.
- **32K native, 128K with YaRN**: trained up to 32K tokens; for longer inputs you must enable the YaRN `rope_scaling` setting, with some quality trade-off.
- **BF16 and FP8**: full-quality 16-bit weights, and an 8-bit version that halves weight memory and speeds up inference on GPUs that support FP8.

This description closely matches Qwen3-30B-A3B. You can check it against the model's config.json with the method in [Model Families](./4-llm-model-families.mdx).

When a term is new, find it in the "Learn more" column and read just the introduction and summary of that page. That is usually enough to keep going, and you can return for the derivation later.

## Common Mistakes

- **Mixing up parameters and tokens.** "8B" is model size; "15T" is training data. Both use the same suffixes.
- **Reading "context length" as output length.** The context window covers the prompt and the generated text together. Output limits are usually much smaller.
- **Treating FLOPs and FLOP/s as the same.** One is an amount of work, the other a speed.
- **Assuming 1K is always 1,000.** Context lengths use powers of two (128K is 131,072); token counts in data and pricing usually use powers of ten.
- **Using "fine-tuning" and "post-training" interchangeably.** Post-training is the lab's full pipeline to make an assistant; fine-tuning usually means adapting an existing model to your task.
- **Equating MoE "experts" with human-meaningful specialties.** Experts specialize in statistical patterns of tokens, rarely in topics like "math" or "biology".

## Summary

- The vocabulary of LLMs falls into a few groups: tokens and vocabularies, probability and losses, architecture, positions, training, post-training, inference and evaluation.
- Most terms are short names for concrete operations: GQA shares K and V across heads, RoPE rotates vectors, LoRA trains a low-rank update, the KV cache stores past keys and values.
- Sizes use B and T for parameters and tokens, K for context lengths in powers of two, and FLOPs for amounts of compute.
- Each term in the tables links to the page that explains it in depth.
