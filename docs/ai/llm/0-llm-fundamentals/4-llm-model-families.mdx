# Model Families: GPT, Llama, Qwen, DeepSeek, Mistral and Gemma

## Introduction

New models appear every week, and their announcements are full of numbers: 8B, 671B total with 37B active, 128K context, GQA, MoE, YaRN. This page gives you two skills that outlast any particular release.

The first is a map of the **model families**: who builds them, which are open, and what architectural habits each family has. The second, more important, is how to read a **model card** and a **`config.json`**, so that when a new model ships you can work out its size, its attention layout, its context length, its positional encoding and its KV cache cost in a few minutes, without trusting anyone's summary.

By the end you will be able to:

- Explain the difference between closed models, open-weight models and fully open models, and what licenses allow.
- Recognize the signature choices of the GPT, Llama, Qwen, DeepSeek, Mistral and Gemma families.
- Read every common field of a Hugging Face `config.json` and know which later page explains it.
- Compute a dense model's exact parameter count and its KV cache size per token from its config.

Every number on this page was taken from the model's published `config.json`, model card or technical report on Hugging Face (as of October 2026). Model details change between versions, so treat the method as the lesson and the numbers as examples.

## Open Weights, Open Source and Closed Models

LLMs reach you in three ways:

| Kind | What you get | Examples |
| --- | --- | --- |
| Closed (API only) | Text in, text out over an API. No weights, usually no architecture details. | OpenAI GPT series, Anthropic Claude, Google Gemini |
| Open weights | Downloadable weights, config and inference code, under a license. Training data and full training code usually not released. | Llama, Qwen, DeepSeek, Mistral, Gemma, gpt-oss |
| Fully open | Weights plus training data, training code and intermediate checkpoints. | AI2's OLMo, Hugging Face's SmolLM |

"Open source" is often used loosely for the second row. Strictly, most open-weight releases are not open source in the software sense, because you cannot rebuild them: the data is missing. They are still enormously useful, because you can run, inspect, quantize and fine-tune them.

**Licenses differ and matter.** Qwen's mainstream models, Mistral's open releases, gpt-oss and Gemma 4 use Apache 2.0. DeepSeek uses MIT for recent releases (the original DeepSeek-V3 used MIT for code plus a separate model license that allows commercial use). Llama models use Meta's own community licenses with an acceptable-use policy and extra terms for very large companies. Gemma 3 and earlier used Google's Gemma Terms of Use. Some of the largest models (for example Qwen's 2.4-trillion-parameter Qwen3.8 flagship) ship under custom licenses. Read the `license` field on the model page and the license file before building a product.

For learning, open weights are what matter: everything in this tutorial about RoPE theta, head counts or expert routing can be checked because these files are public.

## The Families

### GPT (OpenAI)

OpenAI's GPT line established the decoder-only recipe: GPT (2018), GPT-2 (2019, weights released), GPT-3 (2020, 175B parameters, API only), then the ChatGPT and GPT-4 era and the o-series reasoning models. After GPT-2, OpenAI's frontier models have been closed, and their architectures are not published.

In August 2025 OpenAI released **gpt-oss-120b** and **gpt-oss-20b** under Apache 2.0: mixture-of-experts reasoning models with 117B and 21B total parameters and 5.1B and 3.6B active per token. The 20B config shows 24 layers, 32 experts with 4 active per token, 64 query heads sharing 8 KV heads, a 201,088-token vocabulary, and layers that alternate between a 128-token sliding window and full attention.

GPT-2 is still the standard teaching model (it appears throughout this tutorial) because it is small, freely downloadable and architecturally simple: learned position embeddings, LayerNorm, GELU, and full multi-head attention.

### Llama (Meta)

**LLaMA** (February 2023) made a strong open model available to researchers and set the template that most open models still follow: pre-normalization with **RMSNorm**, the **SwiGLU** feed-forward layer, and **RoPE** positions, with no biases in linear layers. **Llama 2** (July 2023) added a commercial license and chat models; its 70B model used grouped-query attention. **Llama 3** (April 2024) moved to a 128K-token tiktoken-based vocabulary, used GQA at every size, raised RoPE theta to 500,000, and trained on over 15T tokens. **Llama 3.1** (July 2024) extended context to 128K with a new RoPE scaling rule and added a 405B dense model. **Llama 4** (April 2025) switched to mixture of experts: Scout has 16 routed experts with 1 active per token (about 109B total, 17B active).

### Qwen (Alibaba)

Alibaba's Qwen team releases many sizes at once, almost all under Apache 2.0, which made Qwen the most fine-tuned base family on Hugging Face. **Qwen2.5** (2024) and **Qwen3** (April 2025) follow the Llama-style recipe with a vocabulary of about 152K tokens and RoPE theta of 1,000,000. Qwen3 added **QK-norm** (RMSNorm on queries and keys inside attention) and dropped the QKV biases Qwen2.5 had, and shipped both dense models and MoE models such as Qwen3-30B-A3B. Its models offer switchable thinking and non-thinking modes.

The newer **Qwen3.5 to Qwen3.8** generations moved to **hybrid attention**: their configs list `layer_types` in which three linear-attention layers alternate with one full-attention layer, with RoPE applied to only a quarter of each head's dimensions (`partial_rotary_factor: 0.25`) and `rope_theta` of 10,000,000. The naming convention `A` plus a number gives active parameters: Qwen3.8-2.4T-A95B has about 2.4T total and 95B active.

### DeepSeek

DeepSeek is known for efficiency research published in detail. **DeepSeek-V2** (2024) introduced **multi-head latent attention** (MLA), which compresses keys and values into a small latent vector to shrink the KV cache. **DeepSeek-V3** (December 2024) has 671B total parameters with 37B active, 61 layers, 256 routed experts plus 1 shared expert with 8 routed experts per token, a KV latent rank of 512, multi-token prediction, and FP8 training on 14.8T tokens. **DeepSeek-R1** (January 2025) was built on V3 with reinforcement learning for reasoning.

The **V4** series (2026) pushed context to one million tokens with compressed sparse attention. The DeepSeek-V4.1-Flash model card, for example, describes 384 routed experts and 1 shared expert with 6 routed experts active per token, and a 1,048,576-token maximum context in its config.

### Mistral

The French company Mistral AI released **Mistral 7B** (September 2023) under Apache 2.0 with grouped-query attention and **sliding window attention** (a 4,096-token window in the v0.1 config). **Mixtral 8x7B** (December 2023) was the first widely used open MoE model: 8 experts per layer, 2 active per token. Later releases span closed API models and open ones; **Mistral Small 4** (2026), for example, is a 119B-parameter MoE with 128 experts and 4 active (6.5B active parameters), Apache 2.0, and its config shows MLA-style `kv_lora_rank` attention, a sign of how quickly good ideas spread between families.

### Gemma (Google)

Gemma models are Google's open-weight counterparts to Gemini. Their signature traits are a very large vocabulary (about 262K tokens), large heads (`head_dim` 256), and **interleaved local and global attention**. Gemma 3 (2025) uses five sliding-window layers with a 1,024-token window for every one global layer, with RoPE base 10,000 on local layers and 1,000,000 on global layers. **Gemma 4** (2026, Apache 2.0) keeps the 5:1 pattern (the 31B config has 10 full-attention layers out of 60), adds an MoE variant (26B A4B) and small "effective" models (E2B, E4B) that use per-layer embeddings for on-device use.

## How to Read a Model Card

A Hugging Face model page has a model card (the README) and the files. On the card, look for:

1. **Base or instruct.** "Base", "pt" or no suffix means pretrained only, a text continuer. "Instruct", "it" or "chat" means post-trained to follow instructions with a chat template. Fine-tune from base for new formats; use instruct for assistants.
2. **Parameter counts, total and active.** For MoE models, total parameters set memory needs; active parameters set compute per token. "30B-A3B" means 30B total, 3B active.
3. **Context length,** native and extended, and which scaling method extends it.
4. **Training data and token count,** if disclosed, and the knowledge cutoff.
5. **Recommended sampling settings.** Reasoning models often specify temperature and top-p and warn against greedy decoding.
6. **License and intended use.**
7. **Precision of the files.** `torch_dtype` or `dtype` in the config (often `bfloat16`), and whether quantized variants (FP8, GGUF, AWQ) exist.

The `safetensors` metadata on the model page shows the exact stored parameter count, which you can compare with your own calculation below.

## How to Read config.json

The config is the architecture's blueprint: `transformers` builds the model class named in `architectures` and passes these values to its constructor. Here is the Llama 3.1 8B config (from the copy mirrored by Unsloth, since Meta's repository is gated):

```json
{
  "architectures": ["LlamaForCausalLM"],
  "attention_bias": false,
  "bos_token_id": 128000,
  "eos_token_id": 128001,
  "head_dim": 128,
  "hidden_act": "silu",
  "hidden_size": 4096,
  "intermediate_size": 14336,
  "max_position_embeddings": 131072,
  "mlp_bias": false,
  "model_type": "llama",
  "num_attention_heads": 32,
  "num_hidden_layers": 32,
  "num_key_value_heads": 8,
  "rms_norm_eps": 1e-05,
  "rope_scaling": {
    "factor": 8.0,
    "high_freq_factor": 4.0,
    "low_freq_factor": 1.0,
    "original_max_position_embeddings": 8192,
    "rope_type": "llama3"
  },
  "rope_theta": 500000.0,
  "tie_word_embeddings": false,
  "torch_dtype": "bfloat16",
  "vocab_size": 128256
}
```

| `num_hidden_layers` | Number of decoder blocks | 32 | [Decoder Block](../3-llm-transformer/2-llm-transformer-block.mdx) |

Other fields you will meet:

- **MoE**: `num_local_experts` or `n_routed_experts` (experts per layer), `num_experts_per_tok` (top-k), `n_shared_experts`, `moe_intermediate_size`, and `first_k_dense_replace` (DeepSeek: the first 3 layers are dense). See [Mixture of Experts](../7-llm-mixture-of-experts/0-llm-moe-introduction.mdx).
- **MLA** (DeepSeek, and now some Mistral models): `kv_lora_rank`, `q_lora_rank`, `qk_rope_head_dim`, `qk_nope_head_dim`, `v_head_dim`. See [Multi-Head Latent Attention](../2-llm-attention/6-llm-mla.mdx).
- **Local attention**: `sliding_window`, `sliding_window_pattern` (Gemma 3), or a per-layer `layer_types` list (gpt-oss, Gemma 4, Qwen3.5 onward). See [Sliding Window, Sparse and Linear Attention](../5-llm-flash-attention/5-llm-sparse-and-linear-attention.mdx).

### What changed in transformers v5

Configs written by older `transformers` 4.x releases store `rope_theta` and `rope_scaling` as separate top-level keys, as above. In `transformers` v5 the config object merges them into one dictionary, `rope_parameters`, and the old `rope_theta` attribute no longer exists on the object. Newer `config.json` files (Gemma 4, Mistral Small 4, Qwen3.5 onward) are written that way, and some nest separate RoPE settings per layer type. Loading Qwen3-8B with `transformers` 5.21:

```python
from transformers import AutoConfig

cfg = AutoConfig.from_pretrained("Qwen/Qwen3-8B")     # downloads only config.json
print(type(cfg).__name__)
for name in ["hidden_size", "num_hidden_layers", "num_attention_heads", "num_key_value_heads",
             "head_dim", "intermediate_size", "vocab_size", "max_position_embeddings"]:
    print(f"{name:24} {getattr(cfg, name)}")
print("rope_parameters         ", cfg.rope_parameters)
print("dtype                   ", cfg.dtype)

# KV cache size per token: K and V, for every layer and every KV head
bytes_per_value = 2                                    # bfloat16
kv_per_token = 2 * cfg.num_hidden_layers * cfg.num_key_value_heads * cfg.head_dim * bytes_per_value
print(f"KV cache per token: {kv_per_token / 1024:.0f} KiB; "
      f"for 32,768 tokens: {kv_per_token * 32768 / 2**30:.1f} GiB")
```

```text
Qwen3Config

num_hidden_layers        36
num_attention_heads      32
num_key_value_heads      8
head_dim                 128
intermediate_size        12288
vocab_size               151936

rope_parameters          {'rope_theta': 1000000, 'rope_type': 'default'}

```

The `config.json` file on disk still says `rope_theta` and `torch_dtype`; the v5 config object exposes them as `rope_parameters` and `dtype`. Code that reads `cfg.rope_theta` breaks on v5. If you parse raw JSON, handle both layouts.

The KV cache line uses the formula from [The KV Cache](../10-llm-inference/2-llm-kv-cache.mdx): two tensors (K and V) times layers times KV heads times head size times bytes. Note how GQA pays off: with 32 KV heads instead of 8 it would be four times larger.

## Worked Scenario: Counting Parameters From a Config

You can recompute a dense model's exact parameter count from its config. For a Llama-style block with no biases:

- Attention: $W_Q$ is $d \times (n_h \cdot h)$, $W_K$ and $W_V$ are $d \times (n_\mathrm{kv} \cdot h)$, $W_O$ is $(n_h \cdot h) \times d$, where $d$ is `hidden_size`, $n_h$ the query heads, $n_\mathrm{kv}$ the KV heads and $h$ the head size.
- MLP (SwiGLU): three matrices of $d \times d_\mathrm{ff}$.
- Two RMSNorm weight vectors of size $d$ per layer (Qwen3 adds a $q$ and $k$ norm of size $h$ each).
- Embedding $V \times d$, a final norm of size $d$, and an LM head $V \times d$ unless tied.

$$
N = V d + L\big(2 d n_h h + 2 d n_\mathrm{kv} h + 3 d d_\mathrm{ff} + 2d\big) + d + V d
$$

```python
import json

def dense_params(cfg):
    d, L, V = cfg["hidden_size"], cfg["num_hidden_layers"], cfg["vocab_size"]
    n_h, n_kv = cfg["num_attention_heads"], cfg["num_key_value_heads"]
    hd = cfg.get("head_dim") or d // n_h
    ff = cfg["intermediate_size"]
    attn = d * n_h * hd + 2 * d * n_kv * hd + n_h * hd * d      # W_q, W_k, W_v, W_o (no biases)
    mlp = 3 * d * ff                                            # gate, up, down (SwiGLU)
    norms = 2 * d                                               # two RMSNorm weight vectors
    if cfg.get("model_type") == "qwen3":
        norms += 2 * hd                                         # q_norm and k_norm
    embed = V * d
    head = 0 if cfg.get("tie_word_embeddings") else V * d
    total = embed + L * (attn + mlp + norms) + d + head         # + final norm
    return total, embed, L * attn, L * mlp

# config.json files downloaded from each model's Hugging Face page
for path in ["llama31_8b_config.json", "qwen3_8b_config.json", "mistral_7b_config.json"]:
    cfg = json.load(open(path))
    total, embed, attn, mlp = dense_params(cfg)
    print(f"{path:24} total {total:>13,}  embed {embed / total:5.1%}  attn {attn / total:5.1%}  mlp {mlp / total:5.1%}")
```

```text
llama31_8b_config.json   total 8,030,261,248  embed  6.5%  attn 16.7%  mlp 70.2%
qwen3_8b_config.json     total 8,190,735,360  embed  7.6%  attn 18.4%  mlp 66.4%
mistral_7b_config.json   total 7,241,732,096  embed  1.8%  attn 18.5%  mlp 77.8%
```

All three match the parameter counts Hugging Face reports from the safetensors files exactly. Check Llama 3.1 8B by hand for one layer: attention is $2 \cdot 4096 \cdot 4096 + 2 \cdot 4096 \cdot 1024$, which is 41,943,040; the MLP is $3 \cdot 4096 \cdot 14336$, which is 176,160,768; plus 8,192 for norms, about 218M per layer, times 32 layers is about 7.0B. The embedding and LM head add $2 \cdot 128256 \cdot 4096 \approx 1.05$B, giving 8.03B.

Two lessons. The MLP, not attention, holds most parameters (about 70 percent). And the bigger vocabulary is why "8B" Llama 3 has more parameters than "7B" Mistral with otherwise similar shapes. For FLOPs and training memory from the same config, see [Counting Parameters, FLOPs and Memory](../3-llm-transformer/6-llm-parameter-and-flop-counting.mdx).

:::warning
The "B" in a model name is marketing-rounded and sometimes counts differently (with or without embeddings, vision encoders or MTP modules). DeepSeek-V3's safetensors hold about 685B parameters because they include the multi-token prediction module, while the paper reports 671B for the main model. Always compute from the config when the number matters.
:::

## Common Mistakes

- **Downloading the base model to chat with.** Base models continue text. Use the instruct or chat variant with its chat template, or expect rambling continuations.
- **Taking `max_position_embeddings` as the tested context length.** It is the maximum position the code allows. The model card says what was trained and validated, and which `rope_scaling` must be enabled.
- **Reading `cfg.rope_theta` in transformers v5.** It moved into `cfg.rope_parameters`. Use the dictionary, or read the raw JSON.
- **Confusing total and active parameters for MoE.** All experts must be in memory; only the active ones cost compute per token.
- **Assuming all models share Llama's defaults.** Gemma uses `head_dim` 256 and GeLU-based gating, Qwen3 adds QK-norm, gpt-oss uses attention biases and sliding windows, DeepSeek uses MLA. Read each config.
- **Ignoring the license.** "Open" does not mean "no conditions". Check usage terms before shipping.

## Summary

- Closed models are API-only; open-weight models ship weights, config and code under a license; fully open models also ship data and training code.
- GPT set the decoder-only template; Llama set the open recipe (RMSNorm, SwiGLU, RoPE, GQA); Qwen spread it with many Apache-licensed sizes and later hybrid attention; DeepSeek introduced MLA and fine-grained MoE; Mistral popularized sliding windows and open MoE; Gemma uses big vocabularies and interleaved local and global attention.
- A model card tells you base versus instruct, total versus active parameters, native versus extended context, sampling settings and license.
- `config.json` fields map directly to architecture choices covered in this tutorial; transformers v5 merges RoPE settings into `rope_parameters`.
- From the config you can compute exact parameter counts and KV cache size per token.
