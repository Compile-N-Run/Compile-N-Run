# HTML Attributes and Escaping

Attributes attach information to elements. They can identify a fragment target, specify a resource URL, or enable built-in behavior. Correct syntax prevents subtle mistakes that affect both presentation and interaction.

**Prerequisites:** [Document anatomy](./2-html-document-anatomy.mdx). Put this lesson's fragments inside a complete document's body.

## Names and values

An attribute usually has a name and a quoted value:

```html
<p id="arrival" class="notice">Arrive ten minutes early.</p>
<a href="#arrival">Read arrival instructions</a>
```

The `id` identifies one element within the document. Give each ID a unique value. A fragment URL such as `#arrival` points to the matching ID. A `class` groups elements for styling or scripting and can be reused. Neither attribute changes the element's meaning: this is still a paragraph.

Use quotes consistently, especially around values containing spaces. Attribute names are conventionally lowercase. An ID must not contain ASCII whitespace; descriptive values such as `arrival-details` are easy to link to. Do not invent multiple elements with the same ID simply to apply the same CSS style; use a shared class instead.

## Boolean attributes depend on presence

Some attributes express true by being present and false by being absent:

```html
<button type="button" disabled>Registration opens tomorrow</button>
<button type="button">View session details</button>
```

The first button is disabled. The second is enabled, although it has no scripted action in this example. Writing `disabled="false"` still leaves the attribute present and the button disabled. Remove it to enable the button. The same presence rule applies to boolean attributes such as `required` and `checked`, which you will use in forms.

Not every attribute follows that rule: `aria-expanded="false"` has a meaningful string value. Learn the particular attribute instead of treating all values as booleans.

## Display reserved characters

When you want to show markup as text, escape the characters that would otherwise start markup:

```html
<p>Write &lt;h1&gt; for the page heading.</p>
<p>Repairs &amp; refreshments</p>
<a href="search.html?topic=bikes&amp;level=beginner">Find sessions</a>
```

The browser displays `<h1>` as text in the first paragraph. The encoded ampersand in the URL becomes an ordinary ampersand in the actual destination. Save normal international characters such as `é` directly in a UTF-8 document; character references are not necessary for every non-English character.

Comments can explain an unusual decision:

```html
<!-- The room name matches the sign at the venue. -->
<p>Meet in Room B.</p>
```

Comments remain visible in page source. Do not put passwords, private notes, or secret keys in them.

## Practice and solution

Create a paragraph containing the literal text “Use `<p>` for a paragraph,” give it the ID `paragraph-tip`, and add a link to it.

```html
<p id="paragraph-tip">Use &lt;p&gt; for a paragraph.</p>
<a href="#paragraph-tip">Read the paragraph tip</a>
```

Check that angle brackets display as text, the link updates the fragment in the address bar, and the ID occurs only once.
