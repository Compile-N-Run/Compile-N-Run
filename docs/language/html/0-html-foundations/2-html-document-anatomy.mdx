# HTML Document Anatomy

An HTML document has a predictable outer structure. Understanding that structure helps you decide where information belongs and recognize browser repairs that can hide mistakes.

**Prerequisites:** [A working local HTML file](./1-html-setup.mdx).

## Separate metadata from content

Use this as the starting template for a new file named `anatomy.html`:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Repair Session | Community Workshop</title>
</head>
<body>
  <h1>Repair session</h1>
  <p>Bring a <strong>clean</strong> bicycle.</p>
</body>
</html>
```

The doctype requests standards-mode parsing. It is a declaration, not a visible element or a version number you increment. The `html` element contains the document; its `lang` attribute identifies the primary language, helping pronunciation and other language-sensitive behavior.

The `head` contains document metadata. The UTF-8 declaration tells the browser how to decode text. Keep it near the start of the file. The viewport declaration supports layouts that use the device width; it does not make oversized content responsive by itself. The title identifies the page in browser tabs and other interfaces.

The `body` contains the page content. The visible `h1` and the document `title` serve different purposes. They may share words, but changing one does not update the other.

## Read elements as a tree

In the paragraph, `strong` is a child of `p`. The paragraph and heading are siblings within `body`. Close nested elements in the opposite order from opening them:

```html
<p>Bring <strong>closed-toe <em>shoes</em></strong>.</p>
```

Here emphasis is inside strong importance, and both are inside a paragraph. Consistent indentation helps you see this relationship. Whitespace indentation generally does not create visible layout spacing.

Some elements are void elements, including `meta`, `img`, `input`, and `br`. They cannot contain children and do not have end tags in HTML. Write `<br>`, not `</br>`. A trailing slash does not turn an ordinary HTML element into a self-closing element; for example, a `div` still needs an appropriate closing tag.

## Browser repair is not validation

A browser may display a page even when elements are incorrectly nested. Some end tags, including a paragraph end tag before a heading, can legally be omitted; that is different from crossing element boundaries. The parser has rules for recovering from errors. That recovery can produce a DOM different from what indentation suggests. Do not use “it looks fine” as proof that the structure is correct.

## Practice and solution

Fix this fragment before inserting it into the body:

```html
<p>Session details
<h2>What to bring</h2>
<p>A helmet and <strong>water.</p></strong>
```

A valid correction separates the paragraph from the heading and closes nested elements in order:

```html
<p>Session details</p>
<h2>What to bring</h2>
<p>A helmet and <strong>water.</strong></p>
```

Inspect the DOM to confirm that the heading and paragraphs are siblings. Continue with [attributes and escaping](./3-html-attributes-and-escaping.mdx).
