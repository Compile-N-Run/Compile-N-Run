# HTML Setup and Browser Tools

A reliable editing loop lets you investigate problems instead of guessing. In this lesson you will create a small folder structure, serve it locally, and inspect what the browser received.

**Prerequisites:** Complete [HTML Introduction](./0-html-introduction.mdx) and keep its `index.html` file.

## Organize the project

Use lowercase filenames without spaces. This is a project convention, not an HTML requirement; it makes URLs easier to type and reduces case mistakes when publishing to a server.

```text
workshop-site/
  index.html
  about.html
  images/
```

Copy `index.html` to `about.html`, then change its title and heading to “About the Workshop.” Keep the two pages in the same directory for now. A project is simply files organized into directories; HTML does not require a compilation step.

## Open files or serve them

Double-clicking `index.html` opens a `file:` URL. That is sufficient for early text and link exercises. An HTTP server is useful when testing requests, root-relative paths, and form submission. If Python 3 is installed, open a terminal in `workshop-site` and run:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

On Windows, an installation with the Python launcher may use `py -m http.server 8000 --bind 127.0.0.1` instead. Open `http://127.0.0.1:8000/`. Leave the terminal running; press Ctrl+C there when finished. This is a local development server, not a production hosting setup.

If port 8000 is busy, use 8001 in both the command and URL. If the browser shows a directory listing, confirm the served folder contains `index.html`. If Python is unavailable, continue through the introductory lessons with file URLs or use your editor's local preview server.

## Inspect three different views

Use the browser's “View page source” command to see the received HTML. Then open Developer Tools from the browser menu and find the Elements or Inspector panel. It displays the live DOM, which may differ from source because the HTML parser repairs invalid nesting or scripts modify elements.

Temporarily edit a paragraph in the Inspector. It changes the displayed page but does not rewrite your file. Refresh: the edit disappears. Make lasting changes in your editor.

With an HTTP server running, open the Network panel and reload. Select the document request. A successful request normally has status `200`; a missing file returns `404`. The request URL reveals exactly which resource the browser attempted to load.

## Practice and check

Request `http://127.0.0.1:8000/about.html`, then deliberately request `/missing.html`. Explain why one succeeds and the other fails.

The first path matches a file under the served directory; the second does not. Fixing this requires creating the missing resource or correcting the URL, not changing a paragraph's markup. Check the Network panel to confirm the failing path. Finally, change the real about-page heading in your editor and refresh to verify persistence.
