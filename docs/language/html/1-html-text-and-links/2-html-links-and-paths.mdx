# HTML Links and File Paths

A link combines a destination with text that explains what readers will find. Most broken links in small projects come from misunderstanding the current file's location.

**Prerequisites:** [The local editing workflow](../0-html-foundations/1-html-setup.mdx). Create this structure, copying the starter document into each HTML file:

```text
workshop-site/
  index.html
  about.html
  sessions/
    repair.html
```

## Resolve paths from the current document

In `index.html`, use:

```html
<a href="about.html">About the workshop</a>
<a href="sessions/repair.html">Bicycle repair session</a>
```

In `sessions/repair.html`, use:

```html
<a href="../index.html">Workshop home</a>
<a href="../about.html">About the workshop</a>
```

The `..` segment moves to the parent directory. A path without a leading slash is relative to the current document URL, assuming no `base` element overrides that base URL. This course does not use `base` because explicit paths are easier to reason about.

A leading slash starts at the origin's root: `/about.html` means the root of `http://127.0.0.1:8000`, regardless of the page's directory. It does not mean the project folder under every hosting arrangement. A site deployed under `/workshop/` would need a different root-relative destination. Document-relative paths are convenient for this portable project.

An absolute URL includes a scheme and host, for example `https://www.w3.org/`. A fragment identifies a point within a document:

```html
<a href="sessions/repair.html#equipment">Repair equipment list</a>
```

On `repair.html`, add a matching target:

```html
<h2 id="equipment">Equipment</h2>
<p>Tools are provided. Bring your bicycle and helmet.</p>
```

## Write useful link text

“Repair equipment list” provides more context than “click here.” Readers may review links separately from surrounding paragraphs. Avoid using the raw URL as the label when a short descriptive phrase is clearer.

Use links for navigation and buttons for actions such as submitting a form. A link with `href="#"` is not a working placeholder for an action: it navigates to a fragment and can move the page unexpectedly.

Let links open in the current tab by default. If a real requirement calls for a new tab, tell readers and use an explicit relationship:

```html
<a href="https://www.w3.org/" target="_blank" rel="noopener">
  W3C website (opens in a new tab)
</a>
```

## Practice and solution

From `sessions/repair.html`, link directly to a heading with `id="contact"` in `about.html`.

```html
<a href="../about.html#contact">Contact the organizer</a>
```

Test from the nested page itself. Confirm the destination filename, case, and fragment. A `404` indicates a resource path problem; arriving at the right page without scrolling may indicate a missing or mismatched ID. Short pages may have insufficient scroll distance to place the target at the top even when the fragment works.
