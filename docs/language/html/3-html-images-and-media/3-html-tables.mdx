# HTML Data Tables

Use a table when information has meaningful row and column relationships. A workshop schedule fits: readers compare each session's start time, topic, and room. Page layout does not need a table.

**Prerequisites:** [Lists](../1-html-text-and-links/1-html-lists.mdx). Add this complete table inside a page's main content.

## Start with a simple structure

```html
<table>
  <caption>Saturday workshop schedule</caption>
  <thead>
    <tr>
      <th scope="col">Start time</th>
      <th scope="col">Session</th>
      <th scope="col">Room</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>09:30</td>
      <th scope="row">Bicycle repair</th>
      <td>Garden room</td>
    </tr>
    <tr>
      <td>11:00</td>
      <th scope="row">Simple sewing</th>
      <td>Studio</td>
    </tr>
  </tbody>
</table>
```

The `caption` names the table as a whole. `tr` defines a row, `th` a header cell, and `td` a data cell. The scope attribute identifies whether a header describes a column or a row. In this example, a reader encountering “Garden room” can associate it with the Room column and Bicycle repair row.

`thead` and `tbody` group rows structurally. They do not by themselves make every cell a header. A cell becomes a header because you choose `th`, not because its text is bold or because it appears in the first row.

## Keep comparisons understandable

If a value is unknown, write a meaningful explanation such as “To be announced” rather than leaving readers to infer whether an empty cell means zero, missing data, or not applicable.

Use consistent units in headers when appropriate: “Duration (minutes)” is clearer than unexplained numbers. Keep dates and times unambiguous in the surrounding context. A caption should identify the dataset, while nearby prose can explain an unusual calculation or convention.

Merged cells with `rowspan` and `colspan` can represent real groupings, but they complicate reading and header relationships. Begin with a rectangular table. If a complex header arrangement is unavoidable, learn the required associations and test with assistive technology rather than adding spans solely for visual symmetry.

## Layout and small screens

Do not use tables to position a sidebar next to an article. CSS handles that arrangement. Conversely, do not replace genuine tabular data with disconnected `div` elements just to imitate a visual table.

For a wide table, a later CSS enhancement may provide horizontal scrolling. Make sure the content remains keyboard-accessible and header relationships remain intact. Avoid shrinking text until it becomes unreadable.

## Practice and solution

Add a Duration column and a third session. Give each session a row header and each column a column header.

Your new heading should be `<th scope="col">Duration (minutes)</th>`, with one corresponding data cell in every body row. The third session's name should be `th scope="row"`. Check that every row has the same number of effective columns and that the caption still describes the full table.
