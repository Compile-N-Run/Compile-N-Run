# HTML Audio, Video, and Captions

A recording should be usable when someone cannot hear the audio, cannot see important visuals, or prefers reading. Plan those alternatives before publishing the media.

**Prerequisites:** [Resource paths](../1-html-text-and-links/2-html-links-and-paths.mdx). This example requires your own short recording; HTML markup does not generate the media file. Create a `media` folder with a browser-playable MP4 named `intro.mp4`, a caption file named `intro-en.vtt`, and a matching written transcript in your page.

## Add native playback controls

```html
<video controls preload="metadata" width="640">
  <source src="media/intro.mp4" type="video/mp4">
  <track kind="captions" src="media/intro-en.vtt"
         srclang="en" label="English" default>
  <p>Your browser does not support embedded video.</p>
</video>
<p><a href="media/intro.mp4">Download the workshop introduction video</a></p>
<h2>Introduction transcript</h2>
<p>[The presenter points to the tool table.]</p>
<p>Welcome. Shared tools are on the table beside the entrance.</p>
```

`controls` asks the browser to provide playback controls. `preload="metadata"` is a loading hint, not a promise of an exact download amount. Keep the visible download link outside the video so it remains available even when the browser supports the element but cannot decode the file.

The MP4 container does not guarantee a supported codec. Test the actual export in the browsers you intend to support. For narrow layouts, apply a suitable CSS rule such as `video { max-width: 100%; height: auto; }`.

## Write synchronized captions

Save this UTF-8 text as `media/intro-en.vtt`, adjusting timing and wording to match the recording:

```text
WEBVTT

00:00:00.000 --> 00:00:02.000
[Light music]

00:00:02.000 --> 00:00:06.000
Welcome. Shared tools are on the table beside the entrance.
```

Captions include relevant sounds as well as speech. Subtitles typically provide a translation or dialogue text, while captions support people who cannot hear the audio. A transcript provides a separate reading experience but does not replace synchronized captions for video.

If important visual information is not expressed by the audio, provide an appropriate audio-described version or another suitable description arrangement. The example transcript describes a gesture, but real accessibility needs depend on the recording's content and required conformance level.

Serve the files through your local HTTP server when testing tracks. File-URL restrictions can interfere with loading local caption resources.

## Audio-only content

For an audio recording, use the same native-controls approach and place a transcript beside it:

```html
<audio controls src="media/welcome.mp3"></audio>
<p><a href="media/welcome.mp3">Download the audio introduction</a></p>
```

This separate example requires its own actual MP3 file. Avoid autoplay: unexpected sound can disrupt reading and is often restricted by browsers anyway.

## Practice and check

Record a five-second introduction, transcribe it, and make a matching WebVTT track. Check playback, keyboard access, captions on and off, and transcript accuracy. A successful solution has real files at the stated paths and conveys meaningful sounds and visuals, not just syntactically correct markup.
