# HTML Details and Summary

A disclosure lets readers reveal additional information when they need it. HTML's `details` and `summary` elements provide this behavior without JavaScript.

**Prerequisites:** [Semantic containers](./1-html-articles-and-sections.mdx). Add the example inside your page's main content.

## Build a useful disclosure

```html
<h2>Frequently asked questions</h2>
<details>
  <summary>Can I borrow tools?</summary>
  <p>Yes. Shared tools are available during the session.</p>
  <p>Please return each tool to the labeled storage box.</p>
</details>
<details>
  <summary>Can I bring a friend?</summary>
  <p>Each participant needs their own confirmed place.</p>
</details>
```

The `summary` is the disclosure's visible label and should be the first child of `details`. Activating it toggles the remaining content. A meaningful question makes the purpose clear before someone opens it.

Open the page, activate a summary with the pointer, and then test it from the keyboard. Native browser presentation varies, but the fundamental expand/collapse behavior requires no script. Preserve the focus indicator and enough visual indication that the summary is interactive when you later add CSS.

## Choose the initial state

Add the boolean `open` attribute to expand a disclosure initially:

```html
<details open>
  <summary>What should I bring?</summary>
  <ul>
    <li>A clean bicycle</li>
    <li>A helmet</li>
  </ul>
</details>
```

`open="false"` still means open because the attribute is present. Remove `open` to start collapsed. The reader can still close a disclosure that starts open.

Do not hide essential instructions behind a question readers may never open. Location, start time, and immediate safety information often belong in ordinary visible content. A disclosure is helpful for supplementary detail, not for solving every long-page problem.

## Avoid unnecessary custom behavior

Do not add `role="button"` or a manually maintained `aria-expanded` to the native summary just to duplicate built-in semantics. A separate script that updates only the visual icon can drift out of sync with the actual disclosure state.

Keep the summary label simple. Putting a link or another control inside it creates competing interactive targets and can make activation confusing. Place related links in the expanded content instead.

This pattern is a disclosure, not a dialog box: it remains in the normal document flow and does not trap focus. It is also not a substitute for tabs. Different widgets have different interaction expectations.

## Practice and solution

Create a collapsed question, “Is the venue step-free?”, with an answer and a link to the about page's contact section.

```html
<details>
  <summary>Is the venue step-free?</summary>
  <p>The teaching room is reached through a level entrance.</p>
  <p><a href="about.html#contact">Ask about access requirements</a></p>
</details>
```

Use accurate venue information in a real site. Check that the answer starts hidden, the summary toggles it, and the link becomes reachable after opening. No JavaScript should be necessary.
