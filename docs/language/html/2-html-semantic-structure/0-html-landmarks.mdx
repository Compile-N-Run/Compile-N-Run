# HTML Page Landmarks

A page usually has site-wide information, navigation, unique content, and supporting information. Semantic elements describe these roles so people and software can understand the structure without relying on position or color.

**Prerequisites:** [Heading hierarchy](../1-html-text-and-links/0-html-headings-and-paragraphs.mdx). Replace the body of your workshop home page with this example.

## Give the page recognizable regions

```html
<header>
  <p>Community Workshop</p>
  <nav aria-label="Main">
    <ul>
      <li><a href="index.html" aria-current="page">Home</a></li>
      <li><a href="about.html">About</a></li>
    </ul>
  </nav>
</header>
<main id="main-content">
  <h1>Learn useful skills together</h1>
  <p>Join a small session led by a local volunteer.</p>
  <h2>Next session</h2>
  <p>Bicycle repair for beginners.</p>
</main>
<aside aria-labelledby="newsletter-heading">
  <h2 id="newsletter-heading">Workshop newsletter</h2>
  <p>Ask the organizer about future sessions.</p>
</aside>
<footer>
  <p>Community Workshop is a fictional learning project.</p>
</footer>
```

`header` introduces a page or a section. At the body level, it commonly represents the site banner. `nav` identifies a major navigation region, not every collection of links. `main` contains this page's dominant content; keep one visible main region for this ordinary document.

`aside` contains tangential material that relates to the surrounding content. It does not simply mean “a box on the right.” Essential workshop instructions belong in the main content even if a future design puts them in a sidebar. `footer` holds closing information for its page or section.

These elements do not create a multi-column layout. Their default rendering may look like ordinary blocks. CSS determines positioning; the HTML should remain logical when read from top to bottom.

## Names and context matter

The navigation's `aria-label` provides a short name. If a page has a second navigation region for session topics, a different label such as “Session topics” helps users distinguish them. Do not add redundant words such as “navigation” to every label when the role already conveys that idea.

`aria-labelledby` names the aside from its visible heading. Keep the referenced ID correct and unique. Prefer visible labels when suitable, so sighted readers and assistive technology users get consistent information.

Nested headers and footers can describe articles or sections without acting as the page-level banner and content-information landmarks. Context matters; adding a semantic-looking tag does not guarantee a particular landmark role everywhere.

## Practice and check

Move a page's site navigation into `nav`, its unique lesson content into `main`, and its copyright or project note into `footer`. Keep their source order sensible.

A correct result has one visible main region, a meaningful top-level heading inside it, and no essential lesson paragraphs hidden in a tangential aside. Inspect the accessibility tree if your browser exposes one, and compare region names with the visible page.
