# HTML Form Labels and Controls

A form is an interface for collecting information. Before choosing controls, decide what information is genuinely needed and explain why the visitor should provide it.

**Prerequisites:** [Document structure](../0-html-foundations/2-html-document-anatomy.mdx) and [attributes](../0-html-foundations/3-html-attributes-and-escaping.mdx). Create `register.html` from your document template. This lesson practices controls; submission is covered separately.

## Associate every control with a label

Put this fragment in the body:

```html
<h1>Practice registration form</h1>
<p>This local example does not register you for an event.</p>
<form>
  <p>
    <label for="full-name">Name</label>
    <input id="full-name" name="full_name" autocomplete="name">
  </p>
  <p>
    <label for="email">Email address</label>
    <input id="email" name="email" type="email" autocomplete="email"
           aria-describedby="email-help">
  </p>
  <p id="email-help">Use an address where the organizer could contact you.</p>
  <p>
    <label for="questions">Questions for the organizer</label>
    <textarea id="questions" name="questions" rows="4"></textarea>
  </p>
</form>
```

The label's `for` value matches a unique control `id`. Clicking the label should focus its control. This association also supplies an accessible name. The `name` attribute has a different purpose: it identifies the key used when data is submitted. A label can work perfectly even when a missing name causes a control's value to be omitted from submission.

The `email` input type conveys an email-shaped value and supports browser validation. It does not prove that the address exists or that the visitor owns it. The `autocomplete` tokens describe the information expected so browsers can offer appropriate completion.

`textarea` is for multiline text and has a closing tag. Its initial content goes between its tags. Ordinary text inputs instead use a `value` attribute for an initial value.

## Instructions must remain available

`aria-describedby` connects the email field to supplementary text. It does not replace the label; it adds a description. Keep the instructions visible so everyone benefits.

A placeholder disappears as someone types and should not be the only label. If you add a placeholder as an example, make the real label and any format requirements explicit outside the field.

Avoid asking for private information unnecessarily. In this practice page, use invented data. A form with no explicit action can submit to the current page if a browser triggers implicit submission; it still does not gain a database or mail service. You will set an explicit demonstration destination in the submission lesson.

## Practice and solution

Add a telephone field with a label and optional completion hint:

```html
<label for="phone">Telephone number (optional)</label>
<input id="phone" name="phone" type="tel" autocomplete="tel">
```

Do not use `type="number"` for phone numbers: a phone number is an identifier that may contain a plus sign, spaces, and leading zeros, not a quantity for arithmetic. Check that clicking the label focuses the field and Tab moves through the controls in source order.
