# HTML Form Groups and Choices

The control should match the decision. Use radio buttons for one choice from a small set, checkboxes for independent yes-or-no choices, and a select when a compact list is useful.

**Prerequisites:** [Labels and controls](./0-html-form-labels-and-controls.mdx). Add these fragments inside the same form.

## Group related radio buttons

```html
<fieldset>
  <legend>Choose one session</legend>
  <p>
    <input type="radio" id="repair" name="session" value="repair" required>
    <label for="repair">Bicycle repair</label>
  </p>
  <p>
    <input type="radio" id="sewing" name="session" value="sewing" required>
    <label for="sewing">Simple sewing</label>
  </p>
</fieldset>
```

The shared `name` makes these radios one group, so selecting one clears the other. Each control still needs its own unique ID and label. `value` identifies the chosen option in submitted data; it is not the visible label.

`fieldset` groups related controls and `legend` explains the group. A heading above unrelated controls does not provide the same programmatic grouping. Keep legends concise while including enough context to understand the question.

A required radio group needs a selected option to pass native validation. Here the attribute is repeated consistently across the group to make the requirement obvious in the source. Do not preselect a value simply to make validation pass if the person needs to make an informed choice.

## Independent options use checkboxes

```html
<fieldset>
  <legend>Optional equipment to borrow</legend>
  <p>
    <input type="checkbox" id="pump" name="equipment" value="pump">
    <label for="pump">Pump</label>
  </p>
  <p>
    <input type="checkbox" id="toolkit" name="equipment" value="toolkit">
    <label for="toolkit">Tool kit</label>
  </p>
</fieldset>
```

Both can be selected. When submitted, repeated names can produce multiple values. Unchecked checkboxes are generally omitted from the submitted entry list, so a server must not assume every possible checkbox appears with an explicit false value. If a checkbox lacks a value, the default submitted value is `on`, which is often less informative than a deliberate identifier.

## A compact choice list

```html
<label for="experience">Repair experience</label>
<select id="experience" name="experience" required>
  <option value="">Choose an option</option>
  <option value="none">No previous experience</option>
  <option value="some">Some basic repairs</option>
</select>
```

For this ordinary single-select control, the empty first option prompts a deliberate selection and fails the required constraint. The selected option's value is submitted, while its text is the human-readable label.

## Practice and check

Add three radio options for morning, afternoon, and evening. Give them one shared name, unique IDs, and distinct values. Then add a separate optional checkbox for borrowing a helmet.

The correct solution lets you select only one time but independently toggle the helmet. Use the keyboard as well as the pointer; native radio groups generally support arrow-key movement once entered. Avoid replacing native controls with styled generic elements that would require recreating this behavior.
