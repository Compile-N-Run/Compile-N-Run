# HTML Metadata and Language

Metadata describes a document to browsers and other consumers. It helps identify the page, decode its text, and interpret its language. It is separate from the visible content, though the two should agree.

**Prerequisites:** [Document anatomy](../0-html-foundations/2-html-document-anatomy.mdx). Update the head of your workshop detail page.

## Give each page its own identity

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Bicycle Repair Session | Community Workshop</title>
  <meta name="description"
        content="Prepare for a beginner bicycle repair session, review the schedule, and find the equipment list.">
</head>
<body>
  <h1>Bicycle repair session</h1>
  <p>Learn basic checks with a local volunteer.</p>
</body>
</html>
```

The title should identify this specific page. If every tab says only “Community Workshop,” switching between the schedule and registration pages becomes harder. Put the distinguishing topic first, followed by the site name when useful.

A description summarizes the page honestly. Search services may use it when presenting a result, but HTML does not force a service to display your exact text or improve a ranking. Avoid adding a long list of unrelated keywords. Good metadata supports useful content; it does not substitute for it.

Keep the character encoding declaration near the start of the head. Save the actual file in UTF-8 too: a declaration cannot repair text that was already saved with an incompatible encoding.

## Declare language where it changes

The language on `html` establishes the document's primary language. Mark a meaningful change within the page:

```html
<p>Our welcome sign says <span lang="es">Bienvenidos</span>.</p>
```

Language information can help assistive technologies choose pronunciation. It does not translate the text. For languages written right to left, direction is a separate concern, commonly expressed with `dir="rtl"`; changing `lang` alone is not a complete layout strategy.

A site with translated pages should link to real translated documents. Do not label the same English page as a Spanish version merely to create a language selector.

## Add resource metadata only when real

A favicon can be linked from the head if the referenced file exists:

```html
<link rel="icon" href="images/favicon.svg" type="image/svg+xml">
```

This example requires an actual SVG icon at that path. Metadata links are still resource references that can break. Similarly, a canonical URL is a publishing decision about the preferred public URL; do not invent one using a local development address.

The viewport declaration lets a small-screen layout use the device width. Do not disable user zoom with restrictive viewport options. Readers may need magnification even when your layout already fits a small screen.

## Practice and solution

Give `index.html`, `about.html`, and `register.html` distinct titles and descriptions. A suitable registration title is “Practice Registration | Community Workshop,” with a description that explicitly calls it a demonstration. Open all three tabs and confirm you can distinguish them without switching to the page contents. Check that the language matches the actual prose.
