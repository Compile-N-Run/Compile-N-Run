# HTML Validation and Debugging

Different failures need different tools. Invalid nesting is a markup problem; a missing photo is a resource problem; an unclear label is a usability problem. A disciplined diagnosis prevents random edits.

**Prerequisites:** [Browser tools](../0-html-foundations/1-html-setup.mdx) and [accessibility checks](./1-html-accessibility-checks.mdx).

## Validate a complete document

Open the [Nu HTML Checker](https://validator.w3.org/nu/) and use its text-input option for a non-private practice document. Paste the complete source, including the doctype, head, and body. The checker reports conformance issues; it does not execute your entire application workflow.

Start with the first reported error, because one malformed tag can produce several later messages. Fix it in your actual source file, save, and check again. Review warnings individually rather than hiding them automatically.

Try this deliberately broken fragment inside a complete document:

```html
<p><strong>Bring water.</p></strong>
<label for="email">Email</label>
<input id="contact" name="email" type="email">
```

The first line crosses element boundaries. The label references an ID that is not the input's ID. A correction is:

```html
<p><strong>Bring water.</strong></p>
<label for="email">Email</label>
<input id="email" name="email" type="email">
```

Do not assume every missing end tag is an error: HTML permits omission of some tags in specific contexts. This course usually writes explicit closing tags to make structure easier to read. Crossed nesting and duplicate IDs are different issues from permitted omission.

## Compare source with the DOM

If the page appears in an unexpected order, compare View Source with the Inspector. A browser can repair invalid markup and move or implicitly close elements. The displayed DOM is what later CSS and JavaScript operate on, even when it differs from your intended source structure.

Reduce a confusing example to the smallest document that reproduces the problem. Remove unrelated sections in a copy of the file rather than destroying your working page. Add them back one at a time after identifying the cause.

## Inspect resource requests

For a missing image or broken link, open the Network panel and reload. Check the requested URL and status. A `404` suggests a wrong path or absent file. A successful `200` does not prove the resource has the expected format; inspect the response and confirm it is not an HTML error page returned under an image URL.

If a change does not appear, confirm you saved the right file and loaded the right URL. Then check caching. Avoid treating every issue as a cache problem before checking these simpler causes.

## Practice and solution

Create three deliberate defects in a copy of your page: a mismatched label ID, a missing image filename, and an incorrect current-page indicator. Diagnose each with the most useful evidence.

The checker or accessibility inspection helps expose the label association; the Network panel identifies the missing image request; manual navigation review catches the incorrect `aria-current` value. A page can pass markup validation while still making a false statement about which page is current. Finish by fixing the source and repeating all three checks.
