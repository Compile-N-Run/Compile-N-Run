# The CSS Cascade and Specificity

When two declarations set the same property on the same element, the cascade decides which one wins. “The last rule wins” is only true after higher-priority comparisons tie. Increasing selector specificity is therefore not a universal fix.

## Start with an ordinary conflict

Add this HTML to your practice page and these rules to an otherwise empty stylesheet:

```html
<p class="notice" id="lesson-note">Save your work before refreshing.</p>
```

```css
.notice { color: navy; }
p { color: green; }
.notice { color: maroon; }
```

The paragraph is maroon. Within this same origin, importance, and layer, a class selector beats a type selector; the later of the two equally specific `.notice` rules wins.

Specificity compares three counts from left to right: IDs; classes, attributes, and pseudo-classes; then types and pseudo-elements. `.notice` has `(0, 1, 0)`, while `p.notice` has `(0, 1, 1)`. These are ordered counts, not a base-ten score: adding many type selectors does not overtake one class selector. Combinators and the universal selector add no specificity. `:where()` and its arguments add none; `:is()`, `:not()`, and `:has()` use their most specific selector argument.

## Layers come before selector specificity

Replace the CSS with this experiment:

```css
@layer base, components;

@layer base {
  #lesson-note { color: red; }
}

@layer components {
  .notice { color: #14532d; }
}
```

The paragraph is green even though the red rule uses an ID. For normal author declarations, the later layer wins before specificity is compared. Add an unlayered `p { color: navy; }` and navy wins over both layers. Normal unlayered author rules outrank normal layered author rules.

`!important` changes the comparison: important declarations outrank normal declarations, and layer priority reverses for important declarations. Earlier layers' important declarations outrank later layers', and layered important declarations outrank unlayered important declarations. Avoid using importance as a routine styling strategy; it makes this reasoning harder.

## Know the boundary of the simple model

For ordinary stylesheet conflicts in this course, ask: does the rule match, does its condition apply, is it important, which layer contains it, how specific is it, and which tied declaration comes later? These examples use one author origin and no scoped rules or active animations.

The full cascade also includes browser and user origins, animations, transitions, and scoping proximity. User important declarations can beat author important declarations, supporting user preferences. Inline author styles also have special precedence within the relevant importance level; they are not just another ID selector. Consult the [cascade ordering specification](https://www.w3.org/TR/css-cascade-5/#cascade-sort) before treating the simplified sequence as an exhaustive algorithm.

Developer tools show overridden declarations crossed out. Inspect the winning rule and its source before editing. A declaration that never matched is a selector problem; one crossed out by a competing rule is a cascade problem.

## Exercise and solution

In the layer example, make the base layer's red rule win by changing only the initial layer-order declaration. Do not add importance or selectors.

```css
@layer components, base;
```

Remove the unlayered navy rule first. The paragraph becomes red because `base` is now the later layer. Changing the order of the layer blocks alone does not change an order already established by the initial declaration.
