# Inheritance and Browser Defaults

A paragraph can be blue even when no rule directly sets its color. Some properties inherit their parent's computed value. Others use their own initial value unless a matching declaration supplies something else. Inheritance fills gaps after the cascade; it does not compete with declarations directly targeting the child.

## Follow a value through a document

Start a fresh copy of the starter page, replace the entire stylesheet with the CSS below, and replace its main contents with:

```html
<section class="note">
  <h1>Inheritance experiment</h1>
  <p>A paragraph with <strong>important words</strong>.</p>
  <p class="special">A paragraph with its own color.</p>
  <button type="button">Practice button</button>
</section>
```

```css
.note {
  color: #234e9b;
  font-family: Georgia, serif;
  padding: 1rem;
  border: 2px solid currentColor;
}

.special { color: #9f1239; }
button { font: inherit; }
```

The ordinary paragraph and its strong text inherit blue. The special paragraph is dark red because a value assigned directly to it wins over an inherited value, regardless of the parent's selector specificity. The section's padding and border are not copied onto every descendant: these properties are not inherited by default.

The button uses the section's font because `font: inherit` explicitly requests inheritance. Form controls often have browser styles that make their typography differ from surrounding text. `currentColor`, used on the section's border, means that element's computed `color`; it is useful for keeping a decoration aligned with text.

## Reset with a purpose

Browsers supply their own styles for common HTML elements. That is why an unstyled heading is larger than a paragraph and lists have markers. Those defaults are useful. Start with a small reset whose effects you understand:

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}

body { margin: 0; }

button,
input,
select,
textarea {
  font: inherit;
}

img {
  max-width: 100%;
  height: auto;
}
```

The universal selector does not automatically include pseudo-elements, which is why the first rule lists them. The [box model lesson](../1-visual-design/05-css-box-model.mdx) explains border-box sizing. Keep list markers and focus indicators unless your design provides a considered replacement. A large reset copied without review can remove behavior you depend on.

## Four keywords worth distinguishing

`inherit` requests the parent's computed value, even for a property that normally does not inherit. `initial` requests the property's CSS initial value, not the browser's usual style for that HTML element. For example, `display: initial` does not restore a paragraph's browser-provided block display.

`unset` acts like `inherit` for inherited properties and `initial` for non-inherited ones. `revert` rolls the cascade back to an earlier origin, which is often useful when restoring browser styling. `revert-layer` instead rolls back the current cascade layer. These are precise tools, not interchangeable “reset” commands. The [W3C defaulting definitions](https://www.w3.org/TR/css-cascade-5/#defaulting) describe the distinctions.

## Exercise and solution

Add `padding: inherit` to `.special`. Predict the result before reloading: that paragraph gains `1rem` padding because its parent section has that computed value. Its sibling remains unpadded.

Now remove the padding experiment and make `.special` use the section's color again:

```css
.special { color: inherit; }
```

Verify in developer tools that the paragraph is blue and its inherited value comes from `.note`. Finally, change the section to a different color. Both paragraphs should follow without editing their selectors. This is the foundation for the [custom property and component](../4-responsive-design/20-css-custom-properties.mdx) patterns later in the course.
