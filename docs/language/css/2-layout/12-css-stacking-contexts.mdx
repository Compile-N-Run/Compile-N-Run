# Stacking Contexts and z-index

`z-index` is not a page-wide ranking of every element. Elements paint within stacking contexts, and a context's descendants are grouped together when that context competes with its siblings. A child with a huge number cannot leap out of a lower parent context.

A positioned element with a non-auto `z-index` can create a stacking context. So can properties such as `transform` and an `opacity` below one. Fixed and sticky positioning create contexts too. Flex and grid items have their own useful z-index behavior even without positioning. You do not need to memorize every trigger immediately, but inspect ancestors when an overlap is surprising.

## Build an overlap you can explain

Use this HTML and CSS in your practice files:

```html
<div class="stage">
  <section class="panel panel-a">
    A
    <span class="label">A's label: z-index 999</span>
  </section>
  <section class="panel panel-b">B: z-index 2</section>
</div>
```

```css
body { font: 1rem/1.5 system-ui, sans-serif; padding: 1rem; }
.stage { position: relative; min-height: 16rem; }
.panel {
  position: absolute;
  width: 15rem;
  height: 10rem;
  padding: 1rem;
  box-sizing: border-box;
}
.panel-a { z-index: 1; background: #dbeafe; }
.panel-b {
  z-index: 2;
  top: 4rem;
  left: 4rem;
  background: #bbf7d0;
}
.label {
  position: absolute;
  z-index: 999;
  top: 5rem;
  left: 2rem;
  padding: 0.25rem;
  background: #fef3c7;
}
```

Panel B covers the overlapping part of A's label. A is its own stacking context at level 1; B competes with that whole context at level 2. The label's 999 only orders it inside A's context. Changing the label to 999999 does not solve the conflict.

Change `.panel-a` to `z-index: 3`. Now its entire context paints above B. This demonstrates why changing the correct ancestor matters more than the magnitude of the number.

## Make layering intentional

For a real component, `isolation: isolate` creates a stacking context deliberately. This can keep local decorations from interacting with unrelated components. A small shared scale for page-level layers is easier to reason about than accumulating enormous numbers.

Clipping is separate from stacking. If a parent's overflow clips a tooltip, increasing z-index does not necessarily reveal it outside the clipping boundary. Identify whether the problem is paint order or clipping before changing styles.

Native modal dialogs opened with `showModal()` use the browser's top layer, which is separate from ordinary document stacking. A giant z-index is not a substitute for correct dialog semantics, keyboard behavior, and focus management. Those behaviors require HTML and, for a custom interaction, JavaScript; CSS alone cannot implement them completely.

## Exercise and solution

Remove panel A's z-index declaration while leaving it positioned. Its label can now participate in the stage's surrounding stacking context, and its high z-index can paint above B. Then add `isolation: isolate` to A and observe the grouping return.

Your explanation should name the nearest stacking context, not simply say that “higher numbers win.” Restore the original example and inspect each ancestor in developer tools. This method carries into the [debugging workflow](../5-production/23-css-debugging-and-maintainability.mdx).
