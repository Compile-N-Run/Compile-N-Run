# Sizing, Intrinsic Content, and Overflow

An element's size is negotiated among its content, specified dimensions, constraints, and layout mode. A width declaration is only one input. Learning to identify the other inputs is more productive than repeatedly reducing the width until a screenshot looks right.

Use `width` or `inline-size` for a preferred size, `max-width` or `max-inline-size` for an upper bound, and `min-width` or `min-inline-size` for a lower bound. Logical inline and block sizes follow the writing mode; in the examples here they correspond to width and height.

## Reproduce overflow first

Add the following to your practice page, then resize the browser:

```html
<article class="card">
  <h1>Export ready</h1>
  <p class="filename">learningnotebook2026verylongunbrokenexportfilename012345678901234567890123456789.json</p>
  <pre><code>const topic = "CSS sizing";
console.log(topic);</code></pre>
</article>
```

```css
* { box-sizing: border-box; }
body { margin: 0; padding: 1rem; font: 1rem/1.6 system-ui; }
.card {
  max-inline-size: 32rem;
  padding: 1rem;
  border: 2px solid #94a3b8;
}
.filename { overflow-wrap: anywhere; }
pre {
  max-inline-size: 100%;
  overflow-x: auto;
  padding: 1rem;
  background: #e2e8f0;
}
```

The filename wraps when necessary. The code preserves whitespace and can scroll horizontally inside its own region. Those are different content requirements; forcing both to wrap would damage the code's formatting, while refusing to wrap both could widen the whole page.

## Understand content-based minimums

`min-content` describes a size based on the tightest wrapping opportunities; `max-content` describes a size without optional line wrapping. These concepts influence layout even when you never type those keywords.

Flex and grid items can have automatic minimum sizes based on content. A shrinking column may therefore refuse to become narrower than a long string. The common fix is to let the item shrink with `min-inline-size: 0`, then deliberately wrap or scroll its content. Grid tracks often need `minmax(0, 1fr)` for the same reason. These rules solve different levels of the layout and should be applied to the element actually imposing the constraint.

## Choose an overflow policy

`overflow: visible` allows content to paint outside the box. `hidden` clips it and can establish a scroll container even without visible scrollbars. `auto` adds scrolling when needed. `clip` clips without creating a scroll container. The choice can affect sticky positioning as well as appearance.

Do not add `overflow-x: hidden` to the entire page simply to remove a scrollbar. That can conceal unreachable text, clipped focus rings, or a genuinely oversized child. Locate the source first using the box-model tools.

For ordinary text sections, prefer natural height or `min-block-size` over a fixed height. A card whose content doubles should usually grow, not crop its last paragraph.

## Exercise and checks

Give the card `inline-size: 100%`, duplicate its paragraph, and enlarge the browser text. It should remain within the body gutter and grow vertically. Now remove `overflow-wrap: anywhere` and observe the long filename; restoring it should solve that specific overflow.
