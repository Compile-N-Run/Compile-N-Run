# Normal Flow and Display

Normal flow is the browser's default way of arranging content. It already produces a useful document: paragraphs follow headings, text wraps into lines, and later content moves down when earlier content grows. Preserve that behavior unless a layout requirement calls for something else.

In a typical horizontal writing mode, block boxes stack vertically and an auto-width block fills its available inline space. Inline content flows within line boxes and can wrap. These are layout behaviors, not HTML semantics: CSS can change how an element participates without changing what it means.

## Compare three display values

Place these paragraphs inside the starter document and add the stylesheet:

```html
<p>Read <a class="tag inline" href="#notes">inline notes</a> today.</p>
<p>Read <a class="tag inline-block" href="#notes">inline-block notes</a> today.</p>
<p>Read <a class="tag block" href="#notes">block notes</a> today.</p>
<section id="notes"><h2>Notes</h2><p>Compare the boxes above.</p></section>
```

```css
body { font: 1rem/1.6 system-ui, sans-serif; padding: 1rem; }
.tag {
  width: 10rem;
  padding: 0.25rem 0.5rem;
  border: 1px solid #234e9b;
  background: #dbeafe;
}
.inline { display: inline; }
.inline-block { display: inline-block; }
.block { display: block; }
```

The inline link remains part of its sentence, and its declared width does not size it like a block. The inline-block link stays inline but accepts the width and forms one atomic box. The block link occupies its own block row, splitting the surrounding inline content around it.

Vertical padding on a non-replaced inline element can paint outside the line's usual space without increasing line-box height as a block's padding would. Avoid making a multi-line paragraph's links into oversized painted boxes without testing how lines overlap.

## Separate outer and inner layout

`display: flex` normally makes the element a block-level flex container: its outside participates in its parent's layout, while its children use flex layout. Likewise, `display: grid` establishes grid layout for its children. Setting flex on a card does not automatically change how that card's siblings are arranged; set the layout on their parent.

`display: flow-root` establishes a new block formatting context. It can contain floats and prevent certain parent-child margin-collapse surprises without pretending overflow should be hidden. Floats remain useful for wrapping prose around an image, but use Flexbox or Grid for the multi-column interface patterns in this course.

`display: none` removes the element's boxes and usually removes that content from the accessibility tree as well. `visibility: hidden` preserves layout space while hiding the element. Neither is a general substitute for a carefully designed disclosure component or a visually hidden accessible label.

## Exercise and solution

Create a small row of links that have internal padding but may wrap onto another line naturally. You can use inline-block for this simple experiment:

```css
.tag {
  display: inline-block;
  width: auto;
  margin-block: 0.25rem;
  padding: 0.4em 0.7em;
}
```

Verify that longer text expands a link and narrow screens wrap the row. For consistent spacing between many items, continue to [Flexbox patterns](../3-flexbox-and-grid/14-css-flexbox-patterns.mdx). If an item grows beyond its parent, study [intrinsic sizing and overflow](./10-css-sizing-and-overflow.mdx) before forcing a fixed height.
