# Media Queries and User Preferences

A media query conditionally applies CSS according to the environment. Width queries are useful for page layout; preference queries let an interface respond to choices such as a dark color scheme or reduced motion. A query does not inherently outrank ordinary rules: its declarations still participate in the cascade.

## Add a content-driven layout change

Use a fresh starter page with a `.layout` wrapper around a main content section and an aside. Apply the base layout first:

```css
.layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  gap: 1.5rem;
}

@media (min-width: 48rem) {
  .layout {
    grid-template-columns: minmax(0, 2fr) minmax(14rem, 1fr);
  }
}
```

The single-column layout applies everywhere. At or above the threshold, the later matching rule supplies two columns. A media query does not test a device model or physical screen pixels. Resize the viewport to see the condition become active in developer tools.

You can combine conditions with `and`. Do not assume a wide viewport implies a mouse, or that a small one implies touch. Input capabilities and layout space are separate facts.

## Add hover as an enhancement

If a decorative hover effect is only useful with accurate pointing, guard it:

```css
@media (hover: hover) and (pointer: fine) {
  .course-link:hover {
    text-decoration-thickness: 0.2em;
  }
}
```

Keep the link's text and focus indicator visible regardless. These features describe the primary input's capabilities; hybrid devices may have additional inputs. Never hide essential content behind hover or infer all user behavior from one media query.

## Respect color preferences

A small theme can define paired text and surface colors:

```css
:root {
  color-scheme: light;
  --surface: #ffffff;
  --text: #172033;
  --link: #174398;
}
body { background: var(--surface); color: var(--text); }
a { color: var(--link); }

@media (prefers-color-scheme: dark) {
  :root {
    color-scheme: dark;
    --surface: #111827;
    --text: #f1f5f9;
    --link: #93c5fd;
  }
}
```

The custom property syntax is explained in [the component lesson](./20-css-custom-properties.mdx). `color-scheme` also informs browser-rendered controls about supported schemes. Test borders, focus indicators, images, and disabled controls in both themes; changing only the body background often leaves unreadable components.

## Print and motion are environments too

A reading page may benefit from a print stylesheet:

```css
@media print {
  nav, .screen-only { display: none; }
  body { color: black; background: white; }
  article { max-width: none; }
}
```

Check print preview before hiding controls: some links or instructions remain meaningful on paper. For motion, define a still baseline and enable nonessential animation inside `prefers-reduced-motion: no-preference`; the [transitions lesson](../5-production/22-css-transitions-and-motion.mdx) demonstrates that pattern.

## Exercise and solution

Add a visible `.scheme-label` paragraph that stays readable in both themes and use developer tools to emulate the color preference. Then print the page to preview and verify the navigation disappears while article text remains.

If a component ignores the theme, inspect it for hard-coded colors. Replace those with the paired variables instead of adding successively stronger selectors. Finally, move the width query above an equally specific base rule and observe how source order can override its active declaration.

Further reading: [W3C media features](https://www.w3.org/TR/mediaqueries-5/) and [web.dev dark-mode guidance](https://web.dev/articles/prefers-color-scheme).
