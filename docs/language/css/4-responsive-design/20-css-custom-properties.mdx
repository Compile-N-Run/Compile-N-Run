# Custom Properties and Reusable Components

Custom properties store reusable values within the cascade. They are not global text replacements: ordinary unregistered custom properties inherit, can be overridden on a subtree, and are resolved where they are used. That makes them useful for themes and component variations.

Name tokens by their purpose when the purpose matters. `--color-text` describes a role that can change between themes; `--blue-700` describes a palette entry. A small course project usually needs only a few role-based colors, spacing values, and component-specific options.

## Create a component with a local theme

Use a fresh practice document and stylesheet:

```html
<section class="course-list">
  <article class="course-card">
    <h2>CSS foundations</h2><p>Learn how rules apply.</p>
    <a href="#practice">Practice foundations</a>
  </article>
  <article class="course-card course-card--project">
    <h2>Build a dashboard</h2><p>Combine the core ideas.</p>
    <a href="#practice">Practice the project</a>
  </article>
</section>
<p id="practice">Choose an exercise from your lesson notes.</p>
```

```css
:root {
  --color-text: #172033;
  --color-surface: #ffffff;
  --space: 1rem;
  --radius: 0.75rem;
}
body {
  margin: 0;
  padding: var(--space);
  color: var(--color-text);
  background: #f1f5f9;
  font: 1rem/1.6 system-ui, sans-serif;
}
.course-list { display: grid; gap: var(--space); }
.course-card {
  --accent: #234e9b;
  padding: var(--space);
  border: 2px solid var(--accent);
  border-radius: var(--radius);
  background: var(--color-surface);
}
.course-card a { color: var(--accent); }
.course-card--project { --accent: #166534; }
```

The first card's border and link are blue. The project variant's border and link are green. Overriding one custom property changes the component's coordinated details without repeating every declaration.

These variables are scoped by normal inheritance: changing `--accent` on one card does not change its sibling. If you define `--accent` directly on each card, a parent-level `--accent` cannot override that local declaration merely through inheritance. Decide which element should own each default.

## Understand fallback values

`color: var(--optional-accent, #234e9b)` uses the fallback when that custom property is missing or has a guaranteed-invalid value. It does not validate an arbitrary defined value for the destination property. If `--optional-accent: 20px` is defined, substituting it into `color` is invalid; the fallback is not used just because a length is not a color.

When substitution makes a declaration invalid at computed-value time, an earlier ordinary declaration for the same property is not automatically reconsidered. This is a frequent source of confusion when trying to build fallbacks. Keep token types consistent and inspect computed values when a theme suddenly inherits an unexpected color.

Custom properties hold values, not selector names or normal media-query breakpoints. `@media (min-width: var(--breakpoint))` is not the ordinary way to parameterize a media query.

## Keep selectors easy to compose

Use a base component class, a small variation class, and local child classes when needed. Avoid coupling the component to an entire page path such as `.dashboard main section article a`. The [cascade layer lesson](../0-foundations/03-css-cascade-and-specificity.mdx) provides a further organization tool as the stylesheet grows.

## Exercise and solution

Add a warning variant with a dark amber accent, then override padding only for a compact card:

```css
.course-card--warning { --accent: #92400e; }
.course-card--compact { padding: calc(var(--space) / 2); }
```

Verify that applying both classes combines the changes without editing the base rule. Check link contrast on the card surface before treating any new palette value as finished.
