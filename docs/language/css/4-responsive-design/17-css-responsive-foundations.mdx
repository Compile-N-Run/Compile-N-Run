# Responsive Design Foundations

Responsive design means the interface adapts to its available space and its users' needs. A layout should survive a narrow phone, a split browser window, longer translated text, and enlarged fonts. It is more robust to express flexible relationships than to recreate a few fixed screenshots.

Start with a useful single-column page. Add more columns only when the content has enough room. This mobile-first approach also gives browsers a simple base layout before conditional enhancements apply.

## Establish the baseline

Keep this viewport declaration in the HTML head:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

Do not disable user scaling. The declaration lets mobile browsers use the device's CSS viewport width rather than a wider legacy layout viewport.

Use a fresh practice page with a main element containing an `h1`, several paragraphs, and a list of lessons. Apply:

```css
*, *::before, *::after { box-sizing: border-box; }
body {
  margin: 0;
  font: 1rem/1.6 system-ui, sans-serif;
  color: #172033;
}
main {
  width: min(100% - 2rem, 72rem);
  margin-inline: auto;
  padding-block: 2rem;
}
h1 { font-size: clamp(1.8rem, 1.2rem + 2vw, 3rem); line-height: 1.15; }
p { max-width: 65ch; }
img { display: block; max-width: 100%; height: auto; }
```

The page maintains gutters, stops expanding at a readable outer width, and allows text to wrap. This accomplishes much of the responsive work without a media query.

## Let content choose breakpoints

If a sidebar becomes cramped at a certain width, keep it below the main content until both columns have enough space. Resize slowly and find where the content first looks comfortable. Then add a minimum-width query at that point. Do not choose a breakpoint solely because it has a familiar device label.

A layout that looks correct at 375 and 1440 pixels may still fail at 700. Test intermediate sizes, especially just before and after a breakpoint. Content-driven automatic grids can eliminate some breakpoints entirely; see the [Grid lesson](../3-flexbox-and-grid/15-css-grid.mdx).

## Make images flexible without distorting them

The baseline image rule reduces an oversized image while preserving its aspect ratio. Supply intrinsic `width` and `height` attributes in HTML when known, so the browser can reserve space before the image loads. Those attributes do not prevent CSS from making the image smaller.

For a deliberately cropped thumbnail, give a wrapper an aspect ratio and make the image fill it. This example requires your own `lesson.jpg` file:

```html
<div class="thumbnail"><img src="lesson.jpg" alt="A student arranging study notes"></div>
```

```css
.thumbnail { aspect-ratio: 16 / 9; }
.thumbnail img {
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

The image retains its proportions while excess edges are cropped. Cropping is inappropriate when it removes essential information, such as part of a chart. HTML `srcset` and `sizes` can select more suitable image resources; CSS alone does not reduce the bytes of an unnecessarily large original.

## Exercise and checks

Create three cards using the automatic Grid pattern, then test the page at 320, 768, and 1280 CSS pixels and at 200% zoom. Replace one heading with a much longer title. Success means no overlapping text, no inaccessible controls, and no page-level horizontal scroll from ordinary content.

If the page fails, inspect minimum widths and unbreakable strings before adding another query. Continue with [media queries and preferences](./18-css-media-queries.mdx).
