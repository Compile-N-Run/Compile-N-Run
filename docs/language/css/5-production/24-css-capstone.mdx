# CSS Capstone: A Responsive Study Dashboard

This project combines the course into a study dashboard: a wrapping navigation bar, a responsive course collection, native exercise disclosures, and a temporary checklist. It uses only HTML and CSS, so you can open it locally without installing a build tool.

[Open the finished dashboard](/examples/css/index.html). To work offline, save the [HTML file](/examples/css/index.html) as `index.html` and the [stylesheet](/examples/css/styles.css) as `styles.css` in the same folder. When saving the HTML from a browser, use page source or an HTML-only save option so you preserve the source document. The complete files also live in the repository at `static/examples/css/`. Open your local `index.html`; it links to `styles.css` beside it.

The checklist is intentionally temporary. Its native reset button works, but checking an item does not save progress or update a remote service. The disclosures and local navigation are functional browser features. No external images, fonts, libraries, or scripts are required.

## Build the structure first

Read the HTML before changing its styles. The skip link targets the main content, the navigation has a clear label, and the course titles follow a heading hierarchy. The sidebar comes after the main course and practice content in source order. That gives the narrow layout and keyboard navigation a sensible sequence.

Temporarily disable the stylesheet. You should still be able to follow links, open exercises, and operate the checklist. This is your first acceptance test: presentation should enhance an understandable document.

## Understand the layout decisions

The stylesheet declares its layer order once:

```css
@layer reset, base, layout, components, utilities;
```

The reset handles box sizing and control fonts. Base rules define typography and theme tokens. Layout rules arrange regions. Components style cards, links, buttons, and disclosures. Utilities contain the skip link and print adjustments. All normal application rules participate in these layers, avoiding accidental unlayered overrides.

The overall dashboard starts as one column, then gains a sidebar when enough room exists:

```css
.dashboard { display: grid; grid-template-columns: minmax(0, 1fr); gap: 2rem; align-items: start; }
@media (min-width: 62rem) {
  .dashboard { grid-template-columns: minmax(0, 1fr) 19rem; }
}
```

Inside the content area, the course grid chooses how many cards fit using the automatic pattern from [Grid fundamentals](../3-flexbox-and-grid/15-css-grid.mdx). Each card uses a column Flexbox layout so its final action can sit below flexible description space. A named container query changes metadata arrangement based on the card's own width.

The header wraps naturally instead of hiding its navigation. The page uses real disclosure elements for exercises and native checkboxes for the study plan. A still baseline remains usable with reduced motion; dark-mode tokens pair readable text with their surfaces.

## Make a meaningful change

Add a fourth card about accessibility. Give it a heading, a short description, and a local link to a new exercise. Use the existing component classes first; add a modifier only if the design requires a distinct accent.

A reasonable solution adds another `.course-slot` containing an `.course-card` article and adds a matching `details` element inside the practice section. Keep the new card title at `h3`, make its link target unique, and write a concrete check in the exercise. You should not need a new column count or another viewport breakpoint.

## Verify behavior, not one screenshot

- At 320, 768, and 1280 CSS pixels, ordinary content fits inside the page without horizontal scrolling.
- At 200% zoom and with a longer card title, text wraps and controls remain visible.
- Tab reveals the skip link, then follows navigation, course links, disclosures, and checkboxes in a sensible order.
- Enter or Space opens a focused exercise summary; the reset button restores unchecked defaults.
- Dark preference preserves readable text, borders, and focus indicators. Reduced-motion preference removes the optional transitions.
- With CSS disabled, the content hierarchy and native interactions still make sense.

Print preview provides a simpler reading layout. Closed exercise bodies are not promised to print; open the exercises you want to include before printing. For a production print workflow, test the target browsers and decide whether you need a dedicated expanded print view.

If a check fails, use the [debugging sequence](./23-css-debugging-and-maintainability.mdx) to identify the relevant rule before adding an override. For a next project, adapt the same components into a reading list with different content lengths and a different theme. If you later add persistent checklist state, continue with [JavaScript](/docs/language/javascript) while keeping these semantic controls and layout foundations.
