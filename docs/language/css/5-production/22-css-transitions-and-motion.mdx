# Transitions, Animation, and Reduced Motion

A transition interpolates between property values when state changes. An animation uses named keyframes to describe a sequence. Both can help someone notice a change, but neither should be required to understand or operate the interface.

Begin with a usable still design. Enable optional movement only when the user's preference permits it. That avoids making the reduced-motion version a collection of emergency overrides.

## Add a deliberate transition

Put this link and destination in a fresh starter document and use the following stylesheet:

```html
<a class="lesson-link" href="#practice">Start the layout exercise</a>
<section id="practice">
  <h1>Layout exercise</h1>
  <p>Create a three-card grid that becomes one column on narrow screens.</p>
</section>
```

```css
body { padding: 1rem; font: 1rem/1.6 system-ui, sans-serif; }
.lesson-link {
  display: inline-block;
  padding: 0.75em 1em;
  border: 2px solid #234e9b;
  border-radius: 0.5rem;
  background: #234e9b;
  color: white;
  text-underline-offset: 0.2em;
}
.lesson-link:hover { background-color: #17376d; }
.lesson-link:focus-visible {
  outline: 3px solid #9f1239;
  outline-offset: 3px;
}
@media (prefers-reduced-motion: no-preference) {
  .lesson-link {
    transition: background-color 160ms ease, transform 160ms ease;
  }
  .lesson-link:hover { transform: translateY(-2px); }
}
```

Without motion enhancement, the link still changes background immediately and retains a visible focus indicator. When motion is allowed, its background and small positional change animate over 160 milliseconds. Put the transition on the base rule so it applies both when entering and leaving hover.

The shorthand specifies property, duration, timing function, and optionally delay. List intended properties instead of `transition: all`: a later change to width or spacing should not silently become animated. Keep focus feedback immediate and clear.

## Know what moves and what lays out

A transform changes the visual rendering without moving surrounding flow boxes. Translating a card does not make its neighbors reserve new space, so large movement can overlap content. Animating width, height, or positional layout properties can require repeated layout work. Transform and opacity are often better candidates for smooth effects, but compositing is a browser decision, not a guarantee of zero cost.

Do not add `will-change` everywhere. It can consume resources, and performance claims should be measured using developer tools rather than inferred from the property's name.

## Use keyframes sparingly

For an optional, one-time status reveal, add a paragraph with class `status` and this CSS:

```css
@keyframes reveal-status {
  from { opacity: 0; transform: translateY(0.25rem); }
  to { opacity: 1; transform: translateY(0); }
}
@media (prefers-reduced-motion: no-preference) {
  .status { animation: reveal-status 180ms ease-out; }
}
```

The paragraph is visible in its ordinary styles. The animation runs once when applied, and no animation is required to reveal its content. Avoid indefinite decorative motion, flashing, or removing an essential update when reduced motion is requested. A real dynamic status also needs appropriate HTML and announcement behavior; CSS opacity alone does not provide that.

## Exercise and checks

Emulate `prefers-reduced-motion: reduce` in developer tools or change the operating-system preference. The link should stop translating and the status should appear immediately. Keyboard focus must remain visible in both modes.

Then change the transform distance to `1rem` temporarily. Observe that nearby content does not move away to accommodate it, and restore the subtle value. This verifies the difference between visual movement and layout.

Further reading: [W3C transition behavior](https://www.w3.org/TR/css-transitions-1/) and [web.dev reduced-motion guidance](https://web.dev/articles/prefers-reduced-motion).
