# Grid Page Layouts and Named Areas

Named grid areas make a page's intended structure visible in CSS. They are useful when several elements occupy stable roles, such as an introduction, main content, and supporting notes. Start with a good single-column reading order before arranging those areas on a larger screen.

## Build the document in reading order

Use the starter document with this content and a fresh stylesheet:

```html
<div class="dashboard">
  <header class="intro"><h1>Your learning dashboard</h1></header>
  <main class="lessons">
    <h2>Current lessons</h2>
    <p>Continue with Grid, then practice responsive layouts.</p>
  </main>
  <aside class="notes" aria-labelledby="notes-title">
    <h2 id="notes-title">Study reminders</h2>
    <p>Finish one exercise before starting the next lesson.</p>
  </aside>
  <footer class="footer">Progress comes from practice.</footer>
</div>
```

```css
* { box-sizing: border-box; }
body { margin: 0; padding: 1rem; font: 1rem/1.6 system-ui; }
.dashboard {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  grid-template-areas:
    "intro"
    "lessons"
    "notes"
    "footer";
  gap: 1rem;
  max-width: 72rem;
  margin-inline: auto;
}
.intro { grid-area: intro; }
.lessons { grid-area: lessons; }
.notes { grid-area: notes; background: #eff6ff; }
.footer { grid-area: footer; }
.dashboard > * { min-inline-size: 0; padding: 1rem; }

@media (min-width: 50rem) {
  .dashboard {
    grid-template-columns: minmax(0, 2fr) minmax(14rem, 1fr);
    grid-template-areas:
      "intro intro"
      "lessons notes"
      "footer footer";
    align-items: start;
  }
}
```

Below the breakpoint, the document forms one column. Above it, the lessons and notes share a row while the introduction and footer span both columns. `align-items: start` prevents the shorter area from stretching its background to the full row height.

The breakpoint is a design choice for this content, not a claim that every tablet or laptop has that width. The next section covers [choosing breakpoints](../4-responsive-design/17-css-responsive-foundations.mdx) from actual layout pressure.

## Keep area maps valid

Each quoted row must contain the same number of cells. Repeated cells with the same name must form a rectangle. Use `.` for an intentionally empty cell. A typo or nonrectangular area can invalidate the template declaration, so inspect the resulting grid if every item suddenly falls into unexpected tracks.

Named areas place elements visually; they do not rewrite reading order. This example keeps intro, lessons, notes, and footer in a sensible order in both layouts. Avoid moving an action visually before the content that explains it while leaving keyboard users to encounter it later.

## Nest layouts at the right level

Inside `.lessons`, a second grid can arrange lesson cards. Inside a card, Flexbox can align metadata or push an action below its description. An ordinary nested grid has independent tracks. `subgrid` can share an ancestor's tracks when alignment across nested content is an actual requirement, but it is unnecessary for a simple collection of independent cards.

## Exercise and solution

Add a full-width announcement between the introduction and lessons. Add a new element in that same source position with class `announcement`, set `grid-area: announcement`, and insert an `"announcement"` row in the small template and `"announcement announcement"` in the wide template.

Check that every row has the right cell count and the announcement remains before the lessons when CSS is disabled. This confirms both the grid map and the underlying document structure.

Further reading: [W3C named grid areas](https://www.w3.org/TR/css-grid-2/#grid-template-areas-property).
