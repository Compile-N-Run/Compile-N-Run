# Practical Flexbox Patterns

A useful layout pattern encodes a relationship, such as “the search field receives leftover space” or “the action stays below the description.” Flexbox expresses these relationships with a small number of rules instead of device-specific offsets.

## A header that can wrap

Start with the standard practice document, replacing its body content and stylesheet:

```html
<header class="site-header">
  <a class="brand" href="#home">Study notebook</a>
  <nav aria-label="Main navigation">
    <ul class="nav-list">
      <li><a href="#topics">Topics</a></li>
      <li><a href="#plan">Study plan</a></li>
      <li><a href="#notes">Notes</a></li>
    </ul>
  </nav>
</header>
<main id="home">
  <section id="topics"><h1>Topics</h1></section>
  <section id="plan"><h2>Study plan</h2></section>
  <section id="notes"><h2>Notes</h2></section>
</main>
```

```css
body { margin: 0; font: 1rem/1.5 system-ui, sans-serif; }
.site-header {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 1rem 2rem;
  padding: 1rem;
  background: #eff6ff;
}
.brand { font-weight: 700; margin-inline-end: auto; }
.nav-list {
  display: flex;
  flex-wrap: wrap;
  gap: 0.5rem 1rem;
  margin: 0;
  padding: 0;
  list-style: none;
}
a { color: #174398; }
main { padding: 1rem; }
```

The brand's automatic end margin consumes available main-axis space, pushing navigation toward the other edge. The header and navigation can both wrap. At a narrow width, the links remain available without a JavaScript menu.

## Let a form field grow

For a labeled search form, give the input flexible space and the button a content-sized basis:

```css
.search-row { display: flex; flex-wrap: wrap; gap: 0.5rem; }
.search-row input { flex: 1 1 12rem; min-inline-size: 0; }
.search-row button { flex: 0 0 auto; }
```

This fragment assumes a real HTML label connected to the input. The styles arrange controls; they do not implement search or supply an accessible name. Keep labels visible when possible, and use meaningful form behavior before presenting a search action as functional.

## Put a card action after flexible content

Inside a card, a column layout can align actions across equally tall cards:

```css
.course-card { display: flex; flex-direction: column; }
.course-card__action { margin-block-start: auto; }
```

The parent row or grid must actually give the cards extra height, and the action needs room above it. Use a wrapper or a `gap` so automatic margin does not replace the minimum desired separation. This pattern lets longer descriptions push the action naturally while shorter cards use the remaining space above it.

## Keep the reading order honest

`order`, `row-reverse`, and `column-reverse` can change visual order without changing DOM order. Keyboard navigation and assistive technology may still follow the original structure. Do not use these properties to repair a document whose source order is wrong. Write a sensible reading sequence first, then use layout to express it.

## Exercise and solution

Add one more navigation link with a long label and resize to 320 CSS pixels. All links must remain visible and keyboard reachable without horizontal page scrolling. If the brand becomes too long, allow emergency wrapping:

```css
.brand { overflow-wrap: anywhere; }
.site-header > nav { min-inline-size: 0; }
```

Tab through the links and confirm the focus order matches their visual order. Then compare this content-driven header with a [Grid page layout](./16-css-grid-patterns.mdx), where shared rows and columns matter more.
