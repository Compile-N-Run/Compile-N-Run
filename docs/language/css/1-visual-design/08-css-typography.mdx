# Readable CSS Typography

Typography is a layout decision. Font metrics change line breaks, the height of cards, and how much information fits on screen. Start with readable body text, then establish headings and supporting text around it.

## Establish a reading rhythm

Use this article in the starter document and place the CSS in your stylesheet:

```html
<article class="article">
  <h1>Understanding a layout before changing it</h1>
  <p class="lede">Good debugging begins with a small observation.</p>
  <h2>Ask what determines the size</h2>
  <p>A box may be sized by its content, its parent, a fixed value,
     or a layout algorithm. Identify that relationship first.</p>
  <p>Then change one declaration and compare the result.</p>
</article>
```

```css
body {
  margin: 0;
  padding: 1rem;
  font-family: system-ui, -apple-system, "Segoe UI", sans-serif;
  font-size: 1rem;
  line-height: 1.6;
  color: #172033;
}
.article { max-width: 65ch; margin-inline: auto; }
h1, h2 { line-height: 1.2; }
h1 { font-size: 2.25rem; margin-block: 0 1rem; }
h2 { font-size: 1.5rem; margin-block: 2rem 0.75rem; }
p { margin-block: 0 1rem; }
.lede { font-size: 1.2rem; }
```

The article remains a comfortable width on large displays and shrinks within narrow viewports. The unitless `line-height: 1.6` is inherited as a multiplier, allowing descendants with different font sizes to calculate their own line height. A fixed pixel line height inherited by larger text can be too tight.

Font stacks are ordered fallback choices. If a named font is unavailable, the browser tries the next one. A generic family such as `sans-serif` or `serif` provides a final fallback. The exact system font differs across operating systems, so test wrapping rather than relying on one machine's line breaks.

## Preserve meaning and flexibility

Use the heading level that fits the document, then style its appearance. A visually small heading can still be an `h2`; a large paragraph is still a paragraph. Keep important text in HTML, not in pseudo-elements.

Avoid fixed heights on text containers. Users can enlarge text, translate the page, or use a wider font. For long URLs or user-generated strings, `overflow-wrap: anywhere` allows emergency breaks. Apply it where needed rather than using `word-break: break-all` globally, which can split ordinary words unnecessarily.

Do not use ellipsis to hide essential instructions. If a compact interface truncates supplementary text, provide an accessible way to read the full content. A `title` attribute alone is not a reliable solution for every input method.

## Optional local web font

If you have a licensed font file, you can declare it:

```css
@font-face {
  font-family: "Notebook Sans";
  src: url("fonts/notebook-sans.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}
```

This is a template: it requires a real file at that path. `swap` allows fallback text while loading, but a font with different metrics can cause layout movement. Load only the weights you use and keep a reasonable fallback stack.

## Exercise and checks

Add a long unbroken identifier to a paragraph with class `reference`, then apply:

```css
.reference { overflow-wrap: anywhere; }
```

Check at a narrow width and 200% zoom. The article should wrap without horizontal scrolling or overlapping headings. Increase the browser's default font size and confirm spacing still works. If only one component breaks, inspect its fixed widths and heights before shrinking all text.
