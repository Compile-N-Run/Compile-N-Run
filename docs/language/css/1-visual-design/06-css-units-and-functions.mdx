# CSS Units and Sizing Functions

A number is useful only when you know what it is relative to. CSS offers fixed reference units, font-relative units, percentages, and viewport-relative units. Choosing the right relationship matters more than memorizing a long unit list.

## Match the unit to the intent

| Unit | Reference | A useful starting point |
| --- | --- | --- |
| `px` | CSS reference pixel, not necessarily one physical screen pixel | Thin borders |
| `rem` | Root element's font size | Text and consistent spacing |
| `em` | Element's font size; for `font-size`, the inherited font size | Padding that scales with a component's text |
| `%` | A reference determined by the property | Width relative to a containing block |
| `vw` | One percent of viewport width | A fluid value combined with bounds |
| `dvh` | One percent of dynamic viewport height | A screen-filling minimum height that follows browser UI changes |

Do not assume every percentage is based on the parent height or width in the same way. Percentage heights often need a definite containing-block height. Percentage padding in common horizontal layouts is based on the containing block's inline size, even for top and bottom padding.

Keep the root font size at the user's normal default unless you have a reason to change it. `1rem` is commonly `16px` initially, but it is not a permanent conversion rule.

## Build a fluid reading panel

Use the starter HTML with a heading and two paragraphs inside `.panel`; put the following in the separate stylesheet:

```html
<main class="panel">
  <h1>Learning at your own pace</h1>
  <p>Resize this page and watch the gutters and heading.</p>
  <p>The content should remain readable at every width.</p>
</main>
```

```css
* { box-sizing: border-box; }
body { margin: 0; font-family: system-ui, sans-serif; }
.panel {
  width: min(100% - 2rem, 65ch);
  margin-inline: auto;
  padding-block: clamp(1rem, 4vw, 3rem);
}
h1 {
  font-size: clamp(1.75rem, 1.2rem + 2vw, 3rem);
  line-height: 1.15;
}
p { font-size: 1rem; line-height: 1.6; }
```

The panel is the smaller of the available width minus two gutters and `65ch`. A `ch` is based on the font's zero glyph advance; it approximates text measure, not an exact character count. The heading grows with the viewport between lower and upper limits. A `rem` component in the preferred size helps preserve text scaling, but you should still test zoom and larger default fonts.

`min()` chooses the smallest expression; `max()` chooses the largest; `clamp()` bounds a preferred value. `calc()` performs compatible arithmetic, for example `width: calc(100% - 2rem)`. Include whitespace around addition and subtraction. Avoid inventing mixed-unit sums outside these functions.

## Common traps

Using only `vw` for font size can make text tiny on narrow screens and reduce the effectiveness of zoom. Fixed heights can clip wrapped or enlarged text. Nested `em` font sizes compound: a child at `1.2em` inside another `1.2em` region becomes larger again. Use `rem` when that compounding is unwanted.

A viewport-sized `100vw` element can also be wider than the available content area, depending on scrollbar behavior. A normal page container usually needs `width: 100%`, not a forced viewport width.

## Exercise and checks

Add a callout whose padding grows with its own font size:

```css
.callout {
  font-size: 1.25rem;
  padding: 1em;
  border: 1px solid currentColor;
}
```

At a `16px` root size, both the text size and padding are `20px`. Change the component's font to `1.5rem`: both become `24px`. Then replace the padding with `1rem` and confirm it stays tied to the root instead. Continue with [typography](./08-css-typography.mdx) for readability choices.
