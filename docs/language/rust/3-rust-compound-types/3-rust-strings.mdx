# Rust Strings

## Introduction

Strings are one of the first things that surprise people coming to Rust from other languages. Rust has **two** main string types, it refuses to let you write `s[0]`, and `len()` sometimes gives an answer that looks wrong. None of this is accidental. Rust stores all text as UTF-8 and makes you deal with that fact up front, so you avoid subtle bugs with non-English text later.

In this guide you will learn the difference between `String` and `&str`, how to create and grow strings, why integer indexing is not allowed, how to slice and iterate safely, and which type to use in function signatures.

## `String` vs `&str`

Rust's core language has one string type: the string slice `str`, which you almost always see behind a reference as `&str`. The standard library adds the `String` type.

| Feature | `String` | `&str` |
|---------|----------|--------|
| Ownership | Owns its data | Borrows data owned by someone else |
| Storage | Heap-allocated buffer | Points into a `String`, the binary, or anywhere else |
| Mutability | Can grow and shrink (if declared `mut`) | Read-only view |
| Size known at compile time | No, it can change | No, but the reference stores the length |
| Typical source | `String::from`, `to_string`, `format!` | String literals, slices of a `String` |

Under the hood, a `String` is a wrapper around a `Vec<u8>` that is guaranteed to hold valid UTF-8. A `&str` is a "fat pointer": a pointer to some bytes plus a length.

A good mental model: `String` is to `&str` what `Vec<T>` is to `&[T]`.

## Creating Strings

String literals are `&str` values baked into your compiled program. To get an owned, growable `String`, use one of several equivalent approaches:

```rust
fn main() {
    // A string literal has type &'static str
    let literal: &str = "Hello";

    // Three common ways to create an owned String
    let a = String::from("Hello");
    let b = "Hello".to_string();
    let c = "Hello".to_owned();

    // An empty String, ready to be filled later
    let mut empty = String::new();
    empty.push_str("now filled");

    // Pre-allocate space when you know roughly how big it will get
    let buffer = String::with_capacity(64);

    println!("{literal} {a} {b} {c}");
    println!("{empty}");
    println!("len = {}, capacity >= 64: {}", buffer.len(), buffer.capacity() >= 64);
}
```

**Output:**

```text
Hello Hello Hello Hello
now filled
len = 0, capacity >= 64: true
```

`String::from`, `to_string` and `to_owned` all produce the same result. Pick whichever reads best to you; `String::from` is the most common in tutorials.

## UTF-8 and Why You Can't Index by Integer

Every Rust string is UTF-8 encoded. In UTF-8, a single character can take between 1 and 4 bytes:

```rust
fn main() {
    let english = "hello";
    let russian = "Здравствуйте";
    let emoji = "🦀";

    println!("{english}: {} bytes, {} chars", english.len(), english.chars().count());
    println!("{russian}: {} bytes, {} chars", russian.len(), russian.chars().count());
    println!("{emoji}: {} bytes, {} chars", emoji.len(), emoji.chars().count());
}
```

**Output:**

```text
hello: 5 bytes, 5 chars
Здравствуйте: 24 bytes, 12 chars
🦀: 4 bytes, 1 chars
```

Notice that `len()` returns the number of **bytes**, not characters. Because of this, Rust does not let you write `s[0]`:

```rust
fn main() {
    let s = String::from("hello");
    let h = s[0]; // does not compile
}
```

```text
error[E0277]: the type `str` cannot be indexed by `{integer}`
 --> src/main.rs:3:15
  |
3 |     let h = s[0]; // does not compile
  |               ^ string indices are ranges of `usize`
```

There are three good reasons for this rule:

1. **A byte is not a character.** In `"Здравствуйте"`, byte 0 is `208`, which is only half of the letter `З`. Returning it would almost never be what you wanted.
2. **It is ambiguous.** Should `s[0]` give a byte, a `char`, or a user-perceived letter (a grapheme cluster)? These can all be different.
3. **It would be slow.** Indexing is expected to be O(1), but finding the nth character in UTF-8 means walking the string from the start.

Instead, Rust asks you to say what you mean: bytes, characters, or a range of bytes.

## Slicing on Character Boundaries

You can take a slice of a string with a byte range, just like with arrays. The range must start and end on character boundaries:

```rust
fn main() {
    let hello = "Здравствуйте";

    // Each Cyrillic letter is 2 bytes, so 0..4 covers the first two letters
    let first_two = &hello[0..4];
    println!("{first_two}");

    // Check a boundary before slicing
    println!("Is 1 a boundary? {}", hello.is_char_boundary(1));
    println!("Is 2 a boundary? {}", hello.is_char_boundary(2));

    // get() returns None instead of panicking
    println!("{:?}", hello.get(0..1));
    println!("{:?}", hello.get(0..2));
}
```

**Output:**

```text
Зд
Is 1 a boundary? false
Is 2 a boundary? true
None
Some("З")
```

If you slice with `&hello[0..1]` directly, the program compiles but **panics at runtime** with a message like:

```text
thread 'main' panicked at src/main.rs:3:19:
end byte index 1 is not a char boundary; it is inside 'З' (bytes 0..2 of string)
```

When the range comes from user input or calculations, prefer `get()` so you can handle the `None` case.

## Iterating with `chars()` and `bytes()`

To work with individual characters, iterate instead of indexing:

```rust
fn main() {
    let word = "Зд🦀";

    for c in word.chars() {
        print!("{c} ");
    }
    println!();

    for b in word.bytes() {
        print!("{b} ");
    }
    println!();

    // char_indices gives the byte position of each char
    for (i, c) in word.char_indices() {
        println!("byte {i}: {c}");
    }

    // The nth character (walks the string, so it is O(n))
    println!("third char: {:?}", word.chars().nth(2));
}
```

**Output:**

```text
З д 🦀 
208 151 208 180 240 159 166 128 
byte 0: З
byte 2: д
byte 4: 🦀
third char: Some('🦀')
```

`chars()` yields Unicode scalar values (`char`). Some written letters, such as many in Hindi or emoji with skin-tone modifiers, are made of several `char`s. If you need true user-perceived letters, use a crate like `unicode-segmentation`; the standard library does not provide that.

## Growing a String: `push`, `push_str`, `+` and `format!`

A `String` declared with `mut` can grow:

```rust
fn main() {
    let mut s = String::from("foo");
    s.push_str("bar"); // append a &str
    s.push('!');       // append a single char
    println!("{s}");

    // + takes ownership of the left side and borrows the right side
    let s1 = String::from("Hello, ");
    let s2 = String::from("world");
    let s3 = s1 + &s2;
    // println!("{s1}"); // error: s1 was moved into s3
    println!("{s3} (s2 is still usable: {s2})");

    // format! borrows everything and returns a new String
    let a = String::from("tic");
    let b = String::from("tac");
    let c = String::from("toe");
    let game = format!("{a}-{b}-{c}");
    println!("{game} ({a} {b} {c} still usable)");
}
```

**Output:**

```text
foobar!
Hello, world (s2 is still usable: world)
tic-tac-toe (tic tac toe still usable)
```

The `+` operator calls a method with roughly this signature: `fn add(self, s: &str) -> String`. That explains both quirks:

- `self` (not `&self`) means the left `String` is **moved**. Its buffer is reused, so this is efficient.
- The right side must be a `&str`. Writing `&s2` gives a `&String`, which Rust automatically converts to `&str` through **deref coercion**.

For anything beyond joining two strings, `format!` is usually clearer. The next page, [Rust String Manipulation](./4-rust-string-manipulation.mdx), covers replacing, trimming, splitting and more editing techniques in depth.

## Ownership and Borrowing with Strings

`String` owns heap memory, so normal ownership rules apply. Assigning or passing a `String` **moves** it. A `&str` is just a borrow and can be copied freely.

```rust
fn takes_ownership(s: String) {
    println!("I own: {s}");
} // s is dropped here

fn borrows(s: &str) {
    println!("I borrowed: {s}");
}

fn main() {
    let owned = String::from("data");

    borrows(&owned);          // lend it out
    borrows(&owned);          // still ours, can lend again

    let copy = owned.clone(); // explicit deep copy
    takes_ownership(owned);   // ownership moves into the function
    // println!("{owned}");   // error: borrow of moved value

    println!("The clone survives: {copy}");
}
```

**Output:**

```text
I borrowed: data
I borrowed: data
I own: data
The clone survives: data
```

A slice also borrows from its `String`, so the borrow checker stops you from modifying the `String` while a slice is still in use:

```rust
fn main() {
    let mut s = String::from("hello world");
    let first = &s[0..5];
    // s.clear(); // error: cannot borrow `s` as mutable because it is also borrowed as immutable
    println!("{first}");
    s.clear(); // fine now: `first` is no longer used
    println!("cleared, len = {}", s.len());
}
```

**Output:**

```text
hello
cleared, len = 0
```

## Converting Between String Types

| From | To | How |
|------|----|-----|
| `&str` | `String` | `String::from(s)`, `s.to_string()`, `s.to_owned()`, `s.into()` |
| `String` | `&str` | `&s`, `s.as_str()`, `&s[..]` |
| number | `String` | `n.to_string()`, `format!("{n}")` |
| `&str` | number | `s.parse::<i32>()` (returns a `Result`) |
| `String` | `Vec<u8>` | `s.into_bytes()` |
| `Vec<u8>` | `String` | `String::from_utf8(bytes)` (returns a `Result`) |
| `char` | `String` | `c.to_string()` |

```rust
fn main() {
    let owned: String = "rust".into();
    let borrowed: &str = owned.as_str();

    let n = 42;
    let n_text = n.to_string();
    let parsed: i32 = "123".parse().unwrap();
    let bad = "12a".parse::<i32>();

    let bytes = String::from("hi").into_bytes();
    let back = String::from_utf8(bytes.clone()).unwrap();
    let invalid = String::from_utf8(vec![0xff, 0xfe]);

    println!("{owned} {borrowed} {n_text} {}", parsed + 1);
    println!("bad parse is_err: {}", bad.is_err());
    println!("{bytes:?} -> {back}");
    println!("invalid UTF-8 is_err: {}", invalid.is_err());
}
```

**Output:**

```text
rust rust 42 124
bad parse is_err: true
[104, 105] -> hi
invalid UTF-8 is_err: true
```

## Common Methods

Most read-only methods are defined on `str`, so they work on both `String` and `&str`:

```rust
fn main() {
    let text = String::from("  Hello, Rust World  ");
    let t = text.trim();

    println!("trimmed: '{t}'");
    println!("is_empty: {}", t.is_empty());
    println!("contains \"Rust\": {}", t.contains("Rust"));
    println!("starts_with \"Hello\": {}", t.starts_with("Hello"));
    println!("find 'R': {:?}", t.find('R'));
    println!("upper: {}", t.to_uppercase());
    println!("replace: {}", t.replace("World", "Fans"));

    let words: Vec<&str> = t.split(", ").collect();
    println!("split: {words:?}");

    let mut s = String::from("abc");
    s.insert(0, '>');
    let last = s.pop();
    s.truncate(2);
    println!("after edits: {s}, popped {last:?}");
}
```

**Output:**

```text
trimmed: 'Hello, Rust World'
is_empty: false
contains "Rust": true
starts_with "Hello": true
find 'R': Some(7)
upper: HELLO, RUST WORLD
replace: Hello, Rust Fans
split: ["Hello", "Rust World"]
after edits: >a, popped Some('c')
```

Note that `find` returns a **byte** position wrapped in `Option`, which you can safely use for slicing because it always lands on a character boundary.

## `&str` or `String` in Function Signatures?

A simple rule of thumb:

- **Take `&str`** when the function only needs to read the text. It accepts string literals, `&String` (via deref coercion) and slices, so it is the most flexible choice.
- **Take `String`** when the function needs to keep the text, for example storing it in a struct. This lets the caller decide whether to move or clone.
- **Return `String`** when you create new text inside the function. You cannot return a `&str` that points to a local `String`, because the local would be dropped.

```rust
struct User {
    name: String, // the struct owns its data
}

// Read-only: take &str
fn shout(s: &str) -> String {
    format!("{}!", s.to_uppercase())
}

// Stores the value: take String
fn new_user(name: String) -> User {
    User { name }
}

fn main() {
    let owned = String::from("alice");

    println!("{}", shout("hi"));    // literal works
    println!("{}", shout(&owned));  // &String works too

    let user = new_user(owned);      // move, no copy needed
    println!("user: {}", user.name);
}
```

**Output:**

```text
HI!
ALICE!
user: alice
```

## Real-World Scenario: Parsing a Config Line

Imagine you are reading a simple settings file where each line looks like `key = value`. This example combines slicing, `find`, trimming, ownership and conversions:

```rust
#[derive(Debug)]
struct Setting {
    key: String,
    value: String,
}

fn parse_line(line: &str) -> Option<Setting> {
    let line = line.trim();
    if line.is_empty() || line.starts_with('#') {
        return None; // skip blank lines and comments
    }
    let eq = line.find('=')?; // byte index of '=', or return None
    let key = line[..eq].trim();
    let value = line[eq + 1..].trim();
    if key.is_empty() {
        return None;
    }
    Some(Setting {
        key: key.to_lowercase(),
        value: value.to_string(),
    })
}

fn main() {
    let config = "\
# server settings
Host = example.com
port = 8080
greeting = Привет, мир
broken line
";

    let mut settings = Vec::new();
    for line in config.lines() {
        match parse_line(line) {
            Some(s) => settings.push(s),
            None => println!("skipped: {line:?}"),
        }
    }

    for s in &settings {
        println!("{} => {} ({} chars)", s.key, s.value, s.value.chars().count());
    }

    let port: u16 = settings
        .iter()
        .find(|s| s.key == "port")
        .and_then(|s| s.value.parse().ok())
        .unwrap_or(80);
    println!("port as number: {port}");
}
```

**Output:**

```text
skipped: "# server settings"
skipped: "broken line"
host => example.com (11 chars)
port => 8080 (4 chars)
greeting => Привет, мир (11 chars)
port as number: 8080
```

Things to notice:

- `parse_line` takes `&str` because it only reads its input, but `Setting` stores `String`s because it must outlive the original text.
- Slicing with the result of `find` is safe even with Cyrillic text, because `find` always returns a character boundary.
- `chars().count()` reports the human-friendly length, while `len()` would report bytes.

## Summary

- Rust has two main string types: the owned, growable `String` and the borrowed string slice `&str`.
- All Rust strings are valid UTF-8, so a character can be 1 to 4 bytes and `len()` counts bytes.
- You cannot index a string with an integer. Use `chars()`, `bytes()`, `char_indices()`, or byte-range slices instead.
- Slices must fall on character boundaries; use `get()` or `is_char_boundary()` when unsure.
- Grow strings with `push`, `push_str`, `+` (moves the left side) or `format!` (borrows everything).
- Prefer `&str` parameters for reading, `String` parameters for storing, and return `String` for newly created text.
