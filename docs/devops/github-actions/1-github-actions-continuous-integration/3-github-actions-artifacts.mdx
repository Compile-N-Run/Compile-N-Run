# GitHub Actions Artifacts and Test Reports

An artifact is a result retained from a workflow run, such as a test report or build bundle. A cache speeds up future work; an artifact records output from a particular run. Their purposes and trust implications differ.

**Prerequisites:** [Node CI](./0-github-actions-node-ci.mdx). The following steps assume a Node test suite and a Linux runner. They belong after checkout and runtime setup.

```yaml
- name: Create report directory
  run: mkdir -p reports
- name: Run tests with TAP output
  run: node --test --test-reporter=tap > reports/tests.tap
- name: Upload test report
  if: ${{ !cancelled() }}
  uses: actions/upload-artifact@v7
  with:
    name: node-test-report
    path: reports/tests.tap
    if-no-files-found: error
    retention-days: 7
```

The test command's exit status remains meaningful even though stdout is redirected. If tests fail, the step fails. The upload condition allows report upload after a failure while avoiding a canceled run. It does not turn a failed test step into a successful one.

## Choose failure behavior deliberately

`if-no-files-found: error` is appropriate when the report is required evidence. If setup fails before report creation, the upload may fail too; the earlier log still explains the original issue. You can use a more specific condition tied to whether the test step ran when that distinction matters.

Uploading only a known report path is safer and easier to review than uploading the entire workspace. The workspace can contain credentials, temporary configuration, or irrelevant dependencies. Review report contents as well: an application test could accidentally print sensitive values into its logs.

The official upload-artifact repository advertised version 7 at verification time. Check current runner and platform support when adopting it, especially on GitHub Enterprise Server, whose supported artifact-action versions may differ from GitHub.com.

## Give parallel jobs unique names

If a matrix runs several versions, name artifacts with those dimensions, for example `tests-${{ matrix.os }}-${{ matrix.node }}`. Do not make independent jobs upload into one shared artifact name and expect them to merge automatically.

Retention controls how long evidence remains available within the repository's allowed limits. It does not replace a release retention policy or guarantee that a download link is permanent. Keep artifact sizes and retention proportional to their usefulness.

## Trust results according to their source

An artifact created by untrusted pull-request code is still untrusted data. A later privileged workflow must not blindly execute a downloaded script or deploy a bundle just because it came through Actions. Validate provenance and establish a reviewed-source relationship before granting it authority.

## Practice and check

Locally run the report command and inspect the TAP file. Introduce a failing assertion and confirm the command returns failure while a report still exists. The correct workflow would retain that diagnostic output without masking the failed check. Local file creation validates the command, not the hosted upload service.
