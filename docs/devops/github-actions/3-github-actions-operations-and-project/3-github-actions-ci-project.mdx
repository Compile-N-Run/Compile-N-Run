# GitHub Actions Project: Minimal Tested CI

This project contains a tiny numeric-summary module, behavioral tests, and a CI workflow. It demonstrates reproducible installation, runtime selection, failing test status, and report artifacts without deployment credentials or third-party npm dependencies.

**Prerequisites:** The [CI](../1-github-actions-continuous-integration/index.mdx) and [security](../2-github-actions-reuse-and-security/index.mdx) sections. Use Node 22 locally; the workflow proposes testing Node 22 and 24 on Ubuntu.

## Copy the complete example

The repository source is `static/examples/github-actions/`. Keep this layout in a separate practice directory:

```text
ci-practice/
  package.json
  package-lock.json
  src/total.js
  test/total.test.js
  ci.yml
```

Save the linked files if you do not have a checkout: [package.json](/examples/github-actions/package.json), [package-lock.json](/examples/github-actions/package-lock.json), [module](/examples/github-actions/src/total.js), [tests](/examples/github-actions/test/total.test.js), and [workflow](/examples/github-actions/ci.yml).

First validate the application locally:

```bash
npm ci --ignore-scripts
npm test
```

Expect three passing tests covering a normal total, invalid values, and an overflowing result. No npm package downloads are required by this dependency-free manifest. The local test run does not execute GitHub's hosted workflow.

## Inspect the workflow before activating it

The supplied `ci.yml` is intentionally outside `.github/workflows` in this website's repository. In your own practice repository, move it to `.github/workflows/ci.yml` only when you intend to enable Actions, then commit the complete project and workflow together.

It runs on pull requests, pushes to main, and manual dispatch. It grants read-only contents access, disables persistent checkout credentials, selects Node explicitly, installs from the lockfile, and runs Node's tests with TAP output. Each matrix job uploads a separately named report with short retention.

Actions are pinned to full commit SHAs resolved from the official version-7 tags during course preparation. Comments identify the corresponding major for review. Pins make the referenced code immutable; they do not remove the need to review upstream updates and refresh dependencies when appropriate.

## Confirm the failure contract

Change the expected total in one test from 6 to 7. Locally, `npm test` should fail. Restore it and confirm success. If you choose to activate the workflow, the hosted check should show the same failure while retaining its test report, then pass after the repair.

Check that the report name contains the matrix runtime, the workflow has no deployment secret, and its artifact path contains only the report. Do not add `continue-on-error` to the required test step.

## State what was actually validated

The provided application tests and report-generation command can be verified locally. Live event delivery, hosted action execution, repository policy, and artifact upload require an actual run in your repository. A YAML file and local test transcript alone cannot establish those results.

Your finished exercise is complete when both the source-level checks and, if enabled, the hosted run show the expected success and deliberate-failure behavior. Deployment remains a separate project with its own target and authorization.
