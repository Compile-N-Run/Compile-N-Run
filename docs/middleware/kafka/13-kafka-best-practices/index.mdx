# Best Practices

This section collects the design habits that separate a Kafka system that keeps working at scale from one that has to be rebuilt: how to name and shape topics, choose keys, treat schemas as contracts, plan for failure, test against a real broker, observe what is happening and avoid the well-known traps. It is for developers and architects who already know the producer and consumer APIs and are preparing to put Kafka in front of real traffic.
