# Architecture Patterns

This section shows how Kafka is used to build real systems: publishing events reliably from a database, rebuilding state from a log, handling poison messages, deduplicating, asking for an answer, coordinating multi-step workflows and surviving the loss of a whole region. Each pattern is told through a concrete system, the failure it prevents and the simpler alternative it was chosen over, so it is for developers and architects deciding how services should talk to each other.
