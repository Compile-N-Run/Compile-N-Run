# Leakage, Groups, Time, and Imbalanced Classes

A pipeline prevents many preprocessing mistakes, but evaluation can still fail before the first estimator is fitted. Duplicate entities across partitions, future-derived features, and repeated test-driven decisions can all produce optimistic results. Define what a future prediction means before choosing the split.

Class imbalance creates another trap: a model that always predicts the majority label may have high accuracy while finding no positive examples. Use a baseline and metrics that reveal the minority-class behavior.

## Compare a rare-class baseline

Run this synthetic experiment:

```python
from sklearn.datasets import make_classification
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import StratifiedKFold, cross_validate

X, y = make_classification(
    n_samples=1000, n_features=8, n_informative=4,
    weights=[0.95, 0.05], flip_y=0, random_state=42
)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
models = {
    "majority": DummyClassifier(strategy="most_frequent"),
    "weighted logistic": make_pipeline(
        StandardScaler(), LogisticRegression(class_weight="balanced", max_iter=1000)
    ),
}
for name, model in models.items():
    result = cross_validate(
        model, X, y, cv=cv,
        scoring=["accuracy", "balanced_accuracy", "average_precision"],
        n_jobs=1, error_score="raise",
    )
    print(name, {key: round(value.mean(), 3)
                 for key, value in result.items() if key.startswith("test_")})
```

The majority baseline has about 95% accuracy but balanced accuracy of 0.5. Average precision is near the positive prevalence for its constant ranking. Weighted logistic regression changes the fitting objective; it may improve minority detection while lowering ordinary accuracy. That is a tradeoff to inspect, not an automatic improvement in every application.

This example uses all rows for cross-validation to compare a fixed educational recipe. A complete project should reserve final evaluation data before using these results to choose settings.

## Split at the right unit

For repeated observations from a device or customer, use `GroupKFold` or another group-aware splitter and supply the group identifiers. Assert that no group appears on both sides of a fold. Randomly splitting rows from the same entity can let a model recognize the entity instead of generalizing to a new one.

For ordered forecasting data, use chronological splits such as `TimeSeriesSplit`, optionally with a gap when adjacent observations can share information. Sort timestamps first and ensure every feature could have been computed at the prediction time. A field summarizing “next week's activity” is leakage even if a pipeline handles it perfectly.

## Keep resampling inside training folds

Oversampling or undersampling before splitting can duplicate or select information across validation boundaries. Any learned resampling strategy belongs inside the training portion of each fold. scikit-learn does not itself provide every resampling pipeline; external tools need their own correctly integrated workflow.

Class weighting is not a substitute for threshold selection or calibration. Evaluate ranking, chosen-label errors, and probability quality separately when they matter. A tiny number of positives also creates substantial uncertainty even when the metric formula is correct.
