# Decision Trees and Random Forests

A decision tree partitions feature space through threshold questions. It can capture nonlinear relationships and interactions without standardizing numeric features. An unrestricted tree can also memorize training observations, so training accuracy alone is a weak measure of usefulness.

A random forest combines many trees trained with randomness. Averaging their predictions can reduce variance, but it does not remove the need for careful validation. More trees also consume memory and training time.

## Observe training versus validation behavior

Run this complete example:

```python
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score

X, y = make_classification(
    n_samples=500, n_features=12, n_informative=5,
    n_redundant=2, flip_y=0.08, random_state=42
)
X_train, X_valid, y_train, y_valid = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
candidates = {
    "shallow tree": DecisionTreeClassifier(max_depth=3, random_state=42),
    "full tree": DecisionTreeClassifier(random_state=42),
    "forest": RandomForestClassifier(
        n_estimators=100, min_samples_leaf=3, random_state=42, n_jobs=1
    ),
}
for name, model in candidates.items():
    model.fit(X_train, y_train)
    print(name, "train", round(accuracy_score(y_train, model.predict(X_train)), 3),
          "validation", round(accuracy_score(y_valid, model.predict(X_valid)), 3))
```

Expect the unrestricted tree to fit training data extremely closely, often perfectly here. Its validation score need not be the best. The forest is a useful comparison, but the lesson's conclusion should come from the observed train-validation gap rather than a universal ranking.

## Control complexity and cost

`max_depth` limits path length. `min_samples_leaf` requires more observations at terminal regions, which can smooth predictions. In a forest, `n_estimators` controls the number of trees and `max_features` affects feature sampling at splits. Tune a small justified set of parameters before launching an expensive search.

`n_jobs=1` makes the example's resource use predictable. Parallelize at one level deliberately when combining forests and cross-validation; using all cores both inside and outside a search can oversubscribe the machine.

Trees are less sensitive to simple changes of numeric units than distance-based models, but mixed categorical data still needs a supported representation. Keep imputation and encoding in a pipeline where required. Do not infer that “no scaling needed” means “no data preparation needed.”

## Interpret importance cautiously

Built-in impurity-based feature importance can favor high-cardinality features and reflect overfitting. It is not a causal explanation. Permutation importance on suitable held-out data asks a different question: how much does shuffling a feature degrade this model's score? Correlated inputs can complicate that interpretation as well.

If you use validation data to interpret, select, and redesign features repeatedly, preserve another untouched test set for the final assessment.
