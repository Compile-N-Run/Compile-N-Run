# Classification and Predicted Probabilities

Classification predicts discrete labels. A classifier may also produce probability estimates, which support ranking and threshold decisions. Those probabilities are model outputs, not guaranteed frequencies or certainty about an individual observation.

Despite its name, logistic regression is a classification method. It combines a linear decision function with a probability model. Scaling can help optimization and regularization behave sensibly when feature units differ.

## Fit and inspect a binary classifier

Run this fresh script:

```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

X, y = make_classification(
    n_samples=400, n_features=6, n_informative=4,
    n_redundant=0, class_sep=1.2, random_state=42
)
X_train, X_valid, y_train, y_valid = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X_train, y_train)
probability = model.predict_proba(X_valid)
classes = model.classes_
print("class order:", classes.tolist())
print("probability shape:", probability.shape)
print("accuracy:", round(accuracy_score(y_valid, model.predict(X_valid)), 3))
assert np.allclose(probability.sum(axis=1), 1)
positive_column = np.flatnonzero(classes == 1)[0]
positive_probability = probability[:, positive_column]
```

Expect class order `[0, 1]` and probability shape `(100, 2)`. Each row contains one estimated probability per class, in `classes_` order. Do not assume the second column represents your business-defined positive outcome without checking the labels.

The model's label prediction follows its own decision rule. For this binary logistic model, comparing the positive-class probability with 0.5 reproduces the usual boundary apart from exact-tie details. Other estimators may expose decision scores rather than calibrated probabilities.

## Separate model fitting from policy

A threshold determines which probability estimates become positive decisions. Raising it usually reduces the number of positives, trading recall for precision in ways that depend on the data. Choose it using a validation procedure and the actual consequences of errors, not by maximizing a final test score.

A probability near 0.9 does not automatically mean that 90% of similar predictions are correct. Calibration evaluates whether probability estimates align with observed frequencies. Calibration itself is a learned procedure and needs proper data separation.

`C` in logistic regression is an inverse regularization-strength parameter: smaller values mean stronger regularization. This direction differs from Ridge's `alpha`, so do not transfer numerical intuition without checking the estimator reference.

## Exercise and solution

Compare the number of positive predictions at two fixed thresholds:

```python
for threshold in [0.5, 0.8]:
    chosen = positive_probability >= threshold
    print(threshold, int(chosen.sum()))
```

The 0.8 threshold cannot produce more positives than the 0.5 threshold on these same scores. That monotonic count check is meaningful even when exact metric values vary across datasets.

Do not declare one threshold better from the count alone. Continue with [classification metrics](../3-evaluation/13-scikit-learn-metrics.mdx) to examine which errors it changes, and [tree models](./12-scikit-learn-trees-and-ensembles.mdx) for a different model family.
