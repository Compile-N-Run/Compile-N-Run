# Regularization and Feature Scaling

A model can fit training data closely while making unstable predictions on new observations. Regularization discourages certain complex solutions. Ridge regression adds an L2 penalty on coefficients, shrinking them toward zero without usually making them exactly zero.

Its `alpha` parameter controls penalty strength. A larger value means stronger regularization, not a universally better model. Feature scale matters because the penalty acts on coefficient magnitudes; differently measured features can otherwise receive unequal treatment for reasons unrelated to their usefulness.

## Compare predefined strengths on validation data

Run this independent script:

```python
import numpy as np
from sklearn.datasets import make_regression
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import Ridge
from sklearn.metrics import root_mean_squared_error

X, y = make_regression(
    n_samples=120, n_features=30, n_informative=8,
    noise=35, random_state=42
)
X[:, 0] *= 1000
X_train, X_valid, y_train, y_valid = train_test_split(
    X, y, test_size=0.25, random_state=42
)
for alpha in [0.1, 10.0, 1000.0]:
    model = make_pipeline(StandardScaler(), Ridge(alpha=alpha))
    model.fit(X_train, y_train)
    prediction = model.predict(X_valid)
    norm = np.linalg.norm(model.named_steps["ridge"].coef_)
    print(alpha, "RMSE", round(root_mean_squared_error(y_valid, prediction), 2),
          "coefficient norm", round(norm, 2))
```

Expect the coefficient norm to decrease as the penalty grows. Validation error need not decrease monotonically: excessive shrinkage can underfit. The first feature's unit change is absorbed by training-fitted standardization, so the penalty works in a more comparable feature space.

`make_pipeline` chooses names automatically from estimator types. Here they are `standardscaler` and `ridge`; a parameter search would use `ridge__alpha`. An explicitly named `Pipeline` is often clearer when several similar steps appear.

## Interpret the tradeoff correctly

Regularization does not repair data leakage, missing prediction-time features, or a flawed split. It changes the optimization problem under the data you provide. A high-quality workflow can still produce a poor model if the available features contain little useful signal.

Coefficient size after scaling describes association within this fitted model. Correlated features can share or exchange predictive contribution. It is not proof that changing one real-world feature would cause the predicted outcome to change by that amount.

Lasso uses an L1 penalty and can set some coefficients to zero. Elastic Net combines L1 and L2 penalties. These are modeling choices to validate, not automatic feature-discovery guarantees. Keep preprocessing inside the pipeline for every candidate.
