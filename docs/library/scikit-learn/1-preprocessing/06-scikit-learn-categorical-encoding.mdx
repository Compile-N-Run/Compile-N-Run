# Encoding Categorical Features

Most estimators require numeric inputs, but categories are not automatically measurements. Assigning `small=0`, `medium=1`, and `large=2` may express a real ordering; assigning arbitrary numbers to cities usually introduces an ordering that does not exist.

One-hot encoding creates an indicator column for each learned category. It is a useful default for many nominal features, especially with linear models. The vocabulary must be learned from training data and applied consistently to later rows.

## Inspect the learned vocabulary

Run this fresh script:

```python
import numpy as np
from sklearn.preprocessing import OneHotEncoder

X_train = np.array([["email"], ["chat"], ["email"], ["phone"]])
X_new = np.array([["chat"], ["video"]])
encoder = OneHotEncoder(handle_unknown="ignore", sparse_output=False)
train_encoded = encoder.fit_transform(X_train)
new_encoded = encoder.transform(X_new)
print(encoder.get_feature_names_out(["channel"]).tolist())
print(train_encoded.shape)
print(new_encoded)
assert new_encoded.shape == (2, 3)
assert np.all(new_encoded[1] == 0)
```

Expect three feature names corresponding to chat, email, and phone; the training matrix has shape `(4, 3)`. The unseen `video` value maps to all zeros because `handle_unknown="ignore"` requests that behavior. It does not create a new feature at prediction time.

By default, one-hot output is sparse. This example uses `sparse_output=False` only so the tiny matrix is easy to inspect. Large high-cardinality tables can consume much more memory when made dense. Check whether the downstream estimator accepts sparse input before deciding to convert it.

## Decide what an unknown category means

Ignoring unknown values keeps prediction running, but it is not a complete data-quality policy. A new category may indicate normal growth, a spelling error, or a changed upstream system. Monitor it and document how the model behaves when all corresponding indicators are zero.

Rare-category grouping with options such as `min_frequency` can reduce a very large vocabulary. Grouping rules must still be fitted on training data. Do not create a vocabulary from the full dataset merely to avoid an error on the evaluation set.

Dropping one indicator is not universally required. It changes the representation and can affect regularized models. If you combine dropped categories with ignored unknowns, both can produce an all-zero pattern, making them indistinguishable to the estimator. Use an explicit modeling reason for that choice.

## Preserve genuine order explicitly

For an ordinal feature, `OrdinalEncoder` can use a domain-defined category order. Do not infer that order from alphabetical sorting. A target label encoder is a different tool: `LabelEncoder` is intended for target labels, not a convenient general replacement for feature preprocessing.

## Exercise and solution

Add `video` to the training array, fit a new encoder, and inspect the feature names again:

```python
expanded = np.vstack([X_train, [["video"]]])
updated = OneHotEncoder(handle_unknown="ignore", sparse_output=False)
updated.fit(expanded)
assert len(updated.get_feature_names_out()) == 4
```

The updated encoder has a different feature schema. A previously fitted model expecting three encoded columns cannot simply receive these four columns; refit the complete preprocessing-and-model workflow together.
