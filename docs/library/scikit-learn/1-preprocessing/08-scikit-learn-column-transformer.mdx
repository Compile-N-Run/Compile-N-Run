# ColumnTransformer for Mixed Tables

A table often contains numeric measurements and categorical labels. Applying one scaler to every column is not meaningful. `ColumnTransformer` routes selected columns through different transformations, then combines their outputs into the feature matrix used by an estimator.

Combine it with a `Pipeline` so the entire mixed-data workflow is fitted and evaluated together. Explicit column selections also document which information is available to the model.

## Build two preprocessing branches

This small example demonstrates the mechanics; its eight training rows are not enough for a credible performance study. Run it as a fresh script:

```python
import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

X_train = pd.DataFrame({
    "minutes": [12., 18., np.nan, 35., 45., 20., 55., 60.],
    "channel": ["email", "chat", "email", "phone", "chat", "email", "phone", "chat"],
})
y_train = np.array([0, 0, 0, 1, 1, 0, 1, 1])
X_new = pd.DataFrame({"minutes": [25., np.nan], "channel": ["video", "email"]})
numeric = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
])
preprocess = ColumnTransformer([
    ("numeric", numeric, ["minutes"]),
    ("category", OneHotEncoder(handle_unknown="ignore"), ["channel"]),
], remainder="drop")
workflow = Pipeline([("prepare", preprocess), ("model", LogisticRegression())])
workflow.fit(X_train, y_train)
print(workflow.predict(X_new).shape)
print(workflow.named_steps["prepare"].get_feature_names_out().tolist())
```

Expect two predictions and four transformed feature names: one numeric feature plus three channel indicators. The unknown channel is handled by the fitted encoder, and the missing numeric value uses the training median. The model receives the same transformed schema for both new rows.

## Choose columns deliberately

Passing `['minutes']` preserves a two-dimensional selection for the numeric branch. Some text-vectorization transformers require a one-dimensional string sequence and therefore use a different selector form. Check the selected transformer's input expectations rather than treating every column selector as interchangeable.

`remainder="drop"` excludes columns not listed in a branch. That is useful when IDs, notes, or future information should not enter the model. `remainder="passthrough"` can be convenient, but may accidentally admit a target-like or nonnumeric column. Prefer explicit inclusion for a first reliable workflow.

A real categorical branch may also need an imputer before one-hot encoding. Decide whether missing categories should be treated as a dedicated value, replaced by a training statistic, or rejected as a data-quality issue. Apply the chosen rule consistently.

## Preserve the prediction schema

Named DataFrame columns help route features, but prediction still needs the required fields and compatible types. A changed unit or a renamed category does not become correct simply because the column name matches.

Inspect `get_feature_names_out()` when interpreting coefficients or feature importances. Their positions correspond to the transformed matrix, not necessarily the original raw columns. A single categorical field can expand into many model inputs.
