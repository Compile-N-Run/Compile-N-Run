# Features, Targets, and Data Shapes

Most scikit-learn estimators expect a two-dimensional feature matrix `X`: rows are samples and columns are features. A typical single-output supervised target `y` is one-dimensional, with one value per row. Keeping those shapes explicit prevents many confusing errors.

For classification, the target identifies a category. For regression, it represents a numeric quantity. A numeric category code does not make a problem regression: class labels `0`, `1`, and `2` may be names rather than ordered measurements.

## Inspect a complete dataset

Run this as a fresh script in the course environment:

```python
from sklearn.datasets import load_iris

flowers = load_iris(as_frame=True)
X = flowers.data
y = flowers.target
print("features:", X.shape)
print("target:", y.shape)
print("columns:", list(X.columns))
print("classes:", flowers.target_names.tolist())
print("counts:", y.value_counts().sort_index().to_dict())
print("one row:", X.iloc[[0]].shape)
print("one column:", X[[X.columns[0]]].shape)
assert X.index.equals(y.index)
assert not X.isna().any().any()
```

Expect `(150, 4)` features, `(150,)` labels, and 50 rows in each of three classes. `as_frame=True` gives pandas objects with named columns, which makes schema checks easier. Built-in datasets also include descriptions; inspect their documentation rather than assuming what a column measures.

The double brackets in `X.iloc[[0]]` preserve a two-dimensional one-row table with shape `(1, 4)`. `X.iloc[0]` instead produces a one-dimensional Series. A future prediction for one sample still needs the same feature-column structure as training.

## Keep features and labels separate

Do not pass the entire `flowers.frame` as features without removing its target column. That frame includes both measurements and the answer. Accidentally leaving the target in `X` can produce an excellent-looking score for a useless model.

Avoid treating row IDs as measurements by default. An ID can encode collection order, source system, or another accidental relationship that will not exist for future samples. Likewise, a feature observed only after the outcome is not available at prediction time, even if it appears in the historical table.

For real data, record column names, units, expected types, missing-value conventions, and when each field becomes available. A model cannot detect that “length” silently changed from centimeters to millimeters. Named columns help, but they do not replace a data contract.

## Exercise and solution

Select only the first two feature columns while preserving a table and the original row order:

```python
X_two = X.iloc[:, :2]
print(X_two.shape)
assert X_two.shape == (150, 2)
assert X_two.index.equals(y.index)
```

Then inspect `X_two.iloc[[10]]`. It should have shape `(1, 2)`. If you train with these two features, prediction must receive those same two columns in the appropriate order; a four-column row is no longer the matching input.

Before moving on, explain the distinction between number of samples, number of input features, and number of target classes. They are independent quantities, and confusing them often leads to incorrect reshaping.
