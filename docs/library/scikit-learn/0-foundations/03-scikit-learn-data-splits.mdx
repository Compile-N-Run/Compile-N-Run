# Training, Validation, and Test Splits

A model must be evaluated on observations that were not used to learn it. The training set supports fitting; validation data supports decisions such as hyperparameters; the test set estimates performance after those choices are finished. Repeatedly inspecting the test score to improve the model makes that test set part of development.

The correct split depends on how future predictions will be used. Random row splitting is appropriate only when the independence assumptions are plausible. Rows from the same person, device, or time sequence can require different boundaries.

## Make a reproducible stratified split

This fresh script creates a final test set and a training-side validation set:

```python
import numpy as np
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

X, y = load_iris(return_X_y=True)
indices = np.arange(len(y))
trainval_idx, test_idx = train_test_split(
    indices, test_size=0.2, random_state=42, stratify=y
)
train_idx, valid_idx = train_test_split(
    trainval_idx, test_size=0.25, random_state=42,
    stratify=y[trainval_idx]
)
print(len(train_idx), len(valid_idx), len(test_idx))
print(np.bincount(y[test_idx]))
assert set(train_idx).isdisjoint(valid_idx)
assert set(train_idx).isdisjoint(test_idx)
assert set(valid_idx).isdisjoint(test_idx)
X_train, y_train = X[train_idx], y[train_idx]
X_valid, y_valid = X[valid_idx], y[valid_idx]
```

Expect 90 training rows, 30 validation rows, and 30 test rows. The second split takes 25% of the remaining 120 rows, not 25% of the original 150. The test set contains ten examples from each class here.

Splitting indices makes the membership visible, but you can also pass `X` and `y` together to `train_test_split`; it applies aligned indices to both. Do not independently shuffle the feature table and target array.

`stratify=y` approximately preserves class proportions. It helps avoid accidental class imbalance across folds, but does not make related observations independent or guarantee every rare class can be split. Very small class counts can make a requested split impossible.

## Respect how observations were collected

For repeated measurements from the same entity, use a group-aware splitter so one entity cannot appear on both sides. For forecasting, train on earlier observations and evaluate later ones. A random split can leak future patterns into the past even when the target column is absent from the features.

Fit learned preprocessing only on the training portion. For example, a scaler's mean, an imputer's median, and an encoder's category vocabulary all come from data. Estimating them on the full dataset before splitting shares information with evaluation.
