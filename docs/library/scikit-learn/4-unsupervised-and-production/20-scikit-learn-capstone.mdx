# scikit-learn Capstone: A Reproducible Classification Workflow

This project turns the course's pieces into one reproducible experiment. It generates synthetic numeric features, an independent categorical channel, and missing numeric values. It then reserves a final test set, tunes a complete preprocessing-and-classifier pipeline on development data, and writes a readable report.

Download [train.py](/examples/scikit-learn/train.py) and [requirements.txt](/examples/scikit-learn/requirements.txt) into a new folder. The same files live at `static/examples/scikit-learn/` in the repository. No dataset download, credential, notebook server, or external API is required.

## Create the reference environment

The pinned dependency set requires Python 3.12 or newer and was tested with Python 3.14.4. In your project copy, create an isolated environment and run:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python train.py --output-dir artifacts
```

On Windows, activate the environment with `.venv\Scripts\Activate.ps1` in PowerShell. The script writes `artifacts/report.json` and prints the chosen configuration and key scores. Keep generated outputs in your local project; they are not source files needed to publish this tutorial.

For the reference seed of 42, expect 640 development rows, 160 test rows, six candidate configurations, and four cross-validation folds. The checked environment selected `C=1.0` with balanced class weights, with cross-validation balanced accuracy around 0.754 and final test balanced accuracy around 0.692. The majority baseline's balanced accuracy is 0.500. These values describe this synthetic experiment; they are not guarantees for another dataset or dependency set.

## Follow the information boundaries

`make_table` creates 800 independent synthetic rows. The categorical channel is deliberately independent of the target: it demonstrates mixed-input handling without pretending that every available field contains signal. Missingness is also generated without reading the labels.

The script splits row indices before fitting any imputer, scaler, encoder, or classifier. Inside the pipeline, numeric columns pass through median imputation and standardization. The category passes through one-hot encoding with an explicit unknown-category policy. `ColumnTransformer` combines those branches and drops unlisted columns.

`GridSearchCV` fits fresh copies of the entire workflow in each development fold. The selected configuration is refitted on all development rows. Only then does the script evaluate the reserved test set and the predefined majority baseline. If you use that final result to redesign the experiment, acknowledge that the test has entered your development loop.

## Inspect the report

The JSON records versions, seed, row counts, raw and transformed feature names, selected parameters, selection metric, and several final metrics. The confusion matrix explicitly records label order. Read accuracy, balanced accuracy, positive-class F1, and ranking metrics together rather than treating one number as a complete model assessment.

The difference between cross-validation and test results is expected sampling variation, not a reason to search for a more favorable seed. For a real project, you would also review data provenance, the deployment population, error consequences, and uncertainty before using predictions.

## Optional trusted persistence

To save the fitted pipeline and verify a same-environment round trip:

```bash
python train.py --output-dir saved-run --save-model
```

The script loads only the model artifact it just created and asserts that predictions match. Do not adapt that call to load an arbitrary downloaded joblib file. See [persistence](./19-scikit-learn-persistence.mdx) for the trust and version-compatibility limits.

## Exercise and checks

Run the script twice with the same seed into two different output directories. Their reports should match in the same environment. Then inspect the code and identify exactly where the test labels first enter evaluation.

As a development exercise, add another predefined `C` value before evaluating a fresh final protocol. Keep the full pipeline inside the search and record the expanded candidate count. Do not report a repeatedly reused test set as untouched.

A complete solution preserves disjoint row sets, training-only fitted preprocessing, literal feature names, reproducible versions, and honest metric interpretation. The result is a workflow you can audit and adapt, not merely a saved classifier.
