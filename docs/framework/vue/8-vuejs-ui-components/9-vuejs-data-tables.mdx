# Vue.js Data Tables

## Introduction

Data tables are one of the most common UI components in real applications: user lists, order histories, inventory screens and admin dashboards all boil down to "show rows of data and let me sort, search and page through them."

Vue makes it surprisingly easy to build a capable table yourself. Because sorting, filtering and pagination are just transformations of an array, they map naturally onto Vue's `computed` properties. Once you understand that pipeline, you can either build your own reusable table component or pick a ready-made library with confidence.

In this guide, we'll explore:
- Rendering rows with `v-for`
- Sorting with computed properties
- Filtering and search
- Client-side pagination
- Describing columns as data
- Building a reusable `DataTable` component with props, emits and slots
- Comparing PrimeVue, Vuetify and TanStack Table
- Server-side pagination for large datasets

All examples use Vue 3 single-file components with `<script setup>`.

## Rendering Rows with v-for

The simplest table is an array of objects rendered with `v-for`. Always give each row a stable `:key`, ideally a unique ID from your data.

```html
<template>
  <table class="table">
    <thead>
      <tr>
        <th>Name</th>
        <th>Role</th>
        <th>Age</th>
      </tr>
    </thead>
    <tbody>
      <tr v-for="user in users" :key="user.id">
        <td>{{ user.name }}</td>
        <td>{{ user.role }}</td>
        <td>{{ user.age }}</td>
      </tr>
    </tbody>
  </table>
</template>

<script setup>
import { ref } from 'vue';

const users = ref([
  { id: 1, name: 'Alice', role: 'Admin', age: 34 },
  { id: 2, name: 'Bob', role: 'Editor', age: 27 },
  { id: 3, name: 'Carol', role: 'Viewer', age: 45 }
]);
</script>
```

## Sorting with Computed Properties

To sort, we keep two pieces of state: the column we sort by and the direction. A `computed` property returns a sorted **copy** of the data, so the original array is never mutated.

```javascript
import { ref, computed } from 'vue';

const sortKey = ref('name');
const sortDir = ref('asc'); // 'asc' or 'desc'

function sortBy(key) {
  if (sortKey.value === key) {
    sortDir.value = sortDir.value === 'asc' ? 'desc' : 'asc';
  } else {
    sortKey.value = key;
    sortDir.value = 'asc';
  }
}

const sortedUsers = computed(() => {
  const dir = sortDir.value === 'asc' ? 1 : -1;
  return [...users.value].sort((a, b) => {
    const x = a[sortKey.value];
    const y = b[sortKey.value];
    if (typeof x === 'number' && typeof y === 'number') return (x - y) * dir;
    return String(x).localeCompare(String(y)) * dir;
  });
});
```

In the template, make the headers clickable and loop over `sortedUsers` instead of `users`:

```html
<th @click="sortBy('age')">Age {{ sortKey === 'age' ? (sortDir === 'asc' ? '▲' : '▼') : '' }}</th>
```

Key points:
- `[...users.value]` copies the array. Calling `.sort()` directly on `users.value` inside a computed would mutate reactive state, which is a side effect computed properties should avoid.
- Numbers are compared numerically and everything else with `localeCompare`, so `"10"` does not sort before `"9"` for numeric columns.

## Filtering and Search

Search is another computed step. Bind an input with `v-model` and keep rows whose fields contain the query.

```javascript
const query = ref('');

const filteredUsers = computed(() => {
  const q = query.value.trim().toLowerCase();
  if (!q) return users.value;
  return users.value.filter(user =>
    Object.values(user).some(value => String(value).toLowerCase().includes(q))
  );
});
```

```html
<input v-model="query" placeholder="Search users..." />
<tr v-if="filteredUsers.length === 0">
  <td colspan="3">No matching users</td>
</tr>
```

Typing `ed` shows only Bob (role "Editor"). Always render an empty state; a blank table looks like a bug.

## Client-Side Pagination

Pagination is the last step in the pipeline: slice the filtered and sorted rows into pages.

The order matters: **filter, then sort, then paginate**. Paginating first would sort only the visible page.

```javascript
const page = ref(1);
const pageSize = ref(10);

const totalPages = computed(() => Math.max(1, Math.ceil(sortedRows.value.length / pageSize.value)));

const pagedRows = computed(() => {
  const start = (page.value - 1) * pageSize.value;
  return sortedRows.value.slice(start, start + pageSize.value);
});

// Jump back to page 1 when the search changes, or the user may land on an empty page
watch(query, () => { page.value = 1; });
```

And the pager controls in the template:

```html
<button :disabled="page === 1" @click="page--">Previous</button>
<span>Page {{ page }} of {{ totalPages }}</span>
<button :disabled="page === totalPages" @click="page++">Next</button>
```

## Column Definitions as Data

Hard-coding every `th` and `td` doesn't scale. Instead, describe the columns as an array and loop over them. This is the same idea every table library uses.

```javascript
const columns = [
  { key: 'name', label: 'Name', sortable: true },
  { key: 'email', label: 'Email', sortable: true },
  { key: 'age', label: 'Age', sortable: true, align: 'right' },
  { key: 'role', label: 'Role', sortable: false }
];
```

```html
<tr>
  <th v-for="col in columns" :key="col.key" @click="col.sortable && sortBy(col.key)">
    {{ col.label }}
  </th>
</tr>
<tr v-for="row in pagedRows" :key="row.id">
  <td v-for="col in columns" :key="col.key" :style="{ textAlign: col.align || 'left' }">
    {{ row[col.key] }}
  </td>
</tr>
```

Now adding a column is a one-line change, and the column list could even come from user preferences or an API.

## Building a Reusable DataTable Component

Let's combine everything into a `DataTable.vue` component. It will:
- Accept `rows`, `columns` and `pageSize` as props
- Handle search, sorting and pagination internally
- Emit `row-click` when a row is clicked
- Expose a **scoped slot** per column, so parents can render custom cells (badges, buttons, links)

```html
<!-- DataTable.vue -->
<template>
  <div class="data-table">
    <input v-model="query" class="search" placeholder="Search..." />

    <table>
      <thead>
        <tr>
          <th
            v-for="col in columns"
            :key="col.key"
            :class="{ sortable: col.sortable }"
            :aria-sort="ariaSort(col.key)"
            @click="col.sortable && toggleSort(col.key)"
          >
            {{ col.label }}
            <span v-if="sortKey === col.key">{{ sortDir === 'asc' ? '▲' : '▼' }}</span>
          </th>
        </tr>
      </thead>

      <tbody>
        <tr
          v-for="row in pagedRows"
          :key="row[rowKey]"
          @click="emit('row-click', row)"
        >
          <td v-for="col in columns" :key="col.key">
            <slot :name="`cell-${col.key}`" :row="row" :value="row[col.key]">
              {{ row[col.key] }}
            </slot>
          </td>
        </tr>
        <tr v-if="pagedRows.length === 0">
          <td :colspan="columns.length">
            <slot name="empty">No data found</slot>
          </td>
        </tr>
      </tbody>
    </table>

    <div class="pager">
      <button :disabled="page === 1" @click="page--">Previous</button>
      <span>Page {{ page }} of {{ totalPages }} ({{ processedRows.length }} rows)</span>
      <button :disabled="page === totalPages" @click="page++">Next</button>
    </div>
  </div>
</template>

<script setup>
import { ref, computed, watch } from 'vue';

const props = defineProps({
  rows: { type: Array, required: true },
  columns: { type: Array, required: true },
  rowKey: { type: String, default: 'id' },
  pageSize: { type: Number, default: 10 }
});

const emit = defineEmits(['row-click']);

const query = ref('');
const sortKey = ref(null);
const sortDir = ref('asc');
const page = ref(1);

function toggleSort(key) {
  sortDir.value = sortKey.value === key && sortDir.value === 'asc' ? 'desc' : 'asc';
  sortKey.value = key;
}

const ariaSort = key =>
  sortKey.value !== key ? 'none' : sortDir.value === 'asc' ? 'ascending' : 'descending';

// 1. Filter
const filteredRows = computed(() => {
  const q = query.value.trim().toLowerCase();
  return !q ? props.rows : props.rows.filter(row =>
    props.columns.some(col => String(row[col.key] ?? '').toLowerCase().includes(q)));
});

// 2. Sort
const processedRows = computed(() => {
  if (!sortKey.value) return filteredRows.value;
  const dir = sortDir.value === 'asc' ? 1 : -1;
  const key = sortKey.value;
  return [...filteredRows.value].sort((a, b) => {
    const x = a[key];
    const y = b[key];
    if (typeof x === 'number' && typeof y === 'number') return (x - y) * dir;
    return String(x ?? '').localeCompare(String(y ?? '')) * dir;
  });
});

// 3. Paginate
const totalPages = computed(() => Math.max(1, Math.ceil(processedRows.value.length / props.pageSize)));

const pagedRows = computed(() =>
  processedRows.value.slice((page.value - 1) * props.pageSize, page.value * props.pageSize)
);

watch([query, () => props.rows], () => { page.value = 1; });
</script>

<style scoped>
table { width: 100%; border-collapse: collapse; }
th, td { padding: 8px 12px; border-bottom: 1px solid #eee; text-align: left; }
th.sortable { cursor: pointer; user-select: none; }
.pager { display: flex; gap: 12px; align-items: center; }
</style>
```

### Using the Component with Custom Cells

The parent passes data and columns, listens for `row-click`, and overrides specific cells through named slots such as `#cell-status`:

```html
<!-- UsersPage.vue -->
<template>
  <DataTable :rows="users" :columns="columns" :page-size="5" @row-click="openUser">
    <template #cell-status="{ value }">
      <span :class="['badge', value]">{{ value }}</span>
    </template>

    <template #cell-actions="{ row }">
      <button @click.stop="removeUser(row.id)">Delete</button>
    </template>

    <template #empty>No users match your search.</template>
  </DataTable>
</template>

<script setup>
import { ref } from 'vue';
import DataTable from './DataTable.vue';

const columns = [
  { key: 'name', label: 'Name', sortable: true },
  { key: 'email', label: 'Email', sortable: true },
  { key: 'status', label: 'Status', sortable: true },
  { key: 'actions', label: '', sortable: false }
];

const users = ref([
  { id: 1, name: 'Alice', email: 'alice@example.com', status: 'active' },
  { id: 2, name: 'Bob', email: 'bob@example.com', status: 'invited' },
  { id: 3, name: 'Carol', email: 'carol@example.com', status: 'disabled' }
]);

const openUser = user => console.log('Open user', user.name);
const removeUser = id => { users.value = users.value.filter(u => u.id !== id); };
</script>
```

Notice `@click.stop` on the Delete button: without it, the click would bubble up to the row and also fire `row-click`.

## Ready-Made Table Libraries

Once you need features like column resizing, row selection, frozen columns, virtual scrolling or CSV export, a library usually pays off. Three popular choices for Vue 3:

### PrimeVue DataTable

PrimeVue ships a full-featured `DataTable` used together with `Column` components. Sorting, pagination and filtering are enabled through props.

```html
<template>
  <DataTable :value="products" paginator :rows="5" sortMode="single">
    <Column field="code" header="Code" sortable />
    <Column field="name" header="Name" sortable />
    <Column field="price" header="Price" sortable>
      <template #body="{ data }">{{ data.price.toFixed(2) }}</template>
    </Column>
  </DataTable>
</template>

<script setup>
import { ref } from 'vue';
import DataTable from 'primevue/datatable';
import Column from 'primevue/column';
const products = ref([
  { code: 'A1', name: 'Keyboard', price: 49.9 },
  { code: 'B2', name: 'Mouse', price: 19.5 }
]);
</script>
```

### Vuetify v-data-table

Vuetify 3 provides `v-data-table` for client-side data and `v-data-table-server` for server-driven data. Columns are described with a `headers` array using `title` and `key`, much like our own column definitions.

```html
<template>
  <v-data-table :headers="headers" :items="desserts" :items-per-page="5" :search="search" />
</template>

<script setup>
import { ref } from 'vue';
const search = ref('');
const headers = [
  { title: 'Dessert', key: 'name' },
  { title: 'Calories', key: 'calories', align: 'end' }
];
const desserts = ref([
  { name: 'Frozen Yogurt', calories: 159 },
  { name: 'Eclair', calories: 262 }
]);
</script>
```

### TanStack Table for Vue

TanStack Table (`@tanstack/vue-table`) is **headless**: it manages sorting, filtering, pagination and selection state, but renders no markup. You write the `table` HTML yourself and render cells with its `FlexRender` component. This gives you complete design control, at the cost of more template code. The API differs between major versions (v8 uses `useVueTable`, while the newer v9 docs use `useTable` with explicit feature registration), so follow the [TanStack Table Vue quick start](https://tanstack.com/table/latest/docs/framework/vue/quick-start) for the version you install.

## Server-Side Pagination for Large Datasets

Client-side tables load every row into the browser. That's fine for a few hundred or a few thousand rows, but for 100,000 orders it means a slow initial request, high memory use and a sluggish UI.

With **server-side** pagination, the table only holds the current page. Every change to page, sort or search becomes a request:

```html
<template>
  <input v-model="query" placeholder="Search orders..." />
  <p v-if="loading">Loading...</p>

  <table>
    <tr v-for="order in rows" :key="order.id">
      <td>{{ order.id }}</td>
      <td>{{ order.customer }}</td>
    </tr>
  </table>

  <button :disabled="page === 1" @click="page--">Previous</button>
  <button :disabled="page >= totalPages" @click="page++">Next</button>
</template>

<script setup>
import { ref, computed, watch } from 'vue';

const rows = ref([]);
const total = ref(0);
const page = ref(1);
const pageSize = 20;
const sortKey = ref('createdAt');
const sortDir = ref('desc');
const query = ref('');
const loading = ref(false);

const totalPages = computed(() => Math.max(1, Math.ceil(total.value / pageSize)));

let controller;
let debounceTimer;

async function load() {
  controller?.abort(); // cancel a stale request
  controller = new AbortController();
  loading.value = true;

  const params = new URLSearchParams({
    page: page.value,
    pageSize,
    sort: sortKey.value,
    dir: sortDir.value,
    q: query.value
  });

  try {
    const res = await fetch(`/api/orders?${params}`, { signal: controller.signal });
    const data = await res.json(); // expected shape: items + total
    rows.value = data.items;
    total.value = data.total;
  } catch (err) {
    if (err.name !== 'AbortError') console.error(err);
  } finally {
    loading.value = false;
  }
}

watch([page, sortKey, sortDir], load, { immediate: true });

// Debounce search so we don't send a request on every keystroke
watch(query, () => {
  clearTimeout(debounceTimer);
  debounceTimer = setTimeout(() => {
    page.value = 1;
    load();
  }, 300);
});
</script>
```

Important details:
- **Debounce** search input so typing "alice" sends one request, not five.
- **Abort** stale requests so a slow response for page 2 can't overwrite page 3.
- The server must return the **total count** so the pager knows how many pages exist.
- Sorting and filtering must happen on the **server** too; sorting only the current page would be misleading.

Libraries support this mode directly: PrimeVue's `DataTable` has a `lazy` prop combined with `totalRecords`, and Vuetify's `v-data-table-server` takes `items-length` and emits `update:options` when the page, sort or page size changes.

## Real-World Scenario: An Admin Orders Dashboard

Imagine you're building the orders screen for an e-commerce admin panel. Support staff need to search by customer, sort by date or total, and page through results. Some shops have 200 orders; the largest have 2 million.

**Why it matters:** the table is the screen staff use all day. Slow sorting or confusing paging directly costs support time.

**When to choose each approach:**

| Approach | Best for | Pros | Cons |
| --- | --- | --- | --- |
| Hand-built `DataTable` (client-side) | Small datasets (under ~5,000 rows), simple needs | No dependencies, full control, tiny bundle, easy to learn | You maintain sorting, a11y, edge cases yourself |
| Hand-built with server-side paging | Large datasets, custom design | Scales to millions of rows, full control | More backend work, loading and error states to handle |
| PrimeVue / Vuetify table | Feature-rich admin UIs, teams already on that library | Selection, filters, frozen columns, export, lazy mode out of the box | Larger bundle, styling tied to the library's design system |
| TanStack Table (headless) | Custom design systems needing advanced logic | Powerful state logic, any markup, framework-agnostic core | Steeper learning curve, you still write all markup and styles |

**Trade-offs to weigh:**
- **Build** when the table is simple, you need a unique design, or you want to avoid adding a large UI library for one screen.
- **Buy** when you need many advanced features (column resizing, multi-sort, row grouping, virtual scrolling) or your app already uses PrimeVue or Vuetify; reimplementing these well takes weeks.
- **Go server-side** as soon as the full dataset is too large to download comfortably, regardless of whether you build or buy.

For the orders dashboard, a sensible plan is: start with the hand-built component and server-side paging, and switch the rendering to a library only if staff start asking for advanced features like column pinning or bulk selection.

## Best Practices

- Keep the pipeline order **filter, sort, paginate**, each as its own `computed`.
- Never mutate props or reactive arrays inside a computed; copy before sorting.
- Use stable, unique `:key` values (IDs, not array indexes), and reset to page 1 when the search changes.
- Add `aria-sort` on sortable headers and make them keyboard accessible (for example, use a `button` inside the `th`).
- Always show loading, empty and error states; for very long single-page lists, consider virtual scrolling.
