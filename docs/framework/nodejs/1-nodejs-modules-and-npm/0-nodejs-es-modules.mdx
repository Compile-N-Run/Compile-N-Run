# Node.js ES Modules

Modules let a program name its dependencies and expose a deliberate interface. A useful module does one coherent job without assuming how the application will be started.

**Prerequisites:** [Project setup](../0-nodejs-foundations/1-nodejs-setup.mdx). Keep `"type": "module"` in `package.json`.

## Create a small module

Save `src/format.js`:

```javascript
export function formatCount(label, count) {
  if (!Number.isInteger(count) || count < 0) {
    throw new TypeError('count must be a nonnegative integer');
  }
  return `${label}: ${count}`;
}
```

Save `src/report.js`:

```javascript
import { formatCount } from './format.js';
console.log(formatCount('Completed', 3));
```

Run `node src/report.js`. Expect `Completed: 3`. The import names an exported binding; misspelling it produces a module-loading error rather than quietly reading an undefined property.

Use the `.js` extension in relative ES module imports. Node's standard relative resolution does not behave like every bundler's extension guessing. The path is relative to the importing module, not the terminal's current directory.

## Keep entry points thin

`format.js` exports a function and has no printing side effect when imported. `report.js` is an entry point that chooses input and writes output. This separation makes the formatter reusable from a test, a CLI, or a server without starting those interfaces automatically.

A module is generally evaluated once per resolved module identity within a process and its exported bindings are reused. Do not treat module-level mutable state as a fresh instance for every import. If consumers need independent state, export a factory function that creates it.

Import built-in modules using the `node:` prefix, such as `node:path`. The prefix makes the dependency's origin explicit and avoids confusing a built-in API with a package installed from npm.

## Recognize other module formats

A `.mjs` file is explicitly an ES module. A `.cjs` file is explicitly CommonJS and commonly uses `require` and `module.exports`. Existing packages may use either format. This course stays with ESM rather than mixing module syntaxes in one file.

When integrating a CommonJS dependency, read its documented export shape. A default import often corresponds to `module.exports`; inferred named exports are not a universal guarantee for every package. Do not solve an import failure by randomly alternating `require` and `import` without checking the package boundary.

## Practice and solution

Add an exported `formatPercent(value)` that accepts a finite number from 0 to 1 and returns a percentage string. Import it into the report and call it with 0.75.

A valid result is `75%`; negative values, `NaN`, and 2 should throw. Keep output in the entry point so importing the module alone prints nothing. This boundary will make the later test suite simple.
