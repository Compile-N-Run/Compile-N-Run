# Node.js Module Design and Boundaries

A useful module boundary follows a responsibility. Parsing external text, calculating a result, and printing that result change for different reasons, so keeping them separate prevents a small command from becoming difficult to test.

**Prerequisites:** [ES modules](./0-nodejs-es-modules.mdx). Create `src/summarize.js` in the course package.

## Keep the calculation independent

```javascript
export function summarize(values) {
  if (!Array.isArray(values) || values.length === 0 ||
      !values.every(Number.isFinite)) {
    throw new TypeError('Expected a nonempty array of finite numbers');
  }
  const total = values.reduce((sum, value) => sum + value, 0);
  return { count: values.length, total, average: total / values.length };
}
```

This function does not read files, inspect environment variables, or print. Its input and output are plain values, so the same function can serve a CLI, an HTTP handler, or a test.

Create `src/numbers.js`:

```javascript
import { summarize } from './summarize.js';

try {
  const inputs = process.argv.slice(2);
  if (inputs.some((value) => value.trim() === '')) {
    throw new TypeError('Empty values are not numbers');
  }
  const result = summarize(inputs.map(Number));
  console.log(JSON.stringify(result));
} catch (error) {
  console.error(error.message);
  process.exitCode = 1;
}
```

Run `node src/numbers.js 2 4 6`. Expect `{"count":3,"total":12,"average":4}`. Run it without numbers and expect an error rather than an average of `NaN`.

## Put policy at the right layer

The entry point decides that arguments are numeric strings and output is JSON. The computation decides that an empty array is not meaningful. Neither reaches into the other layer's environment.

A returned object gives callers data they can format differently. Printing inside `summarize` would force every caller to intercept console output. Similarly, calling `process.exit` inside a reusable module would unexpectedly terminate a server that imports it.

This small calculation can overflow if fed sufficiently large finite numbers; validating each input does not prove every computed result stays finite. Production numeric code should decide its acceptable magnitude and precision explicitly. The later capstone validates the aggregate result as well.

## Avoid abstractions without a purpose

You do not need a class hierarchy to separate these concerns. Plain functions and a thin entry point are enough. Introduce a storage interface or injected dependency when you have an actual need to replace it in testing or deployment, not simply to increase the number of files.

## Practice and solution

Add a `maximum` property without changing how arguments are parsed. Calculate it within `summarize`, preferably by reduction if arrays may be large rather than spreading an unbounded array into a function call. For `2 4 6`, the new value should be 6. Confirm that invalid input still follows the existing error path.
