# Node.js package.json and npm Scripts

A package manifest records how a project is organized. npm scripts give collaborators a shared vocabulary for operations such as running, checking, and testing the program.

**Prerequisites:** [ES modules](./0-nodejs-es-modules.mdx). Use a package with `src/report.js` and `src/format.js` from that lesson.

## Define a small command interface

Update `package.json`:

```json
{
  "name": "workshop-report",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node src/report.js",
    "check": "node --check src/report.js && node --check src/format.js",
    "test": "node --test"
  },
  "engines": { "node": ">=22" }
}
```

Run `npm start` and `npm run check`. The first runs the report; the second checks syntax without executing its application logic. The `&&` means the second check runs only if the first succeeds. These simple commands work in the usual npm shells on the operating systems covered here.

`npm test` is a convenient alias for the test script. A successful test command with no meaningful tests does not prove the application works; you will add behavioral tests in the final section.

## Pass arguments through the script

If your entry point reads process arguments, use `npm start -- Ada 2` to pass `Ada` and `2` to it. The double dash separates npm's arguments from the script's arguments. This is especially useful when an argument begins with a dash.

An npm script can invoke a locally installed executable from `node_modules/.bin` without a global installation. That keeps tool choice within the project. Avoid requiring every contributor to install an unspecified global linter or build tool and hoping their versions match.

## Keep configuration readable

`dependencies` are packages required by the application at runtime; `devDependencies` commonly hold build and test tooling. This distinction influences installation choices but does not automatically prevent a development dependency from executing during a build.

The version in your manifest describes your package; it is unrelated to the installed Node version. A `main` or `exports` field matters when another package imports yours, but the simple private command project does not need a public package API yet.

Scripts execute commands. Review scripts in downloaded projects before running installation or build operations, particularly lifecycle hooks such as `preinstall` and `postinstall`. A manifest is executable configuration in that practical sense, not just passive documentation.

## Practice and solution

Add a `version:runtime` script that prints Node's version. Use `"version:runtime": "node --version"`, then run `npm run version:runtime`.

Verify that `npm run` lists the commands available. Finally, add a deliberate syntax error to a copy of `format.js` and confirm the check script fails. Restore the source before moving on. The check is useful because it fails for a concrete defect, not because it prints a reassuring label.
