# Node.js Concurrency and Promise Coordination

Independent asynchronous operations can overlap. Related operations must preserve their dependencies, and large workloads need limits so concurrency does not exhaust resources.

**Prerequisites:** [Promises and errors](./1-nodejs-promises-and-errors.mdx). The example uses an artificial asynchronous delay and performs no network requests.

```javascript
import { setTimeout as delay } from 'node:timers/promises';

async function describe(id) {
  await delay(50);
  return `item-${id}`;
}

const results = await Promise.all([1, 2, 3].map(describe));
console.log(results);
```

Save as `src/concurrency.js` and run it. Expect an array with `item-1`, `item-2`, and `item-3` in that order. The operations may complete in a different order if you change their delays, but `Promise.all` preserves input order in the returned results.

## Distinguish starting from waiting

Calling an async function starts its execution. `Promise.all` waits for promises you give it; it does not magically start a collection of uncalled functions. Writing `await describe(1)` and then `await describe(2)` is sequential because the second call happens only after the first completes.

If any input promise rejects, `Promise.all` rejects. Other already-started operations are not automatically canceled. They may still read files, consume bandwidth, or produce side effects. Use the cancellation mechanism supported by those operations if the whole group should stop.

Use `Promise.allSettled` when every result is independently useful even if some operations fail. Its records distinguish fulfilled values from rejection reasons. Do not silently turn rejected items into successful empty objects simply to keep the array length consistent.

## Bound larger workloads

For a small teaching example, fixed-size batches are easy to inspect:

```javascript
const ids = [1, 2, 3, 4, 5, 6, 7];
const collected = [];
const batchSize = 3;
for (let offset = 0; offset < ids.length; offset += batchSize) {
  const batch = ids.slice(offset, offset + batchSize);
  collected.push(...await Promise.all(batch.map(describe)));
}
console.log(collected.length);
```

At most three descriptions are in progress in this loop. A batch waits for its slowest member before starting the next batch, so a worker pool can use resources more continuously. The simpler approach is often sufficient until measurement shows otherwise.

Do not use `array.forEach(async item => ...)` expecting the outer function to await every callback. `forEach` does not collect and wait for returned promises. Use `for...of` for sequence or explicit promise collection for concurrency.

## Practice and check

Make item 2 reject. Observe that `Promise.all` rejects while other started work can finish. Then use `allSettled` and count successful records. Your solution should report two successes and one failure for the original three items, without claiming the failed item completed.
