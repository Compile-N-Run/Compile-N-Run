# Node.js Setup and Project Layout

A predictable setup makes an error easier to reproduce. Start with a supported Node installation, a terminal, and a small directory whose contents you understand.

**Prerequisites:** [Node.js Introduction](./0-nodejs-introduction.mdx). Install Node using an appropriate method linked from the official download page. Installation details vary by operating system; avoid mixing several installation methods without knowing which executable your terminal selects.

## Verify the tools

Open a new terminal after installation and run:

```bash
node --version
npm --version
```

Record both results when asking someone to reproduce a problem. npm is the package manager distributed with common Node installations, but it has its own version. A global tool's version is not necessarily the version installed within a project.

Create this directory using your file manager or terminal:

```text
node-workshop/
  package.json
  src/
    index.js
```

Save the following `package.json`:

```json
{
  "name": "node-workshop",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node src/index.js"
  },
  "engines": {
    "node": ">=22"
  }
}
```

Then create `src/index.js`:

```javascript
console.log('Workshop ready');
console.log('Working directory:', process.cwd());
```

From `node-workshop`, run `npm start`. You should see the script command, followed by `Workshop ready` and the absolute working-directory path. No package installation is needed because this example has no dependencies.

## Know what each setting does

`type: module` makes ordinary `.js` files in this package use ES module semantics. `private: true` prevents accidental publication through npm; it does not encrypt the source or make a Git repository private.

The engines field communicates a compatibility expectation. Do not assume every package manager configuration enforces it as a hard restriction. CI should explicitly select and test supported versions. The broad `>=22` range in this learning package is a baseline declaration, not evidence that every future major was tested.

An npm script runs with the package root as its working directory. If you execute `node` directly from another location, relative filesystem paths may resolve differently. Later lessons distinguish working-directory paths from paths relative to a module.

## Diagnose setup problems

If `npm start` reports a missing script, check that you are in the intended directory and that the JSON saved successfully. JSON requires double-quoted property names and disallows trailing commas and comments. If Node treats `import` unexpectedly, inspect the nearest package's type and filename extension.

## Practice and check

Add a `check` script with value `node --check src/index.js`, then run `npm run check`. Success normally produces no diagnostic output and exits with status zero. Introduce an unmatched parenthesis, rerun the command, and confirm a syntax error. Restore the file before continuing.
