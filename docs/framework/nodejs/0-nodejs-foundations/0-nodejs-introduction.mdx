# Node.js Introduction

Node.js runs JavaScript outside the browser. It supplies APIs for files, networking, processes, and other operating-system capabilities. You can use it for a command-line tool, a development utility, or an HTTP server; you do not need a web framework to begin.

**Prerequisites:** JavaScript variables, functions, arrays, objects, and basic promises. The [JavaScript course](/docs/language/javascript) introduces the language if these are unfamiliar. This course uses ES modules and APIs compatible with Node.js 22.

## Separate the language from its environment

JavaScript syntax is shared between browsers and Node, but available APIs differ. A browser provides `document` and visual page elements. A normal Node process has no browser DOM. Node provides filesystem access that ordinary browser page scripts do not have.

A program starts, performs work, and eventually exits when no relevant work keeps it alive. An HTTP server normally remains running because its listening socket is active. A small calculation can finish immediately.

Create `hello.mjs` containing:

```javascript
const name = process.argv[2] ?? 'Learner';
console.log(`Hello, ${name}!`);
console.log(`Running Node ${process.versions.node}`);
```

Run it in a terminal:

```bash
node hello.mjs Ada
```

The first line should be `Hello, Ada!`; the second displays your actual Node version. `process.argv` contains the executable path, script path, and user arguments. Index 2 is the first user argument, not the second.

## Choose a supported baseline

At this course's October 2026 verification, the official release table lists Node 22 and 24 as LTS lines and Node 20 as end of life. Examples are locally tested with Node 22.22.1 and intentionally avoid features introduced only in newer majors. Use a currently patched release of a supported line, and consult the release table when choosing a version for a real project.

Being compatible with Node 22 does not mean freezing an old patch indefinitely. Patch updates carry important fixes. A project should document its supported major versions and test them, while deployment records the actual version used.

## Understand the execution boundary

Running a Node script grants it the permissions of your operating-system account unless you add other controls. An imported package executes code too. Do not treat a local script as a harmless text document just because it is written in JavaScript.

Node's asynchronous APIs help overlap waiting for input and output. They do not make long synchronous calculations automatically run in parallel. You will inspect this distinction in the event-loop section.

## Practice and solution

Run the script without a name and then with a two-word name:

```bash
node hello.mjs
node hello.mjs "Ada Lovelace"
```

Expect `Hello, Learner!` and `Hello, Ada Lovelace!`. Quoting keeps the second name together as one shell argument. If `node` is not found, continue with [runtime setup](./1-nodejs-setup.mdx).
