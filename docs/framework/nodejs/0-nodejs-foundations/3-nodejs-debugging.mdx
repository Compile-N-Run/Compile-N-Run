# Node.js Debugging and Error Messages

Debugging starts with evidence: the input, actual output, expected output, and exact command that produced the difference. A stack trace is useful only when you connect it to those facts.

**Prerequisites:** [Process arguments](./2-nodejs-process-and-input.mdx). Use the course's ES module package and save the following as `src/total.js`.

```javascript
function totalPrices(items) {
  return items.reduce((total, item) => total + item.price, 0);
}

const items = [{ price: 10 }, { price: '5' }];
console.log(totalPrices(items));
```

Run `node src/total.js`. It prints `105`, not 15, because adding a string changes the operation to concatenation. There is no exception: a logically wrong result can be syntactically valid.

## Inspect the boundary

Before adding a conversion everywhere, decide the contract. If prices must be numbers, reject invalid data where it enters the program:

```javascript
function totalPrices(items) {
  return items.reduce((total, item) => {
    if (!Number.isFinite(item.price)) {
      throw new TypeError('Each price must be a finite number');
    }
    return total + item.price;
  }, 0);
}
```

Replace the original function and rerun. The stack identifies where the error was created and the callers leading to it. Read the first application-owned frame carefully; dependency frames can provide context without being the place you should edit.

For financial applications, floating-point arithmetic has additional limitations. This small example demonstrates type debugging, not a complete money representation strategy.

## Step through execution

Run `node --inspect-brk src/total.js` to pause at startup and attach a compatible debugger, such as your editor's Node debugger. Keep the inspector bound to its default local interface; exposing a debug port can grant powerful access to the process.

Set a breakpoint inside the reducer. Inspect the current item and accumulated total on each iteration. Step over the addition and watch the type change in the original version. A breakpoint answers a focused question more effectively than scattering unstructured logs across every function.

For simple problems, temporary logs remain useful. Log the specific values and types you need, and remove them or convert them to intentional diagnostics afterward. Do not log passwords, access tokens, or entire user records to solve a small type problem.

## Practice and solution

Change the second price to 5 and confirm 15. Then try `NaN` and `Infinity`; both should fail the finite-number check. Write down the smallest failing data set, the command, and the resulting diagnostic.

A useful bug report includes Node's version and whether the program is running as an ES module. It avoids a screenshot-only report when a copyable error message and five lines of source can reproduce the issue.
