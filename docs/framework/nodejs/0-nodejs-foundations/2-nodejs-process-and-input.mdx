# Node.js Process Arguments and Configuration

Arguments and environment variables let one program handle different inputs. They arrive as external data, usually strings, so parsing and validation should happen before business logic depends on them.

**Prerequisites:** [Project setup](./1-nodejs-setup.mdx). Save this example as `src/greet.js` inside the ES module package.

## Validate arguments deliberately

```javascript
const [name, countText = '1', ...extra] = process.argv.slice(2);
const count = Number(countText);

if (!name || extra.length > 0 ||
    !Number.isInteger(count) || count < 1 || count > 5) {
  console.error('Usage: node src/greet.js NAME [COUNT: 1..5]');
  process.exitCode = 1;
} else {
  for (let index = 0; index < count; index += 1) {
    console.log(`Hello, ${name}!`);
  }
}
```

Run `node src/greet.js Ada 2`. Expect two greetings. Run `node src/greet.js Ada many`: expect a usage message on standard error and an unsuccessful exit status.

This implementation rejects extra arguments instead of silently ignoring misspelled options. It converts a complete numeric string with `Number` and then checks its domain. `parseInt('2oops', 10)` would produce 2, which may accept an input the person did not intend.

`process.exitCode = 1` records failure while allowing normal cleanup and pending output to finish. Calling `process.exit(1)` immediately can interrupt pending writes. A command should distinguish human diagnostics on stderr from machine-readable output on stdout.

## Read configuration separately

An environment variable is useful for configuration supplied by a shell, CI runner, or hosting platform:

```javascript
const logLevel = process.env.LOG_LEVEL ?? 'info';
const allowed = new Set(['info', 'debug', 'error']);
if (!allowed.has(logLevel)) {
  throw new Error('LOG_LEVEL must be info, debug, or error');
}
console.log(`Log level: ${logLevel}`);
```

Use your shell's environment-setting syntax, which differs between POSIX shells and PowerShell. Node 22 also supports loading a local file explicitly with `node --env-file=.env src/config.js`; create `src/config.js` from the second snippet and a `.env` containing `LOG_LEVEL=debug` first.

Do not commit real credentials in an environment file. A variable is a configuration mechanism, not a guarantee of secrecy. Avoid printing all of `process.env` when debugging because it can contain tokens and service credentials.

## Practice and solution

Extend the greeting command to reject a whitespace-only name. Use `name.trim()` after confirming a name exists, and pass the trimmed value to the greeting. Test missing input, `"   "`, a valid two-word name, `0`, and `6`.

The correct behavior accepts only a nonempty trimmed name and an integer count from 1 through 5. Keep validation messages specific enough to help the user recover without exposing unrelated configuration.
