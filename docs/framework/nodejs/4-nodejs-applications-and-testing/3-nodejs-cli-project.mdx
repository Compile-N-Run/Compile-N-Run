# Node.js Project: Tested JSON Report CLI

Build a command that reads a JSON array, validates it, and prints a summary. The supplied project also includes a local health server and tests both interfaces. It uses Node's built-in APIs and installs no third-party packages.

**Prerequisites:** The [files and streams](../3-nodejs-files-and-streams/index.mdx) and [testing](./1-nodejs-testing.mdx) lessons. The project was locally exercised with Node 22.22.1; its package documents Node 22 as the minimum baseline.

## Get the complete project

Copy `static/examples/nodejs/` from the repository into a working directory. Without a checkout, save each linked source file using its exact filename and directory:

- [package.json](/examples/nodejs/package.json) and [package-lock.json](/examples/nodejs/package-lock.json).
- [src/report.js](/examples/nodejs/src/report.js), [src/cli.js](/examples/nodejs/src/cli.js), [src/http.js](/examples/nodejs/src/http.js), and [src/server.js](/examples/nodejs/src/server.js).
- [test/report.test.js](/examples/nodejs/test/report.test.js).
- [sample.json](/examples/nodejs/sample.json).

Run from that directory:

```bash
npm ci --ignore-scripts
npm test
node src/cli.js sample.json
```

The sample contains `[2,4,6]`, so the CLI should print:

```json
{"count":3,"total":12,"average":4}
```

The tests check valid data, malformed and out-of-range input, CLI success and failure exit behavior, and HTTP status contracts. They use temporary files and a loopback server on an automatically selected port, so they do not require a fixed port or public network service.

## Follow the program's boundaries

`report.js` parses and validates data, then returns an object without printing. It rejects empty arrays, nonnumeric entries, excessive counts, and a nonfinite total. `cli.js` reads a user-selected local file, enforces a byte limit while reading, calls the reusable logic, and writes either JSON to stdout or a diagnostic to stderr.

The byte limit is one mebibyte. The implementation reads incrementally and stops once the accumulated input exceeds that limit rather than trusting a prior file-size check that could become stale. It still stores accepted input before JSON parsing, so the limit is deliberately small.

`http.js` exports a server factory that does not listen on import. `server.js` is the entry point that binds it to loopback. Start it with `npm start`, then request `http://127.0.0.1:3000/health`. Stop it with Ctrl+C. This is a local learning server, not a published service.

## Extend and verify

Add a `maximum` property to the report. Update the normal-result tests and CLI output expectation. Preserve the existing failure contract and make sure the new calculation handles negative numbers.

Acceptance checks are concrete: valid input produces one JSON line, invalid input produces no successful JSON, failures use a nonzero status, and all resources opened by tests are closed. Run the full suite after your change.

Do not add file-writing behavior silently: exporting a result to a path introduces overwrite and partial-write decisions. Treat that as a separate feature with an explicit contract and tests.

Further reading: [Node.js test runner](https://nodejs.org/docs/latest-v22.x/api/test.html).
