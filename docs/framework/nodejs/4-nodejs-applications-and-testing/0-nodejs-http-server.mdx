# Node.js HTTP Server Basics

An HTTP server receives requests and produces responses. A framework can simplify routing, but the built-in API is enough to understand the contract between client and server.

**Prerequisites:** [Async errors](../2-nodejs-asynchronous-programming/1-nodejs-promises-and-errors.mdx). Save the following as `src/server.js` in the ES module project.

```javascript
import { createServer } from 'node:http';

const server = createServer((request, response) => {
  response.setHeader('Content-Type', 'application/json; charset=utf-8');
  response.setHeader('X-Content-Type-Options', 'nosniff');
  let url;
  try {
    url = new URL(request.url, 'http://localhost');
  } catch {
    response.writeHead(400);
    response.end(JSON.stringify({ error: 'Invalid request target' }));
    return;
  }

  if (request.method !== 'GET') {
    response.writeHead(405, { Allow: 'GET' });
    response.end(JSON.stringify({ error: 'Method not allowed' }));
    return;
  }
  if (url.pathname === '/health') {
    response.writeHead(200);
    response.end(JSON.stringify({ status: 'ok' }));
    return;
  }
  response.writeHead(404);
  response.end(JSON.stringify({ error: 'Not found' }));
});

server.on('error', (error) => {
  console.error(`Server failed: ${error.message}`);
  process.exitCode = 1;
});
server.listen(3000, '127.0.0.1', () => {
  console.log('Listening at http://127.0.0.1:3000');
});
```

Run `node src/server.js`, then open `http://127.0.0.1:3000/health` in a browser. Expect JSON with status `ok`. The terminal stays active while the server listens; stop it with Ctrl+C.

## Make the response contract explicit

The method describes the requested kind of operation, and the URL path selects a resource. This example allows only GET and advertises that choice with an Allow header when returning 405. An unknown path returns 404 rather than a misleading successful response.

Every branch ends the response and returns before another branch can write. Sending headers twice or forgetting to end a response are common beginner errors. Set the media type so clients know the body is JSON.

The fixed URL base is used to parse the incoming relative request target; it is not a claim that the client requested a particular trusted host. A real public server must decide how to handle host headers and proxies explicitly.

## Keep the demonstration's limits visible

Binding to `127.0.0.1` makes the server accessible locally rather than on every network interface. The example has no database, authentication, TLS termination, body parser, or deployment lifecycle. Adding a route does not automatically provide those features.

If you later use an async request handler, catch its failures and decide how to respond; the HTTP server does not turn every rejected promise into a helpful JSON error automatically. Also handle partial responses carefully because headers may already have been sent.

## Practice and solution

Add a GET `/version` route returning a harmless application version such as `{"version":"1.0.0"}`. Test both known routes, an unknown route, and POST using an HTTP client. Expected status codes are 200, 200, 404, and 405. Do not expose environment variables or system paths in the version endpoint.
