# Node.js Security Boundaries

A program's risk depends on who controls its inputs and what authority the program has. A local command reading a file chosen by its owner has a different boundary from a public server handling requests from strangers.

**Prerequisites:** [HTTP basics](./0-nodejs-http-server.mdx) and [filesystem handling](../3-nodejs-files-and-streams/1-nodejs-reading-and-writing-files.mdx).

## Validate shape and size

Parsing JSON only checks syntax. Follow it with validation of types, ranges, required properties, and collection sizes. For a report command, require a bounded, nonempty array of finite numbers and reject an aggregate that overflows to infinity.

For incoming request bodies, count bytes as you receive them and stop accepting data after the configured limit. Do not concatenate unlimited chunks first and check the final length afterward. Rate, concurrency, and timeout limits address different resource problems; one maximum body size does not cover them all.

A small parser can enforce its data contract independently of transport:

```javascript
export function validateValues(values) {
  if (!Array.isArray(values) || values.length === 0 || values.length > 10000) {
    throw new TypeError('Expected 1 to 10000 values');
  }
  if (!values.every(Number.isFinite)) {
    throw new TypeError('Every value must be a finite number');
  }
  return values;
}
```

Call this after parsing, not instead of catching malformed JSON. Keep limits appropriate to the application's actual needs.

## Avoid turning data into shell source

If you must launch a program, prefer a fixed executable with an argument array through an API such as `execFile` or `spawn` without a shell. Interpolating a user-supplied filename into an `exec` command can turn punctuation into executable shell syntax.

Even an argument-array API requires thought: the target executable may interpret a value beginning with `-` as an option. Follow its documented end-of-options convention when needed. Avoid passing arbitrary executable names from an untrusted request.

This course's capstone does not need a shell to read or summarize files, so it uses filesystem APIs directly. Eliminating an unnecessary command boundary is simpler than trying to escape every possible shell character.

## Minimize authority and disclosure

Do not embed credentials in code, check them into example files, or print complete environment snapshots. Limit tokens to the operations they need and rotate credentials that were exposed. A `.gitignore` rule prevents new untracked files from being added automatically; it does not remove secrets already committed.

For a public service, authentication, authorization, transport security, and safe deployment configuration require explicit design. Node's built-in HTTP module is a transport primitive, not a complete security policy.

## Practice and check

Feed the validator an empty array, 10001 numbers, a numeric string, and `NaN`. Each should fail. Then inspect your program for a path where input reaches `eval`, a shell command, or an unlimited allocation. A correct review identifies both the input's owner and the authority available at that operation.
