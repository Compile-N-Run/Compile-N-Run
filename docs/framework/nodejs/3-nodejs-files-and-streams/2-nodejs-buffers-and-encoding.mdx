# Node.js Buffers and Text Encoding

A file or network connection supplies bytes. A JavaScript string represents text. An encoding describes how to translate between them; assuming one byte always means one visible character causes subtle corruption.

**Prerequisites:** [Reading files](./1-nodejs-reading-and-writing-files.mdx). Save each example in a separate ES module file and run it with Node.

## Inspect a buffer

```javascript
const text = 'café';
const bytes = Buffer.from(text, 'utf8');
console.log(text.length);
console.log(bytes.length);
console.log(bytes.toString('hex'));
console.log(bytes.toString('utf8'));
```

Expect string length 4, byte length 5, hexadecimal `636166c3a9`, and the original word. The accented character occupies two UTF-8 bytes. JavaScript string length counts UTF-16 code units, which also do not always equal user-perceived characters; some emoji and combined characters make that distinction visible.

When `readFile` is called without an encoding, it returns a Buffer. Supplying `'utf8'` asks it to decode text. Use the binary form when copying an image or handling arbitrary bytes, because decoding and re-encoding can alter data that was never UTF-8 text.

## Handle a split character

Network and stream chunks are transport boundaries, not guaranteed character or line boundaries. Splitting a multibyte character and decoding each piece independently can insert replacement characters.

```javascript
import { StringDecoder } from 'node:string_decoder';

const bytes = Buffer.from('café', 'utf8');
const decoder = new StringDecoder('utf8');
const first = decoder.write(bytes.subarray(0, 4));
const second = decoder.end(bytes.subarray(4));
console.log(first + second);
```

This should still print `café`. The decoder retains an incomplete sequence between chunks. A readable stream configured with a text encoding provides corresponding decoding support, so you do not need to manually reconstruct every character in ordinary text-stream handling.

## Choose safe allocation and bounds

`Buffer.alloc(size)` creates initialized storage. `Buffer.allocUnsafe` is intended for advanced cases where every byte is overwritten correctly before use; it is unnecessary for these beginner examples. `Buffer.from` creates a buffer from supplied data with a clear conversion.

A buffer slice or `subarray` can share underlying memory. Mutating it may affect the original buffer. Copy deliberately when independent ownership is required, and do not assume a view is a new isolated byte array.

Also remember that limits stated in characters differ from limits stated in bytes. A request-size limit usually protects memory and bandwidth, so count incoming bytes rather than decoded string length.

## Practice and check

Repeat the experiment with an emoji. Compare string length, UTF-8 byte length, and what you see on screen. Then split its buffer halfway through the encoded sequence and reconstruct it with `StringDecoder`. The solution should preserve the original text, not merely happen to work for plain ASCII.
