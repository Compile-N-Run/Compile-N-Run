# Node.js Paths and File URLs

A relative path has no meaning until you know its base. Many filesystem bugs happen because a program works from its own directory but fails when started elsewhere.

**Prerequisites:** [ES modules](../1-nodejs-modules-and-npm/0-nodejs-es-modules.mdx). Create a `data` directory beside `src`, with `message.txt` containing `Hello from data`.

## Choose the base deliberately

Save `src/paths.js`:

```javascript
import { readFile } from 'node:fs/promises';
import { resolve } from 'node:path';
import { fileURLToPath } from 'node:url';

const fromWorkingDirectory = resolve('data', 'message.txt');
const fromModule = new URL('../data/message.txt', import.meta.url);

console.log('Working directory path:', fromWorkingDirectory);
console.log('Module-relative path:', fileURLToPath(fromModule));
console.log((await readFile(fromModule, 'utf8')).trim());
```

Run `node src/paths.js` from the project root. Both printed paths should refer to the same file. Then move into `src` and run `node paths.js`. The working-directory path now points under `src/data`, while the module-relative URL still points to the real data file.

Filesystem functions such as `readFile` accept file URL objects. `fileURLToPath` converts one to a platform-correct path when an API needs a string. Do not use `url.pathname` as a universal filesystem path; URL encoding and Windows drive handling make that unreliable.

## Join segments instead of hardcoding separators

`path.join` combines path segments according to the host platform. `path.resolve` also creates an absolute path based on its arguments and, when necessary, the current working directory. A later absolute argument can replace the earlier base, so inspect the actual behavior before using it on untrusted input.

A CLI commonly treats a user-supplied filename as relative to the user's current directory. An application-owned template is usually better located relative to the module. These are different requirements, not one universally correct base.

## Normalization is not authorization

Cleaning up `..` segments does not prove a requested path is allowed. A web server that accepts arbitrary filenames must also handle traversal, symlinks, platform behavior, and race conditions. A string-prefix test can be wrong for sibling names such as `data-private` versus `data`.

This course's HTTP example does not serve arbitrary filesystem paths. Its CLI accepts a local file selected by the person running it, under that person's existing filesystem permissions. State the trust boundary instead of borrowing a partial “safe path” snippet for a different threat model.

## Practice and check

Create a filename with a space, such as `data/meeting notes.txt`, and read it using a module-relative URL. Confirm it works from both the project root and `src`. When supplying that filename as a CLI argument, quote it so the shell passes one argument. The successful result should not depend on guessing the terminal's current directory.
