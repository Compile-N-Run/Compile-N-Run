# Tailwind Capstone: A Workshop Board

This project combines the course into a responsive workshop board. It includes wrapping navigation, a shared card grid, container-aware metadata, native exercise disclosures, and a temporary checklist. The browser loads compiled CSS; no runtime script, external font, or image service is required.

[Open the finished board](/examples/tailwind/index.html). The complete project lives at `static/examples/tailwind/` in the repository. For an independent copy, save these files together: [index.html](/examples/tailwind/index.html), [input.css](/examples/tailwind/input.css), [output.css](/examples/tailwind/output.css), [package.json](/examples/tailwind/package.json), and [package-lock.json](/examples/tailwind/package-lock.json). Use an HTML-only save or page source when saving the HTML so the source document stays intact.

## Run the project

The included `output.css` lets you open `index.html` immediately. To modify and rebuild it, use Node 22 or newer in your copied project directory:

```bash
npm ci
npm run build
```

For continuous compilation, run `npm run dev` and leave that terminal open. Refresh the browser after edits. Stop the watcher with Ctrl+C. Dependency installation belongs in your project copy, not inside the tutorial website's application dependencies.

Both Tailwind packages are pinned to 4.3.0, and the lockfile records their resolved dependency tree. The compiler input uses explicit discovery:

```css
@import "tailwindcss" source(none);
@source "./index.html";
```

Every class used by the board appears literally in that HTML or is expanded through the input stylesheet's component rules. A production build therefore does not depend on scanning unrelated repository files.

## Read the design before changing it

The page starts as a single column. A large-screen grid adds the session-plan sidebar, while the workshop collection gains two shared columns at a smaller breakpoint. Each card uses a column flex layout so its action can sit below varying description lengths.

The card wrapper establishes a container, and metadata changes arrangement according to that container's width. This differs from the outer page's viewport breakpoints. Resize the page and inspect both conditions to connect the final interface with [the responsive lesson](../1-layout/08-tailwind-responsive-design.mdx).

Theme variables define a small brand palette. Most appearance remains visible in utility classes; `.action-link` extracts a repeated treatment in the component layer. The default dark variant follows the operating-system preference, while native controls receive a matching `color-scheme`.

The checklist does not save data across visits. Its reset button works through native HTML. The disclosures also work without JavaScript. These are complete local interactions, not placeholders for an undisclosed backend.

## Extend the board

Add a third workshop about source detection and a matching exercise disclosure. Keep the card heading at `h3`, use a unique destination ID, and write an actual check learners can perform. Reuse the existing card pattern before inventing a new visual abstraction.

A successful solution requires no additional breakpoint: the existing grid places the third card naturally. If you add a new utility, rebuild and confirm it appears in `output.css`. If you move the new markup into another source file, register that file explicitly.

## Verify the result

Test 320, 768, and 1440 CSS-pixel widths, then enlarge the root text size and replace a title with a long phrase. Ordinary content should remain inside the page without horizontal overflow. Tab from the beginning: the skip link, navigation, workshop links, summaries, and checklist should follow a sensible sequence with visible focus.

Emulate dark mode and reduced motion. Text and controls must remain readable, and the optional action transition should disappear when reduced motion is requested. Toggle a checkbox, then activate Reset checklist and confirm its initial state returns.

Finally rebuild from a clean copy using the lockfile. The generated CSS should recreate the same page. You now have a small, inspectable foundation to adapt into a course catalog, reading list, or event schedule.
