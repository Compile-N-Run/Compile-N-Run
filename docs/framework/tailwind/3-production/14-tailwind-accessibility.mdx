# Accessible Tailwind Interfaces

Tailwind can express accessible styles, but it cannot decide whether a label is meaningful or a control behaves correctly. Accessibility comes from the combination of HTML semantics, application behavior, and presentation. Test that combination with more than a mouse at one screen size.

A useful baseline uses native controls, visible labels, a sensible heading structure, and readable text. Then utilities refine spacing, colors, and states without removing the underlying affordances.

## Build a native disclosure

Reset the starter input to its baseline import and use:

```html
<a href="#main" class="sr-only focus:not-sr-only focus:absolute focus:left-4 focus:top-4 focus:z-10 focus:rounded focus:bg-white focus:p-3 focus:text-blue-900">
  Skip to main content
</a>
<main id="main" tabindex="-1" class="mx-auto max-w-xl p-4">
  <h1 class="text-3xl font-bold wrap-anywhere">Workshop questions</h1>
  <details class="mt-6 rounded-xl border border-slate-400 bg-white open:bg-blue-50">
    <summary class="cursor-pointer p-4 font-semibold focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-blue-800">
      Do I need a JavaScript framework?
    </summary>
    <p class="px-4 pb-4 leading-7">No. This course uses plain HTML and compiled CSS.</p>
  </details>
</main>
```

Rebuild and press Tab from the top of the page. The skip link becomes visible when focused. Activating it moves navigation to the main target. The summary can be activated with keyboard controls, and the disclosure's content is managed by the browser.

The `open:` variant changes appearance when the details element is open. It does not implement the disclosure behavior. Replacing `details` and `summary` with styled generic elements would require you to rebuild semantics and keyboard behavior yourself.

## Check common failure points

Use visible labels for form fields. `sr-only` can visually hide supplementary accessible text when appropriate, but `hidden` removes content from layout and generally from the accessibility tree. Do not hide the only label with `hidden` and assume a screen reader will still announce it.

Keep an explicit focus indicator and test its contrast on each surface. A ring can be obscured by another element or clipped by overflow. Text contrast must also be checked against the actual background, including hover and dark states; shade names do not prove a contrast ratio.

Allow text to wrap at enlarged sizes. Fixed heights, narrow minimum widths, and single-line truncation can make essential content unavailable. Test a narrow viewport and increased default text size in addition to browser zoom.

Preflight removes list markers. When a list is intentionally markerless and list semantics matter, consider `role="list"` and test VoiceOver behavior, as discussed in [Preflight](../0-foundations/04-tailwind-preflight-and-typography.mdx).

## Exercise and checks

Add a second disclosure with a longer summary. Navigate through both using only the keyboard, open them, and increase text size. No summary text should be clipped, and the focus indicator must remain visible.

Then temporarily add `overflow-hidden` to the details element and observe whether its outline is affected. Remove it unless clipping is an intentional and tested requirement. Automated accessibility tools can identify some errors, but they cannot replace operating the page and reading its content.
