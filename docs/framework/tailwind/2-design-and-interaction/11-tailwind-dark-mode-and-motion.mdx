# Dark Mode and Motion Preferences

A dark theme needs coordinated surfaces, text, borders, and focus indicators. Changing only the page background often leaves controls unreadable. Tailwind's default `dark:` variant responds to the user's color-scheme preference; it does not require a JavaScript toggle.

Motion is a separate preference. Define a usable still appearance, then add optional transitions with `motion-safe:`. Avoid making visibility or essential feedback depend on an animation running.

## Start with the system preference

Reset `input.css` to its baseline import for this example and replace the body contents:

```html
<main class="min-h-screen bg-slate-100 p-4 text-slate-900 dark:bg-slate-950 dark:text-slate-100">
  <article class="mx-auto max-w-xl rounded-xl border border-slate-300 bg-white p-6 dark:border-slate-700 dark:bg-slate-900">
    <h1 class="text-2xl font-bold">A comfortable reading surface</h1>
    <p class="mt-4 leading-7 text-slate-700 dark:text-slate-300">This panel follows your color preference.</p>
    <a href="#notes"
      class="mt-6 inline-block rounded-md bg-blue-800 px-4 py-3 font-semibold text-white hover:bg-blue-900 focus-visible:outline-2 focus-visible:outline-offset-4 focus-visible:outline-blue-800 dark:bg-blue-200 dark:text-slate-950 dark:hover:bg-blue-100 dark:focus-visible:outline-blue-200 motion-safe:transition-colors motion-safe:duration-150">
      Read the notes
    </a>
    <section id="notes" class="mt-8"><h2 class="text-xl font-semibold">Theme checks</h2></section>
  </article>
</main>
```

Rebuild and emulate light and dark preferences in developer tools. The panel, paragraph, action, and focus outline should all remain distinguishable. The transition is optional; with reduced motion requested, state changes still happen immediately.

The `dark:` prefix changes CSS conditions, not HTML content. Do not maintain separate duplicate buttons for each theme when one semantic control can change appearance.

## Optional manual theme selection

For a selector-driven theme, add this directive to the input stylesheet:

```css
@custom-variant dark (&:where(.dark, .dark *));
```

After rebuilding, the same `dark:*` utilities respond to a `.dark` ancestor instead of the default media preference. Adding `class="dark"` to the HTML root is enough for a static experiment. This is a replacement variant strategy, not an automatic three-way light/dark/system preference manager.

A production toggle requires application logic to store the preference, respond to system changes when appropriate, and avoid a flash of the wrong theme. This course's capstone keeps the system-driven option, so it does not need that additional behavior. Set the CSS `color-scheme` appropriately if native controls should match the selected theme as well.

## Exercise and solution

First test the default system-driven example in dark mode. Then add the custom variant, rebuild, and toggle the root `.dark` class in developer tools. Confirm that the source of theme selection changed.

Finally emulate reduced motion and tab to the link. Its focus outline must remain immediate and visible. If you added a transform effect, gate that effect with `motion-safe:` too; disabling only its transition would still produce a sudden positional jump.
