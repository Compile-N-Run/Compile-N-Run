# Theme Variables and Design Tokens

A design system benefits from shared decisions: a brand color, a spacing scale, a font family, or a breakpoint. Tailwind 4 expresses these decisions with CSS theme variables. A token can generate related utilities, so adding one named color is more coherent than scattering repeated hexadecimal values through markup.

Not every CSS variable belongs in `@theme`. Use theme namespaces for values that should participate in Tailwind's utility API. Use ordinary custom properties for local runtime values or semantic aliases that do not need new utility names.

## Add a brand palette

Replace the starter's `input.css` with:

```css
@import "tailwindcss";

@theme {
  --color-brand-100: #dbeafe;
  --color-brand-800: #1e40af;
  --color-brand-950: #172554;
  --font-display: Georgia, serif;
}
```

Use these tokens in `index.html`:

```html
<main class="mx-auto max-w-xl p-4">
  <section class="rounded-xl border border-brand-800 bg-brand-100 p-6 text-brand-950">
    <h1 class="font-display text-3xl font-bold">Workshop notebook</h1>
    <p class="mt-4 leading-7">A small palette keeps the interface consistent.</p>
    <a href="#notes" class="mt-4 inline-block font-semibold text-brand-800 underline underline-offset-4">Read the notes</a>
  </section>
  <section id="notes" class="mt-8"><h2 class="text-xl font-semibold">Theme notes</h2></section>
</main>
```

Rebuild. Expect the panel and link to use the custom palette, and the heading to use the display font. The `--color-*` namespace supports color utilities such as backgrounds, text, and borders. The `--font-*` namespace defines font-family utilities. Tailwind recognizes these namespaces; an arbitrary variable name does not automatically create a useful class.

## Separate palette from semantic roles

A palette names values such as `brand-800`. A semantic token names a role such as “surface” or “primary text.” Roles can change with a theme even when the component's class list stays constant.

For a local value, ordinary CSS remains useful:

```css
:root { --card-padding: 1.5rem; }
```

Then a literal utility such as `p-[var(--card-padding)]` uses that variable without inventing a whole spacing scale. If a semantic theme variable references another custom property whose value depends on context, study `@theme inline`: it can make generated utilities reference the intended underlying value rather than resolve an alias at an unexpected ancestor.

Do not reset a namespace with `--color-*: initial` casually. That removes defaults in the namespace and can break components still using standard palette classes. A global token change is a shared-system edit, not a local override.

## Exercise and checks

Add `--color-brand-700` and use it for a hover state on the link. Rebuild and inspect the generated declaration. Confirm the class exists because it is written literally in source.

Next, change only `--font-display`. The heading should change while the paragraph retains its normal font. Finally, check contrast for every text/background pair rather than assuming related shade numbers guarantee accessibility.
