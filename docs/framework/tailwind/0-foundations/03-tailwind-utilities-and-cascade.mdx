# Utilities, Variants, and the Cascade

Tailwind utilities participate in ordinary CSS. The compiler decides how generated rules are ordered, and the browser applies layers, importance, specificity, and source order. Rearranging words in an HTML class attribute does not rearrange the stylesheet.

Start from the [CLI project](./02-tailwind-cli-setup.mdx), keep the baseline import, and replace the body contents with this example:

```html
<main class="mx-auto max-w-xl p-6">
  <h1 class="text-2xl font-bold">One property, one intention</h1>
  <p class="mt-4 rounded-lg bg-blue-100 p-4 text-blue-950">
    This message uses a coordinated surface and text color.
  </p>
  <a href="#notes"
     class="mt-4 inline-block rounded-md bg-blue-800 px-4 py-3 font-semibold text-white hover:bg-blue-900 focus-visible:outline-2 focus-visible:outline-offset-4 focus-visible:outline-blue-800">
    Read the notes
  </a>
  <section id="notes" class="mt-8"><h2 class="text-xl font-semibold">Notes</h2></section>
</main>
```

`px-4` controls horizontal padding, while `py-3` controls vertical padding. The `hover:` prefix applies a utility under a state condition. `focus-visible:` applies a separate keyboard-visible focus treatment. These variants are conditional CSS rules, not event handlers; the anchor's native navigation remains HTML behavior.

## Avoid accidental conflicts

Adding both `p-4` and `p-8` creates two declarations for the same property. Do not rely on whichever appears last in the class attribute. Choose one intended value or use a meaningful condition such as `p-4 md:p-8` to express a change at a breakpoint.

Some combinations are intentionally complementary: `p-4 pt-8` expresses general padding with a more specific top-padding adjustment in Tailwind's generated utility ordering. Still, avoid a large pile of competing utilities that obscures the final result. Inspect the computed style when the shorthand and longhand relationship is unclear.

Tailwind's default import establishes theme, base, components, and utilities layers. Normal unlayered custom CSS can outrank normal layered utilities before selector specificity is considered. If a plain `.notice` rule unexpectedly beats a utility, inspect its layer rather than assuming the class is missing. The [CSS cascade lesson](../../../language/css/0-foundations/03-css-cascade-and-specificity.mdx) gives the underlying model; your generated stylesheet shows the concrete result.

## Arbitrary values are an escape hatch

Use a bracketed value for a precise one-off requirement, such as `max-w-[42rem]`. Use underscores when a class token needs spaces, for example `grid-cols-[minmax(0,1fr)_18rem]`. Keep these tokens literal in scanned source. If the same unusual value appears repeatedly, it may deserve a theme token instead.

Arbitrary values do not validate your design. A fixed `w-[900px]` still overflows a phone, and a color token can still have insufficient contrast. The browser's sizing and accessibility rules remain your responsibility.

## Exercise and checks

Intentionally put `bg-blue-100 bg-amber-100` on the paragraph. Reorder the two tokens and inspect its computed background. The HTML order should not be your control mechanism. Remove one conflicting class, then add `hover:bg-amber-100` if a hover-only change is what you intended.

Use the Styles panel to identify the generated selector and active condition. Continue with [Preflight and typography](./04-tailwind-preflight-and-typography.mdx).
