# Install Tailwind CSS 4 with the CLI

The CLI turns your source classes into a static CSS file. Node and npm are build tools here; the finished browser page loads only HTML and generated CSS. Use a supported Node.js LTS release and a terminal in a new practice directory. The course's build was checked with Node 22 and Tailwind 4.3.0.

## Create the project

Run these commands in a new folder, separate from other applications:

```bash
mkdir tailwind-practice
cd tailwind-practice
npm init -y
npm install --save-dev --save-exact tailwindcss@4.3.0 @tailwindcss/cli@4.3.0
```

Keep the generated `package-lock.json` with the project. It records the resolved dependency tree; later, `npm ci` installs that recorded tree. Do not copy `node_modules` into a website or commit it to source control.

Create `input.css` in the project root:

```css
@import "tailwindcss";
```

Create `index.html` beside it:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Tailwind practice</title>
  <link rel="stylesheet" href="output.css">
</head>
<body class="bg-slate-100 p-4 font-sans text-slate-900">
  <main class="mx-auto max-w-2xl rounded-xl bg-white p-6">
    <h1 class="text-3xl font-bold">My first Tailwind build</h1>
    <p class="mt-4 leading-7">The browser is reading generated CSS.</p>
  </main>
</body>
</html>
```

Build once:

```bash
npx @tailwindcss/cli -i ./input.css -o ./output.css
```

Open `index.html` in your browser. Expect a pale background, a white content panel, and a large bold heading. The generated `output.css` should now exist. For repeated edits, run the same command with `--watch` and leave that terminal running. Stop it with Ctrl+C when finished.

## Know which files to edit

Edit HTML classes and the input stylesheet. Treat `output.css` as a build result: direct changes disappear on the next compilation. If you change the output filename, change the HTML link to match. Relative URLs are resolved from the HTML document's location.

In a small isolated project, automatic source detection finds the HTML. Later you will explicitly constrain sources for predictable production builds. A missing class can result from an unscanned file, an incomplete dynamic class name, or a compiler that has stopped watching; it is not always a browser problem.

Version 4's CLI is the separate `@tailwindcss/cli` package. The CSS import replaces the old three-directive setup used in many version 3 examples. You do not need a JavaScript configuration file for this starter. For existing applications, follow the integration guide for their actual build system instead of stacking multiple competing Tailwind processors.

## Exercise and solution

Change the heading to `text-4xl`, save, and confirm watch mode rebuilds. Then stop watch mode, change it to `text-xl`, and refresh without rebuilding. The change may lack a generated utility. Run a fresh build and verify the smaller heading appears. This demonstrates the separation between source markup, compilation, and browser rendering.
