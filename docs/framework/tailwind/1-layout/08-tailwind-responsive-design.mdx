# Responsive and Container Variants

Tailwind variants conditionally apply utilities. Responsive prefixes such as `md:` refer to viewport breakpoints. Container-query prefixes such as `@md:` refer to an eligible ancestor container. The similar names describe different measurements and should not be treated as interchangeable.

Unprefixed utilities apply at every size unless another rule overrides them. A class such as `sm:text-lg` does not mean “small screens only”; it applies from the small minimum-width breakpoint upward. Put the narrow-screen baseline in unprefixed classes.

## Adapt a component to its own space

Use this markup in the CLI starter:

```html
<main class="mx-auto grid max-w-5xl gap-6 p-4 lg:grid-cols-[minmax(0,1fr)_18rem]">
  <div class="@container">
    <article class="grid gap-4 rounded-xl bg-white p-6 @md:grid-cols-[5rem_minmax(0,1fr)] @md:items-center">
      <div aria-hidden="true" class="grid min-h-20 place-items-center rounded-lg bg-blue-100 font-bold text-blue-950">CSS</div>
      <div class="min-w-0"><h1 class="text-xl font-semibold">Flexible layouts</h1><p class="mt-2">This card responds to its wrapper.</p></div>
    </article>
  </div>
  <aside class="@container">
    <article class="grid gap-4 rounded-xl bg-white p-6 @md:grid-cols-[5rem_minmax(0,1fr)] @md:items-center">
      <div aria-hidden="true" class="grid min-h-20 place-items-center rounded-lg bg-blue-100 font-bold text-blue-950">CSS</div>
      <div class="min-w-0"><h2 class="text-xl font-semibold">Same component</h2><p class="mt-2">A narrow sidebar keeps it stacked.</p></div>
    </article>
  </aside>
</main>
```

At a wide viewport, the main wrapper and sidebar receive different widths. Their cards can therefore choose different internal layouts even though they share the same screen. The `@container` class establishes an inline-size query container; the descendants carry the conditional utilities.

Do not try to make a size-query container style itself based on the size it creates. The wrapper/card separation keeps the dependency clear. An unnamed query uses the nearest eligible container; named containers are useful when nesting creates ambiguity.

## Choose breakpoints from content

The default viewport `md` and container `@md` thresholds are not the same number. Inspect the documented theme or generated CSS when exact values matter. Customize a breakpoint only when the layout requirement justifies changing the shared design system.

Test around a breakpoint, not just at familiar device widths. A panel can look correct at 375 and 1440 pixels yet fail at 700. Long titles, wider fonts, and text zoom often expose those intermediate failures.

Responsive visibility utilities also have semantic consequences. `hidden md:block` removes content from the small-screen layout and accessibility tree. It is suitable only when hiding that content is actually acceptable, not as a shortcut for solving cramped controls.

## Exercise and check

Keep the viewport wide and change the sidebar track from `18rem` to `30rem`. Rebuild. Its card should switch internal layout when its own container crosses the query threshold. Then narrow the viewport and verify both cards remain readable in the unprefixed stacked design.

Replace one title with a much longer phrase and add `wrap-anywhere` where unbroken text is possible. Success means the component adapts without hiding essential content or changing reading order.
