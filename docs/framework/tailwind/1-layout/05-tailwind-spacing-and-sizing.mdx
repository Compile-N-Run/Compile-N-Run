# Spacing, Sizing, and Overflow

A well-sized component expresses relationships: fit the available width, stop growing at a readable maximum, and leave consistent internal space. Tailwind makes those declarations concise, but it does not change the CSS box model.

The default spacing scale shares a common base value. Utilities such as `p-4`, `gap-4`, and `mt-4` therefore coordinate spacing. Prefer a small intentional set of values over unrelated arbitrary lengths. Use `rem`-based sizing and natural text height so user font preferences can affect the design.

## Build a resilient panel

Replace the starter page's body contents with this markup, then rebuild:

```html
<main class="mx-auto w-full max-w-3xl px-4 py-8">
  <article class="min-w-0 rounded-xl border border-slate-300 bg-white p-6">
    <h1 class="text-2xl font-bold wrap-anywhere">Export details</h1>
    <p class="mt-4 leading-7">The panel grows vertically when its contents grow.</p>
    <p class="mt-3 wrap-anywhere font-mono text-sm">
      export01234567890123456789012345678901234567890123456789.json
    </p>
    <pre class="mt-4 max-w-full overflow-x-auto rounded-lg bg-slate-100 p-4"><code>const topic = "responsive design";</code></pre>
  </article>
</main>
```

The outer container fits its parent and stops at `max-w-3xl`. Horizontal padding creates gutters. The long filename may break anywhere because it is content meant to remain visible; the code preserves formatting and scrolls inside its own region when needed.

`min-w-0` permits shrinkage in layouts where an automatic content minimum could otherwise keep a child too wide. It does not itself wrap text. Pair a sizing decision with an appropriate overflow policy, as this panel does.

## Distinguish useful size constraints

`w-full` means the containing block's width, not the viewport width. `w-screen` requests viewport width and can be inappropriate inside a padded parent. `max-w-*` supplies an upper limit, while `min-w-*` can force overflow if the available space is smaller.

Avoid fixed heights for ordinary paragraphs and cards. A height that fits English text at your default font can clip translated or enlarged content. Use `min-h-*` when a minimum visual size is useful while still allowing growth. For a full-screen shell, choose viewport-height units deliberately and test browser chrome behavior on mobile devices.

A hidden overflow utility is not a general layout repair. `overflow-hidden` can conceal content and focus indicators. Before applying it, identify the child or minimum-size constraint causing the page to widen.

## Exercise and solution

Replace the heading with a long unbroken identifier and test at 320 CSS pixels with enlarged text. The `wrap-anywhere` utility should let it remain inside the card. Then remove that utility briefly and inspect the difference.

Next, change the outer `max-w-3xl` to `max-w-xl`; the panel should become narrower on wide screens without changing its mobile gutter. Duplicate the description paragraph several times and verify that height grows naturally.

Success means the panel remains readable without a page-level horizontal scrollbar, while an intentionally long code line can scroll within its own area. Continue with [Flexbox patterns](./06-tailwind-flexbox.mdx).
